Fitting methods

🧠0% 🤖100%

sim.fit() chooses a method that suits the model, so most fits don’t need to name one. This page is for choosing one yourself: what each method gives, what it needs, what its settings are, and how their answers compare on the same data. Fitting a model covers the data, the parameters, and the goodness of fit, which are the same for every method.

Choosing a method

Method Gives The model Likelihood needed? Use it when Avoid it when
'nelder-mead' Best fit Any; default for an ODE with one or two parameters, or one with no gradients No Few parameters, or a model that can’t be differentiated There are many parameters, where it gets slow
'l-bfgs-b' Best fit ODE with gradients; default for three or more parameters No Many parameters of a deterministic model The model is stochastic
'optuna' Best fit Any; default for stochastic models and agents No Runs are noisy, or there is no better option You need a posterior, or a precise optimum (follow it with 'nelder-mead')
'if2' Maximum-likelihood best fit Stochastic compartmental Yes You want the maximum likelihood of a stochastic model, whose noise makes a local search unreliable A parameter is not a rate of the model (e.g. a share reported), has several values (by group, or a time series), or you need a posterior
'nuts' Posterior ODE with gradients Yes You need a posterior of a deterministic model; it’s the most efficient sampler here The model is stochastic or has no gradients, or the data have much more chance in them than the likelihood allows (see below)
'pmcmc' Posterior Stochastic compartmental Yes You need a posterior of a stochastic model, with its process noise counted The model runs as agents, or is deterministic (use 'nuts')
'abc-smc' Approximate posterior Any, including agents No You need a posterior but have no likelihood, or the model runs as agents A likelihood-based posterior is possible, which is usually sharper

A “stochastic compartmental” model has solver='binomial', 'gillespie', or 'tau', and is one that the kernels run from start to finish, which sim.kernel_only() checks. If it doesn’t, 'if2' and 'pmcmc' raise an error that gives the reason.

Two more methods of scipy.optimize.minimize can also be named: 'powell' (no gradients) and 'slsqp' (gradients, when the sim has them). A list runs methods in turn: see below. Every method, with the kinds of model it suits and its cost, is listed in the appendix.

A setting that the method doesn’t take is an error, so a mistyped name can’t be ignored by accident.

The model

Every example fits the same SIR model, of an outbreak in a town of 10,000 people over four months, with half of infections reported. Two parameters are unknown: the transmission rate beta and the infectious period dur_inf. The data are weekly reported cases from a run of the same model as a chain binomial (in which the number of people who move between states each day is random), with beta = 0.3 and an infectious period of 8 days (so R0 is 2.4), and Poisson noise in the counts. Since the right answer is known, each method’s estimate can be compared with it. The likelihood says how the reported cases vary around what the model gives, here Poisson.

The share reported is fixed rather than fitted, since 'if2' can fit only the model’s rates, not how the data are observed.

import time
import pandas as pd
import starsim as ss

beta    = ss.par(0.4, bounds=[0.05, 1])      # Transmission rate per day
dur_inf = ss.par(ss.days(5), bounds=[3, 15]) # Infectious period, in days
S, I, R = ss.states(3)
infection = S >> I @ beta*I
cases = ss.outcome(0.5*infection) # Half of infections are reported
sir = ss.Disease(infection, I >> R @ dur_inf, cases, init=dict(I=0.002), name='sir')

pars = dict(total_pop=10_000, unit='day', stop=120)
truth = dict(beta=0.3, dur_inf=8)
data = ss.Sim(sir, pars=dict(beta=0.3, dur_inf=ss.days(8)), solver='binomial', rand_seed=2, verbose=0, **pars).run().to_data('cases', resample='week')

deterministic = ss.Sim(sir, data=data, verbose=0, **pars)
stochastic = ss.Sim(sir, data=data, solver='binomial', verbose=0, **pars)
likelihood = dict(cases=ss.poisson())

fits = {} # Each method's fit and how long it took, for the comparison at the end
def fit_by(method, sim, **settings):
    """ Fit by one method, and keep the fit and its time """
    start = time.time()
    fit = sim.fit(method=method, verbose=False, **settings)
    fits[method] = dict(fit=fit, seconds=time.time() - start)
    return fit

fit_by() is only for the comparison at the end of the page: each call is sim.fit(method=..., **settings), timed.

Best fits

SciPy: 'nelder-mead', 'l-bfgs-b', and others

These search from the best few points of a scan over the bounds. The gradient-based methods take their gradients from JAX (see Gradients). The fit has converged if the two best searches end at the same value.

Setting Default Meaning
scan 10 per parameter, at most 100 The number of points tried over the bounds
restarts 3 (1 for one parameter of a deterministic model) The number of searches, each from one of the best points that are apart
Others SciPy’s The method’s own options, e.g. maxiter=500; see scipy.optimize.show_options()

Optuna: 'optuna'

Optuna learns where to look from the scores so far, which suits noisy scores: each trial takes fresh random seeds, so the search averages over chance.

Setting Default Meaning
n_trials 100 The number of sets of values to try
n_workers 1 The number of processes running trials at once
storage None A file or database URL that keeps the trials, so a fit that stopped can be resumed
Others Optuna’s The keywords of study.optimize(), e.g. timeout=600 
fit = fit_by('optuna', stochastic, n_trials=100)
fit.table
par initial best low high spread_lower spread_upper
0 beta 0.4 0.248244 0.05 1.0 0.241682 0.314492
1 dur_inf 5.0 14.575778 3.00 15.0 6.205421 14.575778

spread_lower and spread_upper are the range of the best 10% of the trials: an indication of how flat the score is near the best, not an interval.

Iterated filtering: 'if2'

Iterated filtering (IF2; Ionides et al. 2015) finds maximum-likelihood values of a stochastic model. It runs a particle filter many times. Each particle has its own parameter values, which take a small random step at each data point, and particles that fit the data well are kept along with their values. The steps shrink from one pass of the filter to the next, so the particles settle on the best values. It’s the method of the pomp package for R.

Each of several chains starts from its own point, and the fit has converged if they end within 2 of each other in log-likelihood. If they don’t, try more passes or more particles, as the message says.

Setting Default Meaning
particles 1000 The number of particles in each pass; more gives a less noisy likelihood
iterations 50 The number of passes of the filter in each chain
chains 4 The number of chains, each from its own start
sd 0.05 The first size of a random step, on the scale searched on (the logit of a value’s place between its bounds, of its log for wide bounds)
cooling 0.5 The share of the first step size that is left after 50 passes (pomp’s cooling.fraction.50) 
fit = fit_by('if2', stochastic, likelihood=likelihood, particles=200, iterations=25)
fit.summarize();
Fitted 2 parameter(s) by if2, with 101 evaluations
Negative log-likelihood: 1346 before, 237.8 after (the mean of 4 runs)
Not converged: the 4 chains end 8564.52 apart in log-likelihood (best -65.56); try more passes (iterations=) or particles (particles=)
spread_lower and spread_upper: the range of the chains' estimates, an indication of the uncertainty only, not an interval

fit.table gives the range of the chains’ estimates. That shows how far the chains agree, and it is not a confidence interval; ss.fit.profile() gives one, and 'pmcmc' gives a posterior. Every data series needs a likelihood, and each fitted parameter needs to be a single value of one of the model’s rates.

This fit has not converged: three of its four chains end at almost the same values, near the truth, but one has wandered to a low β and a long infectious period, where the outbreak barely grows and the data are very unlikely. The best chain is still the one reported, but the message says to run longer, with more passes or more particles, before trusting it. fit.trials has the estimate and log-likelihood at each pass, which shows which chain has not settled:

Posteriors

A posterior uses each parameter’s prior= if it has one, and otherwise a uniform prior over its bounds. Its draws are in fit.samples, and fit.table adds the median, the 95% interval, and for chains R-hat and the effective sample size. Fit diagnostics covers how to read them. The examples below take fewer draws and chains than the defaults, so that this page runs in about a minute; they can then report that they have not converged, and a real fit should use the defaults or more.

NUTS: 'nuts'

The No-U-Turn sampler uses gradients to move through the posterior of a deterministic model. It needs JAX and BlackJAX. With the same rand_seed, it gives the same draws on the CPU, but on a GPU the last digits can differ from one run to the next, since JAX on a GPU does not always add numbers in the same order, and a long chain carries the difference along; the change is far inside the posterior’s intervals (a median moved by about 0.5%).

Setting Default Meaning
draws 500 The number of draws kept from each chain
warmup 500 The number of warm-up steps of each chain
chains 4 The number of chains
scan 10 per parameter, at most 100 The number of points tried for the chains’ starts

Particle MCMC: 'pmcmc'

Particle MCMC takes a random walk over the parameters, with the likelihood at each point estimated by a particle filter, so it includes the model’s process noise. Its draws are more correlated than those of NUTS, so it takes more of them. summarize() also prints the share of proposals each chain accepted (fit.diagnostics.acceptance); a share of about a quarter is typical of a well-tuned random walk.

scan 10 per parameter, at most 100 The number of points tried for the start

ABC-SMC: 'abc-smc'

Approximate Bayesian computation keeps the parameter values whose runs come closest to the data, by the goodness of fit, over generations with a shrinking tolerance. It needs no likelihood and works for agents, but each generation takes many runs, and the result is only as sharp as the final tolerance.

Setting Default Meaning
particles 200 The number of particles, which are the draws of the posterior
generations 8 The most generations to run
quantile 0.5 The quantile of the distances that sets the next tolerance
tolerance None The distance to stop at 
fit = fit_by('abc-smc', stochastic, particles=100, generations=6)
fit.table

Comparing the methods

Each fit above is kept, with how long it took, so a loop can put their estimates side by side, with the true values:

rows = []
for method, entry in fits.items():
    fit, table = entry['fit'], entry['fit'].table.set_index('par')
    row = dict(method=method, gives='posterior' if fit.samples is not None else 'best fit')
    for par in ['beta', 'dur_inf']:
        row[par] = table.loc[par, 'median'] if fit.samples is not None else table.loc[par, 'best'] # The median of a posterior
        row[f'{par} 95% interval'] = f"{table.loc[par, 'lower']:.3f} to {table.loc[par, 'upper']:.3f}" if fit.samples is not None else ''
    row['seconds'] = entry['seconds']
    rows.append(row)
rows.append(dict(method='(true values)', **truth))
comparison = pd.DataFrame(rows).set_index('method')
comparison.round(3).fillna('')

The table shows what the choice of method changes. The methods that fit the ODE (the SciPy methods and NUTS) agree with each other, as they fit the same deterministic curve, but that curve is not the model that made the data: in the chain binomial, people move between states once a day, and every infection is a chance event. So the ODE’s best fit is a little off (a lower β and a longer infectious period than the truth), and the NUTS posterior is narrow around it, because a Poisson likelihood on an ODE counts only the noise in the reporting, not the chance in transmission. Its 95% interval for β excludes the true value: it is overconfident. Particle MCMC runs the stochastic model itself, so its posterior includes the process noise, and its intervals contain the true values. ABC-SMC, with no likelihood, gives much wider intervals, as it is only as sharp as its last tolerance. Of the best fits of the stochastic model, IF2, which maximizes its likelihood, is near the truth, and Optuna, which minimizes the mismatch averaged over runs, ends near the ODE’s values; neither says how uncertain it is.

So, for data with much more chance in them than reporting noise (a small population, or an outbreak that started from a few cases), a posterior from an ODE understates the uncertainty. A likelihood that allows more variation (ss.nbinom(n=...), with n fitted) widens it, and a stochastic model with 'pmcmc' counts the chance directly, at a higher cost. The times are with this page’s reduced settings, and include compiling with JAX for L-BFGS-B and NUTS (a few seconds, once per model); with the defaults, each posterior takes several times longer. The cost of each method is compared in the appendix.

Several methods in turn

With a list, each method starts from the best values of the one before, and the list stops at a method that doesn’t converge, with a warning (so a search that is still improving is not followed by a polish from the wrong place). A broad search followed by a local one is the usual pairing. A setting goes to the stages that take it, and an entry can be a dict to give one stage its own settings:

fit = deterministic.fit(method=['optuna', dict(method='nelder-mead', maxiter=100)], n_trials=200, verbose=False)
fit.pars
sc.obj(beta=0.2774217981901826, dur_inf=days(9.17002))

The polish ends at the values that Nelder–Mead found on its own, above.

Appendix: every fitting method

Every method that sim.fit(method=...) takes, what it gives, which kinds of model it suits, and what it costs. “ODE with JAX” is a deterministic model whose whole run JAX can compile (see Gradients); “stochastic compartmental” is one run by the kernels from start to finish (sim.kernel_only()); “agents” is solver='abm', or a stochastic compartmental model with Python in its loop. The costs are rough, in runs of the model, with the default settings and two or three parameters.

Method Gives ODE with JAX ODE without JAX Stochastic compartmental Agents Needs Rough cost, in runs Choose it when
'nelder-mead' Best fit Yes (default for one or two parameters) Yes (default) Poorly (noisy scores) Poorly Nothing A scan of 10 per parameter, then a few hundred per search, 3 searches A deterministic model with few parameters
'powell' Best fit Yes Yes Poorly Poorly Nothing As Nelder–Mead Nelder–Mead is slow to settle
'l-bfgs-b' Best fit Yes (default for three or more) No No No Gradients A scan, then tens of runs with gradients per search Many parameters (e.g. a time series) of an ODE
'slsqp' Best fit Yes No No No Gradients As L-BFGS-B As L-BFGS-B
'optuna' Best fit Yes Yes Yes (default) Yes (default) Nothing 100 trials, of 4 runs each (1 for agents) A stochastic or agent model, or a first broad search
'if2' Maximum-likelihood best fit No No Yes No A likelihood; parameters that are rates 4 chains × 50 passes × 1,000 particles (each particle a run, run together) The maximum likelihood of a stochastic model
'nuts' Posterior Yes Slowly, with nopython=False No No A likelihood; gradients 4 chains × 1,000 steps, each tens of runs with gradients A posterior of an ODE, whose data have little chance in them beyond the likelihood’s
'pmcmc' Posterior No No Yes No A likelihood 4 chains × 2,000 draws × tens to hundreds of particles A posterior of a stochastic compartmental model, with its process noise
'abc-smc' Approximate posterior Yes Yes Yes Yes A goodness of fit (no likelihood) 200 particles × 8 generations, at one to several runs each A posterior of an agent model, or with no likelihood
A list What its last stage gives What each stage needs The sum of its stages A broad search, then a local polish

The names come from ss.fit.methods, and the settings each takes from ss.fit.method_options(), so the list of settings can be made from them, with the defaults from each method’s signature (a SciPy method also takes SciPy’s own options, and Optuna those of study.optimize(), which are listed with their defaults too):

import inspect
import optuna

rows = []
for method, func in ss.fit.methods.items():
    defaults = {key:p.default for key, p in inspect.signature(optuna.Study.optimize).parameters.items()}
    defaults |= {key:p.default for key, p in inspect.signature(func).parameters.items()}
    settings = [f'{key}={defaults.get(key)}' for key in ss.fit.method_options(method)]
    rows.append(dict(method=method, settings=', '.join(settings)))
pd.DataFrame(rows).set_index('method')

A default of None is chosen by the fit: for scan, 10 points per parameter, up to 100; for restarts, 3 searches (1 for one parameter of a deterministic model); for particles, 200 for 'abc-smc' and chosen in each chain’s warm-up for 'pmcmc'; for n_workers, 1. What each setting means is in the API docs of ss.fit.fit_scipy(), fit_optuna(), fit_if2(), fit_nuts(), fit_pmcmc(), and fit_abc_smc() (see ss.fit). Their samplers are also callable directly, for a log-density of your own (such as sim.log_density(); see Gradients): ss.fit.nuts(), ss.fit.pmmh(), and ss.fit.abc_smc().
