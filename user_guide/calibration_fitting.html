Fitting a model

🧠10% 🤖90%

Disease models usually need to be fitted to a particular setting before they can answer “what if” questions about it. Calibration is fitting a model’s parameters to data: finding the values for which the model’s results match what was observed. A model of a measles outbreak, for example, may know how long people are infectious from the literature, but not how fast measles spreads in this particular town, or what share of cases were reported. Those are the parameters to estimate from the data.

There are many approaches to calibration, from tuning parameters by hand to fully Bayesian methods. For many applications an optimization-based approach, which looks for the single set of values that fits best, is enough for a first exploration: it avoids the tedium of tuning by hand, and costs much less than a Bayesian method. The optimizer chooses values, the model is run with them, its results are compared with the data, and a measure of the mismatch tells the optimizer where to look next, until it settles on the values that fit best. When the question needs the uncertainty in the values too, a posterior (the distribution of values consistent with the data) can be fitted instead.

In Starsim, calibration needs two things, each stated where it belongs:

  • Which parameters are unknown, and the range of values each could take: a parameter with bounds, such as ss.par(1.5, bounds=[0.5, 4]).
  • The data, attached to the sim, in columns named like the results they measure.

sim.fit() then fits every parameter that has bounds to every result that has data. There is no function to write that puts each value into the model, and none that pulls out the results to compare: the model already knows where each parameter is used and what each result is.

This page covers the options. The calibration tutorial goes through one fit step by step; Parameter identification is about whether the data can determine the parameters at all; Gradients covers posteriors and profile likelihoods; Fit diagnostics covers what to check afterwards; and Optimization uses the same machinery to allocate a budget.

The smallest example

The model is a measles outbreak in a town of 100,000 people, 90% of whom are already immune by vaccination. People are infected (S to E), become infectious about 10 days later (E to I), when the rash appears, and recover after about 8 days (I to R). The reported cases are a share of the people whose rash appears, report. Three things are unknown: the transmission rate beta, the share reported, report, and how many people were infectious at the start, I0, as a share of the town. The last is nearly always unknown for a real outbreak, since the first cases are rarely reported, and it sets when the outbreak takes off:

import numpy as np
import starsim as ss

S, E, I, R = ss.states('S E I R')
beta   = ss.par(1.5, bounds=[0.5, 4])       # Transmission rate per day: unknown
report = ss.par(0.3, bounds=[0.05, 1])      # Share of cases reported: unknown
I0     = ss.par(0.0001, bounds=[1e-5, 1e-3]) # Share infectious at the start (10 people): unknown

infection = S >> E @ beta*I
onset     = E >> I @ ss.days(10)  # The rash appears about 10 days after infection
recovery  = I >> R @ ss.days(8)   # Infectious for 8 days on average
cases     = ss.outcome(report*onset) # Reported cases: a share of the onsets
measles = ss.Disease(infection, onset, recovery, cases, init=dict(I=I0, R=0.9))

pars = dict(total_pop=100_000, start='2025-01-01', stop='2026-01-01')

The value given to each parameter is where the search starts, and the bounds are the range it searches. A parameter is named by its variable (I0 here), or by name=.

The data are weekly reported cases. On this page they are illustrative: made once from an agent-based run of the same disease, in which each infection is a chance event (so its outbreak is not the smooth curve of the ODE fitted below), with beta = 1.9, half of cases reported, and 30 people infectious on 1 January, and with weekly counts that vary more than Poisson counts would, as reported counts usually do. With real data, the data would be read from a file instead (see below):

truth = ss.Sim(measles, pars=dict(beta=1.9, report=0.5, I0=0.0003), n_agents=100_000, rand_seed=3, verbose=0, **pars)
truth.run()
data = truth.to_data('cases', resample='week', noise=None).iloc[:-1] # Weekly cases, leaving out the last, partial week
rng = np.random.default_rng(3)
data['cases'] = rng.negative_binomial(10, 10/(10 + data.cases)) # Counts with more variation than Poisson (negative binomial)

β and the share reported are close to the values the data were made with (1.9 and 0.5). The initial infections are not: the fit finds about 13 people, not 30. In the agent-based run, the first chains of transmission are chance events, some of which die out, and its outbreak took off later than an ODE starting from 30 people would; the fit finds the start that gives an ODE the same timing. That is what a fitted initial condition means: not a count of who was infectious on 1 January, but where the model has to start to match the data. The fitted model against the data:

What is fitted

Every parameter with bounds is fitted, wherever it is: a rate, a share, a duration, an initial condition, a parameter of a network or an intervention, or a setting of the sim. A duration’s bounds are in its own unit, e.g. ss.par(ss.days(8), bounds=[5, 12]) for between 5 and 12 days. Each kind, with how it is named in fit.pars, is listed in the appendix.

  • An initial condition is a parameter like any other, as I0 is above: init=dict(I=ss.par(...)) for a share of the population, or init_n=dict(I=ss.par(10, bounds=[1, 100], name='I0')) for a number of people. Without the name of a variable (or name=), it can’t be named, which is an error that says so.

  • A setting of the sim, ss.Sim(n_agents=ss.par(5000, bounds=[1000, 20000])), is fitted with a new sim for each value (e.g. a population scale).

  • pars= fits only the parameters named, keeping the others at their values: sim.fit(pars=['beta']).

  • Wide positive bounds (where the high end is 10 or more times the low end) are searched on a log scale, since going from 0.05 to 0.1 matters as much as going from 0.5 to 1. The fit says which parameters it searches this way.

  • A prior, ss.par(1.5, bounds=[0.5, 4], prior=ss.normal(2, 0.3)), is used by the methods that use likelihoods: a best fit is then the most probable values rather than the maximum likelihood, and a posterior uses it as its prior. Without one, the prior is uniform over the bounds.

  • In a module written as code, a parameter given as ss.par is fitted and its code sees the value, including a value in a dict parameter, e.g. cin_fn=dict(k=ss.par(0.3, bounds=[0.1, 0.5])), fitted as cin_fn.k. A parameter with the same name in several modules is fitted with its module’s name, e.g. hpv16.rel_beta and hpv18.rel_beta; pars= and ss.Sim(pars=...) take either name.

  • A modifier’s amount, ss.modify(hiv.rel_sus, multiply=ss.par(2.7, bounds=[1, 4])), is fitted as multiply (or with the modifier’s name, if it is a parameter of a declared disease).

  • A parameter whose value is an array, with bounds for each element, has each element fitted, as curve[0], curve[1], …, except those whose low and high bounds are equal, which stay as they are: ss.par(np.array([0.1, 0.4, 0.2]), bounds=[np.array([0, 0, 0.2]), np.array([1, 1, 0.2])]). A time series with bounds, ss.par(ss.timeseries(days, [0.3]*10), bounds=[0.05, 1]), has each of its values fitted in the same way, named by its times (beta[0], beta[14], …), and fit.pars has the time series whole. Either has a gradient for each value, so a deterministic model is fitted by gradients. penalty= adds a function of the values to what a best fit minimizes, e.g. to keep a curve smooth: sim.fit(penalty=lambda pars: 10*np.sum(np.diff(pars['curve'], 2)**2)).

A value that isn’t a parameter

A value set in code, such as a setting of an intervention that its constructor doesn’t take, or anything the model works out from it, is fitted by writing a function that sets it, with the value as a keyword argument given as ss.par, and giving the function as a module. A function given as an intervention is called at every step, with its keyword arguments as the module’s parameters:

def set_testing(sim, symp_prob=ss.par(0.1, bounds=[0.01, 0.5])):
    sim.interventions.testing.symp_prob = symp_prob
    sim.interventions.testing.asymp_prob = symp_prob/10

sim = ss.Sim(..., interventions=[set_testing, testing], data=data)
fit = sim.fit() # Fits symp_prob, with the others

The value is a parameter like any other: fit.pars.symp_prob, ss.Sim(pars=dict(symp_prob=0.2)), sim.sensitivity(), and ss.parallel(sim, pars=dict(symp_prob=[0.1, 0.2])) all find it by name. A module added after the sim was made (e.g. sim.pars.analyzers += my_analyzer) is kept by sim.new(), and so by the runs of a fit.

The data

The data has a time column (date, year, t, or time; an integer year is a calendar year), or dates as its index, and one column for each data series, named like the result it is compared with: here cases. With several modules, a column that could match more than one result is named with its module, e.g. measles.cases. Any result can have data, including an analyzer’s (by_age.cancers_0_15), a result nested deeper in sim.results (hpv.genotype.cancers), and a column of a result with columns (sis.infection.alpha), so gof= is needed only for targets worked out from the results, such as a share.

The data need not be on the model’s time step, and nothing needs to say how to line the two up, since each result knows what kind of quantity it is:

  • A flow, like reported cases, is summed over each interval of the data: weekly data is compared with each week’s total.
  • A stock (like the number infectious) or a ratio (like prevalence) is compared with the model’s value at the data’s time.
  • Data by calendar year is compared over the year it names: a flow summed over it, and a stock or ratio averaged over it.

data= takes a dataframe or a file name. Real files rarely arrive with matching headers, so ss.simdata() renames columns on the way in, and can ignore the columns not needed:

data = ss.simdata('town_cases.csv', aliases=dict(cases='Reported cases (weekly)', date='Week ending'), ignore_extra=True)
sim = ss.Sim(measles, data=data, **pars)

A column that matches no result gets a note listing the closest result names when the sim is initialized, and is an error when the fit compares the data with the results, so a typo in a header is caught. weights= gives series different weights, e.g. sim.fit(weights=dict(cases=1, deaths=5)).

Measuring the fit

Without a likelihood, the measure of fit is the normalized absolute error: for each data series, the mean absolute difference between the model and the data, divided by the mean of the data. It needs no assumptions about the noise in the data, and puts series of different sizes on one scale. gof='rmse' uses the root mean squared error instead, and gof= can also be a function of the sim that returns the mismatch to minimize (lower is better), e.g. to bring data of its own:

def peak_error(sim):
    """ How far the model's peak week is from the observed peak, in weeks """
    weekly = sim.results.measles.cases.resample('week')
    return abs(weekly.values.argmax() - data.cases.values.argmax())

fit = sim.fit(gof=peak_error)

A likelihood says how the data vary around the model’s value: the model’s value is the mean of the distribution, and the likelihood supplies the rest. It can be declared on the outcome, where it is used by every fit, or given to the fit by the name of the data series:

cases = ss.outcome(report*onset, likelihood=ss.poisson()) # On the outcome
fit = sim.fit(likelihood=dict(cases=ss.nbinom(n=10)))     # Or for one fit

The likelihoods are ss.poisson() and ss.nbinom(n=...) for counts, ss.normal(scale=...) and ss.lognorm_ex(std=...) for continuous values, ss.binom(n=...) for the number positive in a survey, and ss.bernoulli() for yes-or-no outcomes; the appendix says what each is for, and which work in JAX. A likelihood can also be a function of the data and the model’s values, fn(observed, model), that returns the log-likelihood of each, for one the list lacks (e.g. a normal whose standard deviation grows with the mean). A function can’t be differentiated in JAX, so the default fit then uses Nelder-Mead, which needs no gradients, and says so; a method that needs gradients ('l-bfgs-b' or 'nuts') is an error that says why.

When every data series has a likelihood, the fit maximizes the sum of their logs (the maximum likelihood estimate), and the methods that give a posterior can be used. Reported cases vary more than Poisson counts, so a negative binomial suits them; its dispersion n (a smaller n is more variable) is rarely known, so it can be fitted too, as a parameter with bounds:

dispersion = ss.par(5, bounds=[1, 100], name='dispersion')
fit_lik = sim.fit(likelihood=dict(cases=ss.nbinom(n=dispersion)), verbose=False)
fit_lik.table

The estimates are much like those of the normalized absolute error, as both fit the same curve; the likelihood weighs each week by how much it is expected to vary, and gives the methods that need one (posteriors, profiles) something to work with. The fitted dispersion is lower than the 10 that the counts were drawn with, since it also takes in the chance of the agent-based run, which the ODE doesn’t have.

To score a run against its data by hand, e.g. to compare scenarios, or to weigh runs for a posterior of your own, ss.fit.mismatch(sim) gives the normalized absolute error (or another gof=) and ss.fit.loglik(sim, likelihood=...) the log-likelihood (with by_series=True, for each data series):

print('Normalized absolute error:', ss.fit.mismatch(fit_lik.sim))
print('Log-likelihood:', ss.fit.loglik(fit_lik.sim, likelihood=dict(cases=ss.nbinom(n=fit_lik.pars.dispersion))))

How the fit is found

By default a fit is a best fit (a single set of values), by a method that suits the model, which sim.fit() prints with its reason. A posterior (the distribution of values consistent with the data) is always asked for by name:

The model The default method (a best fit) A posterior, by name
Deterministic (an ODE) 'l-bfgs-b', a gradient-based optimizer; 'nelder-mead' for one or two parameters, or when the model can’t be differentiated 'nuts' (the No-U-Turn sampler), given a likelihood for every series
Stochastic compartmental 'optuna' 'pmcmc' (particle MCMC), given a likelihood for every series
Agent-based 'optuna' 'abc-smc' (approximate Bayesian computation), which needs no likelihood

'powell' and 'slsqp' (two more methods of scipy.optimize.minimize) can also be given, as can 'if2' (iterated filtering, for a stochastic compartmental model). Fitting methods compares them all, with the settings of each and an example. A list, such as method=['optuna', 'nelder-mead'], runs each method in turn, each starting from the best values the one before found, and stops at a method that doesn’t converge.

The gradient-based methods and their posteriors are covered in Gradients.

A stochastic model

A stochastic model gives a different result on each run, so each set of values gives a noisy score. Starsim fits a stochastic model with Optuna, a library for searching over parameters, which tries values, scores them by running the model, and uses the scores to choose where to try next. Here is the same model as a stochastic compartmental model (a chain binomial, in which the number of people who move between states each day is random):

sim = ss.Sim(measles, data=data, solver='binomial', **pars)
fit = sim.fit(n_trials=300, rand_seed=5) # More trials than the default 100, for three parameters
fit.summarize()

The estimates are less precise than those of the ODE: each score is noisy, so the search can settle anywhere in a region of similar scores (the spread of the best tenth of the trials, spread_lower to spread_upper, is wide), and a fit with another rand_seed gives somewhat different values. With three parameters, the default 100 trials are not enough for the search to settle, and the fit says it has not converged; here it is given 300. Fit diagnostics shows how to check how much this matters.

The options that matter for a stochastic fit:

  • n_trials= is the number of sets of values to try (100 by default). Use more for more parameters.
  • n_runs= is the number of runs that each set of values is scored by: 4 by default for a stochastic compartmental model, and 1 for agents. Each trial uses fresh random seeds, so that the search averages over chance rather than fitting one run’s luck; the best fit is then the trial among the best tenth whose neighbors score best, rather than the luckiest. reseed=False scores every trial with the same seeds instead, e.g. for a rare outcome, where fresh seeds let the search favor values whose runs were lucky.
  • rand_seed= makes the fit itself reproducible.
  • n_workers=4 runs the trials in 4 processes at once, and storage='fit.log' keeps the trials in a file, so that calling fit() again with the same file carries on where it stopped.
  • fit.study is Optuna’s study, for its plots, e.g. optuna.visualization.plot_param_importances(fit.study).

Agents are fitted the same way, e.g. ss.Sim(measles, data=data, n_agents=20_000, **pars).fit(n_trials=200). With agents each run is slower, and with few people in the model the noise is larger, so a fit usually needs more trials.

fit.sim is one run with the best values. Since the model is stochastic, it is more useful to run it many times, and see whether the data lie within the range of the runs:

msim = fit.sim.run(n_runs=20)
msim.plot('measles.cases')

The plot shows the median and 95% of the 20 runs, as weekly totals, against the data.

Using the fit

The calibrated sim is the starting point for scenarios. sim.new() makes a new sim from the same inputs, with whatever is given changed; from fit.sim, that includes the fitted values. Here, a catch-up campaign on 1 April, well before the peak, that vaccinates half of the people who are still susceptible (found, say, from vaccination records), compared with none:

vaccination = ss.vaccinate(efficacy=0.97, who=measles.S, coverage=0.5, at='2025-04-01')
scenarios = {
    'No campaign': fit.sim.new(),
    'Campaign':    fit.sim.new(interventions=vaccination),
}
msim = ss.parallel(scenarios, n_runs=20)
msim.plot('measles.cases')
msim.summarize().loc['measles_cases']

These runs use the best values only, so their spread is chance alone, not the uncertainty in the fitted values. For projections that carry that uncertainty too, fit a posterior and use fit.project(); see Gradients, and T7 for a projection from early data checked against what happened next.

To forecast beyond the data, fit the data so far and run on past them: fit.project() passes its other arguments to sim.new(), so fit.project({'No campaign': None, 'Campaign': vaccination}, stop='2026-06-01') runs each scenario to June 2026, from the best values (or from draws of a posterior).

Which parameters matter

Before calibrating, it helps to know which parameters the results depend on at all, since a parameter that does not matter cannot be fitted either. sim.sensitivity() needs no data: it samples the parameters over their bounds, runs the model at each sample, and gives the partial rank correlation of each parameter with a summary of each result. Near 1 or -1, the result goes up or down with the parameter (with the others held fixed); near 0, it doesn’t depend on it:

sens = sim.sensitivity(n=50, verbose=False)
sens[['measles.I peak', 'measles.cases total']]
measles.I peak measles.cases total
beta 0.978549 0.854362
report -0.038828 0.740793
I0 0.379169 0.151421

Allocating a budget

The same machinery answers a different question: given the spending on each program as parameters of the model, how should a fixed total be divided between them to make a result as small (or as large) as possible? ss.fit.optimize() does this; see Optimization.

Pitfalls

  • A best value at a bound. The fit warns (AtBound) when a best value is at the edge of its bounds: the best value may lie beyond it, so widen the bounds, or check that the parameter means what you think it does.
  • Parameters the data can’t tell apart. Two parameters that only ever appear multiplied together (such as a contact rate and a chance of infection per contact) can’t be fitted separately; the fit notes this. See Parameter identification.
  • A lucky trial. In a stochastic fit, the best trial may simply have been a lucky run. The fit reruns the best values with the same seeds, and says so if they then score worse than the starting values; use more trials, or more runs per trial (n_runs=).
  • A column that matches nothing. Data columns are matched to results by name; a column that matches no result is an error when fitting, with the closest names suggested.
  • Too few runs to judge. One run of a stochastic model, with the best values, says little about whether the model fits; compare the data with many runs, as above.

More checks are in Fit diagnostics. How the fitting works, and how the method is chosen, is explained in Randomness.

Appendix: what can be fitted

Every kind of value that a fit can take as a parameter, and how it is named in fit.pars (and so in pars=, ss.Sim(pars=...), and sim.sensitivity()):

What Given as Named in fit.pars

Appendix: likelihoods and priors

The likelihoods that likelihood= (or ss.outcome(..., likelihood=)) takes. In each, the model’s value is the mean (or, for a share, the probability). “In JAX” means that the log-likelihood can be taken in JAX, as gradient-based fits and NUTS need for a model that runs as an ODE:

Likelihood For data that are In JAX
ss.poisson() Counts, such as reported cases Yes
ss.nbinom(n=...) Counts that vary more than a Poisson, with n the dispersion (a smaller n is more variable); n can itself be an ss.par with bounds, and is then fitted too Yes
ss.normal(scale=...) Continuous values, with the standard deviation scale Yes
ss.lognorm_ex(std=...) Positive continuous values, with the standard deviation std Yes
ss.binom(n=...) The number who test positive out of n people surveyed (the data column holds the number positive), with the model’s value, a share such as a prevalence, as the probability Yes
ss.bernoulli() Yes or no outcomes Yes
A function fn(observed, model) Anything else: it returns the log-likelihood of each value No: the default fit uses Nelder-Mead; a method with gradients needs nopython=False

The priors that ss.par(..., prior=) takes, used by the methods that use likelihoods (a best fit is then the most probable values, and a posterior starts from them). Without one, the prior is uniform over the bounds:

Prior In JAX
ss.normal(), ss.lognorm_ex(), ss.lognorm_im(), ss.gamma(), ss.beta_dist(), ss.beta_mean(), ss.expon(), ss.uniform() Yes
Any other distribution that has a density (e.g. ss.weibull()) No: it works with the methods that run with Python in the loop

Appendix: what a fit holds

The attributes of the ss.fit.Fit that sim.fit() returns (see ss.fit.Fit):

Attribute What it is
fit.pars The best values, which can be passed to ss.Sim(pars=...)
fit.sim The calibrated sim: a copy of the original with the best values, already run
fit.before The sim with the starting values, already run
fit.table Each parameter’s starting value, best value, and bounds; with a posterior, also its median, 95% interval (lower, upper), rhat, and ess; with Optuna and IF2, spread_lower and spread_upper (the range of the best 10% of trials, or of the chains’ estimates: an indication of the uncertainty, not an interval)
fit.method The method used
fit.mismatch, fit.mismatch_before The goodness of fit (or the negative log-likelihood, or the negative log-posterior) at the best values, and at the starting values; fit.measure says which
fit.scores The score of the best values in each run (one for a deterministic model); mismatch is their mean, and their spread is the run-to-run noise of a stochastic fit
fit.converged, fit.why Whether the method reached its own stopping rule, and how it decided (see Fit diagnostics)
fit.trials, fit.to_df() Every evaluation: the values tried, and the objective at each
fit.samples With a posterior, the draws: one row each, with its chain and number
fit.diagnostics divergences (NUTS), acceptance (particle MCMC: the share of proposals each chain accepted), and band (with a posterior, 95% of the model’s values over draws from it, which fit.plot() draws)
fit.study With Optuna, Optuna’s study, for its plots
fit.summarize(), fit.plot(residuals=), fit.project(scenarios, n=, **kwargs) The table with the fit before and after; the model against the data (and the residuals); runs of scenarios from the fit (draws of a posterior, or the best values), with kwargs for sim.new(), e.g. stop=
