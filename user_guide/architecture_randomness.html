Randomness

🧠0% 🤖100%

This page covers how Starsim handles randomness, so that runs are reproducible and scenario comparisons aren’t swamped by noise: random number streams, common random numbers, what identifies a run, and how the same machinery serves calibration. For the modeler’s view, with examples, see Random numbers and Distributions.

Random streams

Every distribution has its own random number stream, seeded from the sim’s rand_seed and the distribution’s name, which is its path in the sim. In a stochastic compartmental run (binomial, tau, gillespie), each module has its own generator, seeded from rand_seed and the module’s name, and draws its flows in an order set by the names of its states and transitions rather than the order they were declared in. The streams of a declared disease are named after its states and transitions:

import starsim as ss

S, I, R = ss.states('S I R')
sir = ss.Disease(infection=S >> I @ 0.2 * I, recovery=I >> R @ ss.days(10), init_prev=0.01, name='sir')
sim = ss.Sim(sir, networks=ss.RandomNet(), n_agents=1000, verbose=0)
sim.init()
print([name for name in sim.dists.dists if 'infection' in name or 'recovery' in name])
['diseases_sir_engine_dists_dst_infection', 'diseases_sir_engine_dists_mix_infection', 'diseases_sir_engine_dists_dst_recovery', 'diseases_sir_engine_dists_mix_recovery', 'diseases_sir_engine_dists_dwell_recovery']

So:

  • Adding a module doesn’t change the draws of any other module.
  • Reordering modules doesn’t change which random numbers each distribution receives (though it can still change results, since a module may then act on different state).
  • The runs of a MultiSim are identical whether run in parallel or in serial.

The first is easy to check:

import numpy as np

def make_sir():
    S, I, R = ss.states('S I R')
    return ss.Disease(infection=S >> I @ 0.3 * I, recovery=I >> R @ ss.days(10), init_prev=0.01, name='sir')

def make_flu():
    S, I = ss.states('S I')
    return ss.Disease(infection=S >> I @ 0.2 * I, recovery=I >> S @ ss.days(5), init_prev=0.05, name='flu')

for kw in [dict(networks=ss.RandomNet(n_contacts=4), n_agents=2000), dict(solver='binomial', total_pop=10_000)]:
    alone = ss.Sim(make_sir(), unit='day', stop=ss.days(60), verbose=0, **kw).run()
    both  = ss.Sim([make_sir(), make_flu()], unit='day', stop=ss.days(60), verbose=0, **kw).run()
    same = np.array_equal(alone.results.sir.infection.values, both.results.sir.infection.values)
    print(f'{alone.solver}: SIR results unchanged by adding flu:', same)
abm: SIR results unchanged by adding flu: True
binomial: SIR results unchanged by adding flu: True

Every draw goes through one small library (solvers/backends/draws.py, compiled with Numba, or its Rust copy, which gives the same numbers bit for bit). Uniforms are counter-based (a SplitMix64 hash of a key and an index), so a draw doesn’t depend on what was drawn before it, or on how the work is split across threads. Most distributions are drawn by inverting their CDF at one uniform, so each draw is a monotone function of its uniform. That property is what makes common random numbers work well: a small change to a parameter moves each draw a little, rather than reshuffling them. The distributions themselves (ss.Dist and its subclasses) are in starsim/distributions.py.

Common random numbers

With common random numbers (CRN), the same agent making the same decision gets the same random number in the baseline and in the intervention scenario. Much of the Monte Carlo noise then cancels in the difference, so small effects can be seen with fewer runs. CRN is on by default.

The key is the agent’s slot, a persistent index that Starsim maintains for exactly this purpose: agent 7’s uniform for a given decision depends only on its slot and the distribution’s stream, not on how many other agents drew from that distribution. A newborn’s slot is drawn from its parent’s stream, so the same birth gets the same slot in both scenarios. The guarantee is: agents with the same slot in both scenarios get identical draws from every paired distribution; agents born after the scenarios diverge may have no counterpart.

CRN has limits. It pairs draws, not outcomes: for a large change, or late in an epidemic, the scenarios infect different people and the noise grows back. It doesn’t cover sampling without replacement or joint draws across agents. And a compartmental run has no agents to pair, so two scenarios start from the same draws but drift apart once their counts differ. ss.options.crn = False turns it off. The user guide’s Random numbers page shows CRN at work.

Run identity

A seed makes a run repeatable, but doesn’t say what was run. The record of that is the code (the commit of the script), with the seed (rand_seed): the same code and seed give the same results on every machine. Two versions of a model are compared by their code (in a text editor), their describe(), or their results.

A related check is sim.check_dt(), which reruns the sim at half the timestep and reports how much each result moves. That covers every effect of order dt at once: converting rates to probabilities, the one-step delay between modules, and module order.

Randomness in fitting

Calibration needs no vocabulary of its own: sim.fit() fits every parameter with bounds (ss.par(0.2, bounds=[0.05, 0.5])) to every result with data, matched by column name (Calibration shows it at work). What it does need is a way to score a stochastic model whose every run is different, and that is where the random number machinery comes in.

Common seeds. A stochastic sim is scored at each point by the mean of several runs (4 for a stochastic compartmental sim, 1 for agents), with the same seeds at every point, so the score changes with the values rather than with chance (and with common random numbers, the runs at nearby values are paired draw by draw). A local method such as Nelder-Mead needs this, or its steps would follow the noise. Optuna, the default for stochastic models, is the exception: it takes fresh seeds at each point, since with one seed everywhere its search would find the optimum of that seed’s realization (reseed=False turns this off).

Many runs at once. A stochastic compartmental run taken by the kernels in one call can be run as many runs of the same program that differ only in their seed (Compartmental.run_many()), and as many particles stepped forward together (ss.solvers.Particles, in solvers/particles.py), each with its own random numbers. At each data point the particles are weighted by the likelihood and resampled, which gives an unbiased estimate of the likelihood. That is what particle MCMC ('pmcmc') and iterated filtering ('if2') need, and why they are offered only for runs the kernels take whole.

No randomness at all. The ODE is run by the kernels with fourth-order Runge–Kutta steps. For a gradient, ss.gradients (starsim/internals/gradients.py) takes the same program and runs the same steps in JAX, which differentiates them; the cheap steps on either side (parameters to the program’s numbers, and the run to results and the goodness of fit) are done by central differences, so the gradient is accurate to about 1e-9. For NUTS the whole log-density (run, likelihood, and priors) is one JAX function. Gradients need a run the kernels take whole, so a when= function, a movement register, or code of your own rules them out, and the printed reason says which.

So the method a fit uses by default follows from what the sim is: L-BFGS-B with gradients for an ODE (Nelder-Mead for one or two parameters), and Optuna for a stochastic model; a posterior is always asked for by name ('nuts' for an ODE, 'pmcmc' for a stochastic compartmental run taken in one call, 'abc-smc' otherwise), so the same call asks the same question on every machine. Every fit says whether it converged (fit.converged, fit.why), by what the method knows: R-hat and divergences for NUTS, whether separate searches agree for the SciPy optimizers, recent improvement for Optuna. A best fit at a bound raises the warning ss.errors.AtBound.

The fitting code is the submodule ss.fit (starsim/fit.py), which an ordinary run never imports. It wraps existing optimizers and samplers (SciPy, Optuna, BlackJAX) rather than reimplementing them; particle MCMC and ABC-SMC are short samplers written in Starsim, since they need the sim’s own particles and runs. The same module has sim.sensitivity() (partial rank correlations over a Latin hypercube of the bounds), ss.fit.compare_models(), ss.fit.profile(), and ss.fit.optimize(). See the calibration tutorial, Fit diagnostics, and Gradients.
