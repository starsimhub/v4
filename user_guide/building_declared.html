What can be declared

🧠0% 🤖100%

A Starsim model is made of two kinds of part. A declared part is a description that Starsim reads: states, transitions and their rates, conditions, interventions, and results. A part written as code is a Python function or class that Starsim calls as the model runs. This page lists what can be declared, how to mix the two, and what each costs in speed.

For how to write a declared model, see Writing models; for modules written as code, Custom modules. For questions such as “can people die” or “can I double a rate”, and whether each runs under every solver, see Will my model run as an ODE?.

Why the difference matters

A declared part can be read, so Starsim can do more with it:

  • It runs under every solver: as an ODE, as a stochastic compartmental model, or as agents (as long as nothing in it is about individuals; see below).
  • It can be shown: describe(), equations(), diagram(), and R0() include it.
  • It is fast: a compartmental model that is all declared runs in compiled code, the whole run in one call, and can be differentiated for fitting.

Code can do anything, but Starsim can only call it. A model with code in it still runs, and runs well, but the code is opaque: it is called at each step, it isn’t in the equations, and in a compartmental run it takes the run out of compiled code a step at a time.

The vocabulary, by idea

Each row is an idea from epidemiology, how it is declared, and an example of a related idea that the vocabulary can’t say, which would be written as code.

Conditions

A condition says who something applies to: who= on ss.modify(), transitions, events, and deliveries; and an event, or a condition that moves people as soon as it holds, says when, in when= (or ss.on()). Conditions are built from:

A condition on Example Runs as compartments?
A state who=hiv.I Yes
The number in a state, or the fraction who=sir.I.n >= 20_000, who=sir.I.frac >= 0.02 Yes, in compiled code
The incidence over a period who=infection.incidence(over=ss.days(7)) > 0.01 Yes, a step at a time
How incidence is changing who=weekly > infection.incidence(over=ss.days(14)) - weekly (this week more than last) Yes, a step at a time
Dates start=, stop=, when= Yes, in compiled code
A person’s traits who=ss.person.age < 5, who=ss.person.female Only if the model is stratified by them; otherwise as agents
Any of these combined & (and), \| (or), ~ (not) As the least of its parts

A condition can also be a function of the sim that returns true or false (for a whole compartmental population) or an array (one value for each person or group). That is for what the list above can’t say, such as “while weekly incidence is above half its highest so far”, which needs a memory of the highest so far.

Here are three measures that cut transmission by 30% while a condition holds, for an influenza-like infection with waning immunity:

import numpy as np
import starsim as ss

S, I, R = ss.states('S I R')
infection = S >> I @ 0.3*I
recovery  = I >> R @ ss.days(10)
waning    = R >> S @ ss.days(180)
flu = ss.Disease(infection, recovery, waning, init_n=dict(I=100), name='flu')

weekly = infection.incidence(over=ss.days(7)) # The fraction of people infected in the last 7 days
last_week = infection.incidence(over=ss.days(14)) - weekly
measures = {
    'No measures':                    None,
    'While 20,000 are infectious':    ss.modify(flu.pars.beta, multiply=0.7, who=flu.I.n >= 20_000),
    'While 1% are infected a week':   ss.modify(flu.pars.beta, multiply=0.7, who=weekly > 0.01),
    'While infections are rising':    ss.modify(flu.pars.beta, multiply=0.7, who=weekly > last_week),
}
pars = dict(total_pop=1_000_000, start='2026-01-01', stop='2027-12-31', verbose=0)
msim = ss.parallel({label: ss.Sim(flu, interventions=measure, **pars) for label, measure in measures.items()})
msim.plot('flu.I')

All four run as ODEs. With waning immunity, the measures lower the first peak and spread out the later ones.

What makes a model run as agents

A declared model runs as compartments unless something in it needs individuals. The common reasons are:

  • A network of individual contacts (ss.RandomNet, ss.SexualNet)
  • A condition or rate on a person’s traits (ss.person.age) that the model is not stratified by
  • A value that varies between people (a distribution, or ss.attr())
  • How long ago, or how often, something happened to each person (.since, .n_times)
  • A module written as code that keeps a value for each person
  • n_agents=, or solver='abm'

The sim prints which solver it chose and why (sim.solver_reason), and the full list is in Solvers and backends.

Mixing declared and coded parts

Declared and coded parts sit in the same sim, and each can read the other: code reads the declared model’s states, transitions, and parameters by name, and a declared modifier can take its amount from a function. Custom modules combines a declared disease with an antibody level written as code.

A function can also stand in for one value in a declared model: a rate (S >> I @ my_rate), the amount of a modifier, or a condition. The rest of the model stays declared, and is still shown by describe(), with the function by name; in a compartmental run, the run is then taken a step at a time rather than in one call to compiled code. Here is the first measure above, with its condition written as a function:

def many_infectious(sim):
    """ True while 20,000 or more are infectious """
    return sim.diseases.flu.I.n >= 20_000

measure = ss.modify(flu.pars.beta, multiply=0.7, who=many_infectious)
sim = ss.Sim(flu, interventions=measure, **pars)
sim.describe()

Performance

A compartmental model that is all declared runs in compiled code, the whole run in one call; a function, a module written as code, or a condition that needs a memory of past steps takes it a step at a time, with the same results but slower, for a small model many times so (how much depends on the model). For one run this doesn’t matter, but for a fit of thousands of runs it does, so where a declared form can say the same thing, it is worth using. As agents, the model is taken a step at a time anyway, and code of your own costs what its own work costs: written with NumPy on whole arrays, or as a loop compiled with @ss.jit, it adds little; as a loop in Python, a lot. Speed and scale gives figures for both.
