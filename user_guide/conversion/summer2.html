summer2

🧠0% 🤖100%

This page is for people who build compartmental models with summer2 in Python, often in or near the AuTuMN group: a base model stratified by age, clinical status, immunity, strain, or place, each stratification with flow adjustments, infectiousness adjustments, and a mixing matrix; parameters that vary in time; derived outputs; and calibration through JAX. It shows a summer2 model next to the same model in Starsim, how their results agree, how long each takes, and what works and what does not yet, including what fails.

The same model in both

summer2’s mixing-matrix example: an SIR with deaths, stratified by age and by location, with a mixing matrix for each:

import numpy as np
from summer2 import CompartmentalModel, Stratification, Multiply
from summer2.parameters import Data

def build_model():
    """Returns a model for the mixing matrix examples"""
    model = CompartmentalModel(
        times=[0, 20],
        compartments=["S", "I", "R"],
        infectious_compartments=["I"],
        timestep=0.1
    )
    model.set_initial_population(distribution={"S": 990, "I": 10})
    model.add_infection_frequency_flow(name="infection", contact_rate=2, source="S", dest="I")
    model.add_transition_flow(name="recovery", fractional_rate=1/3, source="I", dest="R")
    model.add_death_flow(name="infection_death", death_rate=0.05, source="I")
    return model

# Age stratification with young/old mixing
age_strata = ["young", "old"]
age_strat = Stratification(name="age", strata=age_strata, compartments=["S", "I", "R"])
age_mixing_matrix = Data(np.array([
    [0.2, 0.3],
    [0.5, 0.7],
]) )
age_mixing_matrix.node_name = "age_mixing"
age_strat.set_mixing_matrix(age_mixing_matrix)

# Location stratification with urban/rural mixing
loc_strata = ["urban", "rural"]
loc_strat = Stratification(name="location", strata=loc_strata, compartments=["S", "I", "R"])
# Rural people have worse health care, higher mortality rates,
loc_strat.set_flow_adjustments("infection_death", {
    "urban": None,
    "rural": Multiply(3),
})
loc_strat.set_population_split({"urban": 0.7, "rural": 0.3})
loc_mixing_matrix = Data(np.array([
    [0.8, 0.2],
    [0.2, 0.8],
]))
loc_mixing_matrix.node_name = "loc_mixing"
loc_strat.set_mixing_matrix(loc_mixing_matrix)

model = build_model()
model.stratify_with(age_strat)
model.stratify_with(loc_strat)
model.run()
model.get_outputs_df().plot()

In Starsim, a stratification is one call, with its split and its adjustments, and the two mixing matrices are one ss.contacts():

import starsim as ss

S, I, R = ss.states('S I R')
sir = ss.Disease(
    infection       = ss.Transition(S, I, rate=2 * I),
    recovery        = ss.Transition(I, R, rate=1/3),
    infection_death = ss.death(I, rate=0.05),
    init_n          = dict(I=10),
)
sir.stratify(age=['young', 'old'])
sir.stratify(location=['urban', 'rural'], split=[0.7, 0.3], adjust={'infection_death': [1, 3]}) # Rural people have worse health care

mixing = ss.contacts(dict(age=[[0.2, 0.3], [0.5, 0.7]], location=[[0.8, 0.2], [0.2, 0.8]]))
sim = ss.Sim(sir, networks=mixing, total_pop=1000, dt=0.1, stop=20, verbose=0)
sim.run()
sim.plot()
Starsim kernels: Rust, OUT OF DATE (built before its source last changed, so results may be wrong): run "./build" in starsim/solvers/rust/

Every flow and state is a result, by group, so summer2’s output requests are selections: sim.results.sir.infection.select(age='old', location='rural') is request_output_for_flow(..., dest_strata=...). The same model runs as a stochastic compartmental model or as agents with solver='binomial' or solver='abm', which summer2 cannot do.

How the results agree

Model Agreement
The mixing-matrix example (above) Agree: every compartment within 0.08 people of 1,000. The stochastic and agent-based runs give the same number recovered, within 1% (means of 100 runs)
An SEIR with clinical status entered by age, infectiousness and death adjusted by clinical status, and seven derived outputs Agree: every compartment within 0.0006 people of 1,000, and every derived output within 0.005% of its peak
A TB model in 36 compartments (six ages with aging and a mixing matrix, reinfection, births and deaths, and case detection scaled up over time by summer2’s sigmoid times a fitted maximum) Agree: every compartment within 8 people of 1.24 million (6e-6); active TB within 1 person in 1990, 2010, and 2025, and notifications within 0.5%

What works and what does not yet

These are from Starsim’s switching demo for summer2 users (tests/switching/test_summer2.py in the lingua_franca_design repo), which checks each task against summer2’s numbers, and from the review it was built from. “Fails” means the demo’s check does not pass today.

Task Today
The TB model above, written by hand in about 25 lines Works: agreement as above
Fit by NUTS when a fitted parameter multiplies a time series (case detection as a fitted maximum times a scale-up) Works: the log-density in JAX equals the sim’s, and NUTS runs on the JAX path with no divergences and recovers both values within 5%
The log-density as a JAX function, for a sampler of your own (numpyro, estival) Works: sim.log_density(), with .grad() by reverse mode
Calibration by optimization Works: sim.fit() chose L-BFGS-B with JAX gradients for the TB model, and recovered the two values from summer2’s output to 0.2%
Import a live summer2 model, with its parameters and its time functions Not in the same process: summer2 1.3.6 needs JAX 0.4, so it cannot be installed with Starsim. The same model, written to JSON by starsim/converters/summer2.py in summer2’s environment, imports with nothing missing and matches the hand-written model to 1e-13
summer2’s sigmoidal scale-up Not yet: ss.timeseries has constant, linear, and cosine interpolation, so the sigmoid is sampled into a time series
A plain number times a time series (1.5 * ss.timeseries(...)) Works. A parameter with no name inline (ss.par(1.5) * ss.timeseries(...)) raises a ValueError asking for one: give it as ss.par(1.5, name='k'), or assign it to a variable first
The same model as a stochastic model or as agents Works: solver='binomial', 'gillespie', or 'abm'; at a yearly step the stochastic solvers can differ a lot from the ODE, and sim.check_dt() shows how much a smaller step changes the results
Interventions with costs (active case finding) Works: ss.treat(cure=0.7, transition='detection', cost=5, where=I, coverage=0.5, at=[2026, 2027])
Contact matrices and populations by country Works: ss.contacts('Philippines') and ss.people('Philippines', year=2021) are bundled

Bringing your model in

ss.import_from(model, pars=params) reads a live summer2 CompartmentalModel (if summer2 is installed alongside Starsim), and ss.import_from('model.json', format='summer2') reads the JSON written by starsim/converters/summer2.py run as a script, which runs in summer2’s own environment. Each flow becomes one transition with the matching kind of rate, and each stratify_with() a stratification, with its population split, flow adjustments, infectiousness adjustments, and mixing matrix. ss.converters.summer2.outputs(sim) works out summer2’s derived outputs from the results. What is not translated is listed (sim.imported.incomplete), and sim.imported.prompt is a prompt for an AI assistant with Starsim’s import-model skill to finish the job.

See Import/export for importing in general: checking an import, keeping it as code, and finishing one that is incomplete.
