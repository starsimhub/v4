Starsim 4: the full changelog

Every change made in developing Starsim 4, in detail, as recorded during development. The summary is in CHANGELOG.md, and the guide to moving code from Starsim 3 is v3_v4.md. Changes that may result in differences in model output are flagged with the term “Regression”; changes that may require updates to downstream code are flagged with the term “Migration”.

This version adds a way to write a model as declared states and transitions, which can then be run as an ODE, as a stochastic compartmental model, or as agents. Models written as code (ss.SIR, custom step() methods, etc.) still run, but their results are one step later than in Starsim 3 (see Regression below), so they agree with Starsim 3 statistically, not number for number. The migration guide (docs/migration/v3_v4.md) maps Starsim 3 code to Starsim 4.

Simplification

  • ss.TimeArr (float32 step numbers, NaN for never, with due() and .years) replaces ss.arrays.StepArr for every time of agents: the engine’s times of entering and leaving states, people.ti_dead and people.ti_removed. Results are unchanged; reading, writing and comparing them through the array is 2–10× faster (no conversion from 16-bit integers); memory is 2 bytes more per agent per time (LASER’s model: 51 to 66 bytes per agent). arr.due() gives whose time has come, e.g. mask = self.exposed & self.ti_infectious.due() in a disease written as code.
  • == and != on an ss.TimeArr raise, since a time drawn between steps never equals one exactly, so ti_x == ti quietly missed nearly everyone: ti_x.isclose(ti) gives whose time is at the step nearest ti (the rule due() uses, so for a declared state’s time of entering it is “entered this step”), and ti_x.eq(t) exact equality.
  • A time between steps is rounded the same way in a disease written as code and in a declared one run as agents: up or down at random in proportion, by each agent’s phase (ss.People.phase(), spread evenly over the slots and shifted by the seed: a time t is taken at step floor(t + phase)), so its mean is kept. ti_x.due() and isclose() use it, where due() took the nearest step (which loses the mean of a dwell shorter than a few steps), and the agent engine rounds its dwell times by it in place of a draw for each (one distribution fewer for each state, delay and transfer, and no memory per agent). For plain arithmetic, compare the times: ti_x < ti + 0.5 is the nearest step. Results of agent runs change, by chance alone.
  • A second module with a default name is numbered (clip_edges_1) with no warning, as a second modifier already was; a product renamed this way still warns, and two names the user gave still raise. ss.move() on a disease written as code says to set its states in code, and pars= with a key in a sim that has no parameters it can set says so (it raised a ValueError from the suggestion of names).
  • A sim setting given as ss.par with bounds (e.g. ss.Sim(n_agents=ss.par(5000, bounds=[1000, 20000]))) is fitted by sim.fit() like any parameter, with a new sim built for each value, and taken by name in pars= (sim.new(pars=fit.pars)); a setting given as a plain value in pars= raises, saying to give it to sim.new() or as ss.par. A number of agents that is not whole (as a fit chooses) is rounded to the nearest, for people made in advance too (it was truncated, and raised against people made in advance). Arithmetic between a typed value and a parameter that holds one keeps the unit (ss.weeks(40) - preg.pars.loss_threshold is weeks(20); it was 39.6 weeks, from the threshold’s value in years taken as weeks). After sim.shrink(), a disease written as code no longer holds the sim through its engine.
  • ss.by keeps one table of values for groups and agents: a value by groups is the table at each group’s position, and a value by people’s properties the table at each agent’s, so lookup_grid() and binned_grid() are gone (lookup(uids=) looks up some agents). Results unchanged.
  • Migration: there is no model spec. sim.to_code(), ss.diff(), sim.hash(), sim.to_spec() (and each module’s to_spec()), ss.save('model.py', sim), and ss.spec are removed: a model is its code, and two models are compared by their results, describe(), or a text diff of their code. An import still gives code: ss.import_from() writes the model as Starsim code (ss.converters.write()), kept as sim.imported.code, and the sim is that code run; a value an importer cannot write is given as ss.converters.Code. The exporters (SBML, odin) read the built model. A constant function in an imported rate (-log(1 - 0.1)) is now a number, so describe() shows it as a dwell time, with the same results.
  • Migration: ss.strains.Family is removed, with ss.Strains of diseases, shared=, and ss.immunity(rel_trans=, dur=) or from an attribute: strains with courses of their own are one disease per strain, connected by a connector (see Strains). It was about 1.5× slower than HPVsim’s coded genotypes. ssl.Dengue() is now a list of serotypes, with results sim.results.den1 and so on.
  • Migration: less machinery, with one way to do each thing: ss.Event, ss.child, ss.Transition(before=) (write rate*(X.time < d)), operator=, protection by memory (strains.last/.ever, ss.immunity(scale=, curve=, p=)), cross_immunity=, the clock dimension, ss.Loop(steps=) with no sim, Loop.plot_step_order(), the options license, date_sep, numba_indexing, jax_cache and check_method_calls, sim.to_yaml(), Module.requires, ss.save(format=) (use ss.export_to()), the Mermaid export, method='asd', and ss.jit on methods and classes are removed. ss.errors keeps 5 error classes (CapabilityError, AlreadyRunError, DistNotInitializedError, DistSeedRepeatError, BooleanOperationError) and 4 warnings; every other error is a built-in exception (ValueError, KeyError, …) with the same message. summarize_by= is the only spelling for how a result is summarized (kind= is gone, and ss.Result() raises on an unknown keyword).
  • One mechanism for each job: sim.new() is a copy of the sim as it was when init() started, plus the changes given to it (edits to an initialized sim belong to that run); a declared model’s layout is built once; every module reads a parameter’s current value (units, time, modifiers, level) the same way, and a coded module reads typed parameters with no conversion by hand; agents and coded diseases share one transmission (dis.current_value('rel_sus', uids)), so the same model written either way gives the same results, and a coded ss.Infection(strains=ss.Strains(...)) follows the same rules as a declared one; diseases tracked jointly are views of one set of compartments. ss.choice takes a row of p per agent (FPsim’s method choice 27–126 times faster), and ss.Result(..., groups=True) is counted by group from sim.groups.count() (STIsim takes 4.7 s, was 6.6). ss.par shows its label= in its repr and in describe(). dt=ss.datedur(months=1) runs with declared diseases, and monthly dates from the 31st stay at the end of each month.
  • The speed tests compare Starsim’s time, normalized to the reference machine with sc.benchmark() (tests/timing.py), with its own reference, and fail above 1.5 times it, as the performance guard does; another framework’s time is printed, not asserted, so the tests pass on a busy or slower machine.
  • Migration: an ss.Infection written as code transmits in transmit() (was infect()) and transmit_route() (was infect_route()); disease.infect(uids) infects those people now for every disease, declared or written as code (ssl.AgentSIR().infect(uids) raised a TypeError). The migration script renames overrides.
  • Migration: ss.contacts() takes one matrix and says what it is over: ss.contacts(M) for the model’s age groups (was age=M), ages=[0, 15, 65] for the matrix’s own age groups, dims='risk' or dims=['sex', 'risk'] for other stratifications (was risk=M), and a dict for a product of one matrix per stratification (ss.contacts(dict(age=A, area=B)), was age=A, area=B).
  • Migration: lactation is part of ss.Pregnancy (preg.lactating), and ss.Lactation, lactation='auto', and Module.link() are removed; ss.BreastfeedingNet reads preg.lactating.
  • Migration: the first state, where people start, is first= if given, else the state named S or susceptible, else the one state transmission infects people from, else the first state made (it raised); describe() says when it was guessed.
  • Births and deaths declared for the whole population with no disease (demographics=[ss.birth(...), ss.death(...)]) are a declared module like any other, so solver='auto' chooses for them as for any declared model (they were always agents); their results are sim.results.population.
  • ss.birth(rate=) and ss.death(rate=) of everyone (with no state given) read a bare number as ss.Births and ss.Deaths do: per year, and above 1 per 1,000 (ss.birth(rate=30) is 30 per 1,000 a year), with a note.
  • describe() shows each parameter’s bounds, each outcome’s definition, each stratification’s split and adjustments, and distributions as they were given (erlang(k=3, mean=10 days)), in plain words (“transmission, from I”, “time in I ~ …”); its solver plan is shown with verbose=True, and it leaves out step timing under the ODE, Gillespie, and tau-leaping. sim.describe() before a run no longer prints the run’s start line.
  • diagram() draws in a notebook and in Quarto, with values on the arrows (recovery: 8 days); str() of it is still the Mermaid text.
  • A MultiSim shows its progress: nothing for runs under a second, a bar for each of up to 10 slow runs, and otherwise one bar with the number of runs done; a line every tenth when the output is a file.
  • Dates print as 2000-01-07; a plot in a notebook no longer also prints Figure(640x480).
  • n_agents=None means not given (the default); n_agents=0 raises a clear error.
  • The Sim class holds less: building a declared model is in ss.solvers (choose.py), and the body of describe() is in display.py (sim.py is 1,840 lines, was 2,620).
  • Each built-in module’s docstring says whether it keeps common random numbers (“Note: CRN safe.”), and spec 11 lists them; test_crn_pairing now tests CRN directly, on ss.RandomNet(method='safe').
  • A run prints one line saying what it runs (Sim: sir, 10,000 people, as an ODE, days 0 to 100), R0, its notes, a progress bar redrawn in place, and a closing line with the time taken and each disease’s infections and peak; a MultiSim prints two lines. sim.describe() is in sections, in color in a terminal, as tables in a notebook, and as plain text otherwise.
  • Running a sim again runs it from the start, with any parameters changed since: sim.run() on a finished sim, and sim.run(solver='binomial', n_runs=20) on a sim built for another solver, need no sim.new(); sim.restart() builds the sim again where it can’t restart it.
  • Migration: sim.calibrate() is sim.fit(), and ss.contacts(bands=...) is ss.contacts(ages=..., matrix=...).
  • Shares by level as a dict: sir.stratify(age={0: 0.3, 15: 0.6, 65: 0.1}) (a dict was read as its keys, and its shares were dropped); ss.Disease(..., stratify=dict(age=...)).
  • A delivery makes its product from the product’s keywords: ss.vaccinate(efficacy=0.9, coverage=0.8, at='2025-02-01'), ss.treat(cure=0.95, ...), ss.screen(sensitivity=0.9, ...); an explicit product is still given for one product shared by several deliveries.
  • ss.parallel() takes a dict of sims by label ({'No intervention': s1, 'Vaccine': s2}); msim.summarize() is a table of each result over the runs (median, a 95% interval, mean, and standard deviation, by scenario); sim.to_data('cases', resample='week') draws data from a run, as Poisson counts, in the form ss.Sim(data=...) takes.
  • Docstrings, notes and error messages no longer mention Starsim 3, outside the migration tools; notes are plainer (e.g. the large-step note says how long people stay and how long a step is).
  • Regression: R0 (printed when a run starts, and from R0()) is the basic reproduction number, with everyone not infected susceptible; when people start immune, the run also says R at the start (R0 = 15.2 (R = 1.52 at the start, with 10% susceptible)).
  • A flow plotted against data at a longer period (weekly cases from a daily model) is shown as its totals over the data’s periods, as the fit compares them, in sim.plot(), msim.plot() (which shows the data too) and fit.plot(); msim.summarize(baseline='No intervention') gives each scenario’s difference from a baseline, run by run.
  • Building a second disease from the same states and transitions is safe and independent (a disease copies what another already owns); a module keeps the name of the variable it was made as, and a product made by a delivery is named vaccine (or <delivery>_product), with no warning.
  • sim.init() on a sim already initialized returns it; msim.sims['label']; by(...).summarize() is labeled by group; sim.hash(), ss.diff() and to_code() build a sim quietly; to_code() writes one-call deliveries and leaves out defaults.
  • ss.Sim(infection, recovery) (or a list of transitions, or diseases=) makes one disease from them, whose results are also at the top (sim.results.I); every module is also sim.<name> (e.g. sim.sir).
  • A rate can be written as the whole flow, as most other frameworks write it: S >> I @ beta*S*I/N (frequency-dependent) is beta*I, and beta*S*I (density-dependent) is beta*I.n.
  • Migration: the count of each state is the result named after the state, for every module: sim.results.sir.I (was n_I), sim.results.alive (was n_alive), and res.infected for a module written as code (was n_infected); the migration script renames Starsim’s own.
  • Regression: a disease with a transmission seeds 1% of people by default (init_prev=0.01), unless a state is given an initial value.
  • Whatever is compiled says so as it starts, with how long it takes (Compiling the agent solver with Numba, estimated time: 2-10 s): for Numba only when it is not in Numba’s cache, and for JAX once a session. A first ODE run no longer compiles a helper only to time a step (1.6 s, with nothing in the cache).
  • The test suite is split: the core tests (tests/test_*.py, about 300, under 15 s in parallel) are what ./run_tests runs, and the slower developer tests (contracts, inference, the spec, errors, importers and exporters, and the slower tests of each feature) are in tests/devtests/, run nightly in CI. JAX runs on the CPU in the tests.
  • A module’s plot() takes 'states' (the default), 'flows', 'all', or the names of results, in Starsim’s style; sim.plot() leaves out results that never change.
  • Migration: ss.PregnancyPars is removed (ss.Pregnancy defines its own parameters, in ss.Pregnancy().pars), as are Starsim 3’s pregnancy callbacks: add_conception_callback(fn) is preg.add_callback(preg.conception, fn), and add_delivery_callback(fn) is preg.add_callback(preg.birth, fn), called with the newborns. People.find_children() is removed (ss.uids(ppl.auids[np.isin(ppl.parent, parents)])), and ss.parse_age_range() and ss.utils.apply_age_range() moved to STIsim (an age band is a condition, (ppl.age >= 15) & (ppl.age < 25), or a stratification). The migration script flags each of these.
  • Migration: ss.PartnerNet (a Starsim 4 prerelease) is ss.DegreeNet, of which ss.SexualNet is a subclass (adding debut and participation), so both take the same targets; ss.Requires and sim.requires(), msim.outbreaks(), and back= and cap= of ss.geo.Mobility are removed.
  • Regression: a compartmental pars= sweep gives one scenario per value, as agents do (it was one scenario); a draw from a posterior or prior is a run within its scenario. One object used in several places (e.g. one ss.peryear(...) in two transitions) is one parameter, and pars=dict(dur=...) sets the sim’s dur unless the model has a parameter of that name.
  • Migration: removed root names say what replaced them (ss.Calibration → sim.fit()), with no misleading closest-name hint; ss.uids.cat()/concat() are removed (use concatenate()); ss.MultiSim.make_run() is a method, and a subclass adds its own run options with run_options. The migration script rewrites preg.breastfeeding, uniform_targets= and ss.State(infectious=), and flags compute_transmission(), the congenital death keys, ss.People() without ages, and nested follow-ups in a test that isn’t assigned.
  • Migration: ss.Strains(transmit='fittest') is removed; strains are carried only in the states of an infection and those that lead back to one, so a reinfection after clearance is with the new strain alone (describe() lists them); split= takes shares by label, including sets ({'DS': 0.5, 'DS+INH': 0.5}); strains.move((A, B), (A, C)) moves between sets.
  • Migration: ss.Disease is again the base of every disease, declared, written as code (Starsim 3’s class X(ss.Disease) works unchanged), or a mix of both; ss.Infection(ss.Disease) adds only transmission written as code. DiseaseBase is removed.
  • Regression: the time index is the same in every phase of a step (sim.ti == k throughout step k, with sim.now its start), so self.results.x[self.ti] is right wherever it is written; the loop records index 0. Deliveries’ results moved one index later, run(until=) includes the step that starts at until, and ti_entry is removed.
  • Migration: init= is shares of people and init_n= numbers of people; the first state is first=, else a state named S/susceptible, else the first state made.
  • Migration: strains are part of the disease, ss.Disease(strains=ss.Strains(...)), with ss.immunity(due_to=...) replacing protected=; arrow strings are gone (move=DS >> RIF, ss.Delivery(move=S >> V), ss.transfer(risk=('low', 'high'))).
  • Migration: ss.SexualNet(between=) replaces sides= ('mf', 'mm', or two groups, with n_contacts by group and match=).
  • sim.current_scale is public again, verbose takes a fraction again, module lists take one level of nesting, and Results.flatten() keeps case.
  • Starsim 3’s calibration (ss.Calibration, ss.CalibComponent and its likelihoods), interventions and products (ss.RoutineDelivery, ss.CampaignDelivery, ss.BaseTest and the other base classes, ss.treat_num, ss.Dx/Tx/Vx), ss.Samples/ss.Dataset, ss.Debugger, ss.check_version, msim.extinction()/outbreaks(), sim.R0(), sim.solvers() (now part of describe()), Starsim 3’s attributes and result names of ss.Pregnancy (pregnant, ti_delivery, tri1_uids, births, n_fecund, …; set_delivery() reschedules a delivery), and the aliases and error messages kept for Starsim 3 and prerelease names are removed; the migrate-starsim3 skill and python -m starsim.converters.migrate (moved from starsim.migrate) cover each. msim.to_hub() is ss.converters.to_hub(msim). Also removed: stock targets (target=, above=, ss.share), ss.Resource, ss.cascade (give the steps as a list), ss.visit (ss.Delivery(who=...) with no product), and count_events=.
  • Regression: code is no longer run on a throwaway sim to choose the solver. An analyzer, a plain ss.Module, a function given as a module, and a declared disease’s own step() and functions run beside the compartments without changing it from an ODE; a function that needs agents says so when it runs, and compartmental = False on a module says it needs agents.
  • A sim always copies the inputs it is given, together, when it is made (copy_inputs= is removed), and no longer rewrites the functions given to it: a function reads modules from the sim it is given (lambda sim: sim.diseases.sir.I.n), not from a variable.
  • Regression: a smaller set of declared features has a compartmental form; the rest run as agents under auto, and a compartmental solver asked for stops before the run: fetal levels, ss.mother(), ss.Lactation, rates that read the time in a state, clocks, ss.attr, ss.update, queues, delays, .since/.count, waning by a function, events combined, deliveries to several diseases, and coupled ss.Strains. ss.Pregnancy keeps a small compartmental form when a compartmental solver is named. A follow-up of a cure got about 11% too few people as compartments.
  • import starsim no longer imports starsim.library; import it to use it. Another framework’s model is read with ss.import_from() and written with ss.export_to(); ss.load() and ss.save() are for Starsim’s own objects.
  • ss.Loop(steps=[...], times=...) runs ordinary functions with no sim (step(t, dt), and record(t) at each time point), at shared or separate times.
  • A sim written only as code honors unit= (it ran in years); an unknown keyword to any module names the module.
  • ss.SIR, ss.SIS, and ss.SEIR no longer have new_infections and cum_infections, which repeated their infection flow and its total (res.infection, res.infection.cum); their prevalence is declared in the class as a ratio of states, as any model’s is. standard_results is removed, and a data column called new_infections is no longer matched to a declared disease’s transmission. Diseases written as code (ss.Infection, ssl.AgentSIR) keep both.
  • In a sim with dates, a whole year within the sim given as a number (at=2005, start=1980) is that year, since a time that long after the start would be outside the sim. A product whose delivery took its name from their shared variable is named for its kind (bcg_vaccine, not bcg_bcg), and a module passed through a helper’s interventions variable keeps its default name. ss.pars() takes a value that varies in time or by level in place of a rate or duration. Reading a result from a module given to a sim (which ran its own copy) says where the result is. The migrate script also rewrites the code cells of .ipynb, .qmd, and .md files, renames solver='stochastic', and flags f'n_{state}' and quoted 'n_<state>' names.
  • Migration: ss.options.kernels ('auto', 'rust', 'numba' or 'python'; STARSIM_KERNELS) replaces ss.options.compile: 'always' is 'numba', and 'never' is 'python'. @ss.jit raises when Numba can’t compile a function, rather than running it as Python, unless given nopython=False.

Fixes

  • A binomial or Poisson draw with a NaN input or a count too large for exact draws (2^53 or more, on the side of the draw: n·p or n·(1−p) for a binomial) gives NaN: binomial(inf, p) looped forever, poisson(1e19) gave -2^63, and a NaN n or p gave 0.
  • A modifier’s set= of a dwell time that is a distribution gave different results run to run with the same seed (its stream’s seed held a memory address).
  • S >> I @ ss.gamma(...)*I works (it raised WrongDimension), as does ss.by(herd=np.array(...)) (it raised ShapeError); a one-destination split (ss.Transition(I, [F], p=[1.0], rate=...)) is a plain transition, so several compete as rates (it raised BadBranchSplit).
  • ss.RandomNet(n_contacts=0) makes no edges (it raised ZeroDivisionError); several Mobilitys on one dimension give a clear error; a non-reciprocal contact matrix is noted as agents too.
  • Density-dependent transmission (S >> I @ beta*I.n) has an R0 (R0() raised “Singular matrix”), and describe() no longer counts recovered people as infected.
  • Regression: each posterior draw in priors= and fit.project() has its own seed (all ran with the sim’s), so quantiles include chance; seeds in a pars= sweep are runs within a scenario, and msim.runs has a rand_seed column.
  • Regression: whether JAX or the kernels take a compartmental run, and whether the kernels are compiled, depend only on the model’s size, never on timing a step or on Numba’s cache (a seeded ODE run could differ at float rounding from run to run).
  • Regression: infectious people placed at the start transmit for their whole stay on a network, a mixing pool or beta*I well mixed (they lost the first step, and with a one-step stay never transmitted).
  • Regression: a declared disease’s time of entering a state (ti_X) reads as the index of the step the move happened in, for a progression as for an infection, so ti_X == self.ti is “entered this step” in code (a progression read a step early, so STIsim’s ANC testing found nobody); a scheduled exit (ti_exit_X) reads as the step it will be taken in, so np.ceil(preg.ti_exit_P) is the step of the delivery. No model’s dynamics change: the engine keeps its own times (internal()), and the clocks are unchanged. ss.Pregnancy’s ti_delivered and ti_live_birth are the step’s index, and set_delivery(uids, ti) takes the step of the delivery.
  • Regression: with strains.ever, agents’ protection on the course of an infection (p=, dur=, rel_trans) counted the infection’s own strain, so first infections were protected; and the traits of people made by code with people.grow() and no age= (as Starsim 3’s pregnancy and STIsim’s and HPVsim’s migration do) were drawn from a default age, so newborns got adults’ traits: they are now drawn at the next step, from the age the code set.
  • In a disease with strains, a rate on counts (beta*I.frac, beta*I.n) is refused with ss.errors.StrainsByCount, since new cases took the split’s strain rather than the infector’s; write beta*I. sim.new(solver=...) puts substeps= back to the new solver’s default unless it is given too, so an importer’s whole steps for the chain binomial don’t become one Runge-Kutta step for the ODE.
  • Regression: the chain binomial takes substeps by default so that about a tenth of a compartment at most leaves in one (substeps=1 for whole steps; the importers of discrete-time models ask for it); with a stay of about a step it was far from the ODE. The ODE no longer gives a negative flow for a count growing within a step, nor takes millions of substeps for a strain only starting to emerge.
  • Regression: silent wrong answers fixed in strains (ss.immunity(due_to=) of a non-infectious stage, seeding through every transmission), pregnancy (a death of another cause loses the pregnancy whether or not fetuses are agents; ss.Deaths no longer applies to fetuses), an infinite rate (now certain within the step), declared modules’ counts of their own ss.BoolStates, ss.by() of histograms, derived attributes before the first step, priority=[due, ss.ppl.age], levels outside a dimension’s where=, and calibration (parameters changed after the sim was made, one ss.par held twice, bounds lost in a package’s Pars, a time column beside the data’s index).
  • solver='auto' runs agents for a Weibull or gamma dwell scaled by group whose spread is too wide for stages, and for a condition on a property that is not a dimension; a per-agent read of a state in a compartmental run raises CapabilityError; JAX’s chain binomial runs on a machine whose JAX defaults to a GPU; a compartmental map between groups too big for memory is refused with its size.
  • preg.P.time read from code is a duration in the sim’s unit, NaN outside the state, so preg.P.time < ss.weeks(13) is right (it was true for nearly everyone).
  • Regression: a modifier, change or product that nothing would apply raises ss.errors.Unapplied when the sim is built; products now act on a coded disease that overrides infect(), and changes on inflows apply under the ODE.
  • Regression: as agents, drawn dwells are rounded to whole steps at random, keeping the mean (dur=0 stays instant); a country’s contact matrix is contacts a day whatever the sim’s unit (it was 365× too low in a sim in years).
  • Regression: silent wrong answers fixed in births (lost births with short dwells, ss.null parents, newborns’ ages and traits, ss.histogram draws), crossings (the ODE lost people with a fixed dwell), counts at long steps (substepped), weighted agents’ coded results, products shared between deliveries, ss.by keys, dwells after a change of level, STIsim’s aging (a setting changed before init() was overwritten), and calibration (calendar-year data, bounds lost in Pars.update(), “converged” at the start).
  • Many crashes in expressions (ss.by arithmetic, ratios of flows, ss.ppl in modifiers) are fixed, with one table-driven test over every solver.
  • Regression: a duration drawn from ss.choice of typed values (ss.choice(a=ss.weeks([...])), as dur_pregnancy is) was read as bare numbers in the sim’s unit, so it was right only when that unit was the values’ own; it is now converted.
  • Regression: a drawn attribute (ss.attr(dist, on=)) with typed values was drawn in steps rather than in the sim’s unit, so a comparison with a clock (preg.P.time >= anc_ga) was off by the step size.
  • A distribution with a named parameter (ss.bernoulli(ss.par(0.6, name='sero'))) can be drawn in an attribute (it raised a TypeError); the parameter is a parameter of the module, so pars= and a calibration set it.
  • A modifier that reads an attribute with init= no longer raises ClockOutsideDomain in a sim with births: the check for a NaN amount looked at the spare slots in the arrays, for people not yet born, as well as at the people alive. The error now says what has no value (a clock, or an attribute with no init=), and how to give it one.
  • A newborn’s level of a dimension called sex now follows the sex drawn at birth by ss.birth() (they could disagree).

A stochastic compartmental sim (solver='binomial', 'tau', or 'gillespie') whose data series all have a likelihood is fitted by particle MCMC (method='pmcmc'): a random-walk Metropolis sampler on the likelihood as estimated by a particle filter (ss.fit.ParticleFilter), which samples the exact posterior; the particles are stepped together by the kernels, each chain chooses how many it needs in its warm-up, and the chains run in parallel.   • Modifiers and conditions: ss.modify() changes a named quantity (a parameter, a transition’s rate, sir.rel_sus, or sir.rel_trans) while a condition holds, for everyone or for the people selected by where=; ss.change() changes one at given times; sim.what_modifies() lists what acts on a quantity. hold= keeps a modifier on for someone for a while once its condition holds for them, and tr.incidence(over=, by=) is a condition on how many went through a transition over a window, as a share of the people at the same level of a stratification, so that each place can apply a rule on its own (MEmilio’s dynamic NPIs). A modifier that depends only on time, and on who it applies to only through states and stratifications (where=hiv.acute), is worked out before the run, as is a transfer at a constant rate, so a compartmental run stays in one call to the kernels. Conditions are written against the people and modules themselves ((ppl.age > 65) & sir.S) and are evaluated when the sim runs (ss.conditions.Cond), or are functions of the sim. A condition in one disease on a state of another (ss.modify(hiv.rel_trans, multiply=3, where=syph.I)) also works in a compartmental run: the states of the two diseases are then tracked jointly, as a dimension of the sim for each (so hiv.results.n_I.by('syph') splits HIV by syphilis state), and the two have the same people, as agents do. A dimension of some states of one of them (e.g. a strain of its infected states) is allowed. As an ODE, diseases tracked jointly take a whole run together (each taking each step in turn, as they do step by step), so they can be restarted, differentiated, and fitted by NUTS. A modifier on a transition chosen with p= (one of several branches out of a state) changes its probability, and the other branches share the rest; a vaccine’s efficacy against such a transition (efficacy=dict(severe=0.75)) does the same. ss.modify('school.pars.n_contacts', multiply=0.2) changes the contacts of a network, under every solver (as agents, each contact then happens with that probability in a step). As agents, sir.current_value('rel_sus') gives the values with the active modifiers applied (reading sir.rel_sus gives the base), and with ss.Sim(track_writes=True), sim.what_modifies() also lists the modules that assigned rel_sus or rel_trans directly.

  • Modifiers of coded parameters: ss.modify() works on the parameters of a disease written as code, which reads the modified value from self.pars; where it differs between people, the disease reads self.current_value('x', uids) and lists the parameter in allow_modifiers. current_value() also works on the parameters of a declared disease.

  • Interventions: ss.Vaccine, ss.Diagnostic, and ss.Treatment are products, delivered by ss.vaccinate(), ss.screen(), and ss.treat() in rounds, routinely, on an event (on=sir.infection), or by a function, with where=, coverage=, and capacity=; a follow-up is a step of its own (ss.treat(..., who=screening.positive)). trace= delivers to the contacts, in a network, of the people selected, for contact tracing and partner notification (agents only). ss.transfer() with delivery keywords moves people along a stratification; a transfer can be the target of ss.modify(). A delivery’s results can be selected by stratum. These run under every solver: holding a product is a per-agent property in an agent-based run and a stratification in a compartmental one. A test’s delay= and a product whose protection fades by a function of time (waning=lambda t: ...) now work in a compartmental run too: people wait for their result, or hold the product, in levels of one or more steps. ss.death(lifetable=ss.lifetable(ages, deaths)) draws each person’s age at death once from a life table as agents, and is a death rate for each age group in a compartmental run stratified by age; a delivery with move= and capacity= seeds a number of people on a schedule. As agents, a transition can wait for a minimum stay in its source state (after=), apply only during one (before=, as EMULSION’s escape), and ss.birth(NB, per=tr, n=3) gives each person who goes through a transition newborns; the EMULSION importer translates minimum stays as after=. ss.vaccinate(move=S >> V) moves the people reached from one state to another (a one-off campaign), ss.Vaccine(leaky=False) fully protects a share efficacy of those who receive it and leaves the rest unprotected, and at_age= delivers routinely as people reach an age.

The priors are the parameters’ prior= (uniform over their bounds by default), and the fit has the draws (fit.samples), each parameter’s median, 95% interval, rank-normalized R-hat, and bulk effective sample size, and a band over the posterior in fit.plot(). The log-density covers several diseases, including diseases tracked jointly, and outcomes that people stay in; a model it does not cover yet is sampled with Python in the loop, which is much slower. Data by stratum is given in long form, with columns named after dimensions (age) saying which stratum each row is for; each result and stratum is a series (n_I[age=0-14]), compared with res.n_I.select(age='0-14'). A fit notes parameters that the data cannot tell apart (ss.errors.Unidentifiable): ones that appear in the model only multiplied together (or one divided by the other), with the product the data determine; ones almost perfectly correlated over a posterior; and, for a fit by gradients, ones that change the fitted results in almost the same way at the best fit. What JAX compiles is kept for later sessions, in ~/.cache/starsim/jax (unless JAX_COMPILATION_CACHE_DIR says otherwise). In the JAX run, flows are added up with matrices rather than at indices, which makes a gradient about twice as fast.

Changes that may affect results

  • Regression: as agents, the engine’s draws are keyed by stream, step, and round of moves (not by how many times a stream has been called), so a run doesn’t depend on how a round’s work is batched; results with a seed differ from before, and agree statistically. STARSIM_CHECK_DRAWS=1 checks that no agent is drawn twice from a stream in a round.
  • Regression: as agents, people infected by transmission have half a step of exits at their first draw, as other arrivals do, so a model in which infection leads straight to an infectious state no longer runs as if R0 were R0 × (1 − γ·dt/2) at coarse steps (an SIR with an 8-day recovery at an 8-day step: an attack rate of 0.77, was 0.07; the ODE’s is 0.80). Models with a latent state are unchanged. The recorded prevalence reads about γ·dt/2 high at coarse steps, since stocks are recorded after the step’s infections.
  • on_positive=/on_negative= are removed (a follow-up is a step of its own: who=screening.positive); ss.Test is now ss.Diagnostic, and the result diagnosed is positive. ss.People.age etc. are removed: use ss.ppl.age. python -m starsim.converters.migrate rewrites nested follow-ups and mf beta pairs.
  • On networks with acts, rel_trans, rel_sus, source weights and modifiers multiply the hazard of each act (beta 0.03 with rel_trans=10 gives 0.263 per act); ss.MFNet’s acts are a rate (lognormal, mean 80 a year), kept as real acts per step, so results no longer depend on the time step; a typed rate as beta on such a network (including ss.SIS’s and ss.SIR’s defaults on ss.MFNet) raises WrongDimension; a beta pair in a declared disease raises. Mother-to-child networks transmit one way.
  • ss.Deaths and ss.Births hold each period’s rate until the next (not the nearest year); ss.Births picks parents from women aged 15 to 49; ss.Pregnancy gives women 46 to 49 the 45–49 rate, reads p_loss per week of pregnancy, and applies rr_ptb to the preterm share; the unborn are left out of the people counts (results.pregnancy.n_unborn) and are not seeded; deaths claimed by two modules in a step are counted once.
  • Newborns are born in their mother’s place, and a sex dimension follows the newborn’s sex; a split over age and another dimension given as shares within each age group keeps people’s ages.
  • adjust= on a branch chosen with p= scales its probability (as ss.modify does), not its dwell; as agents, a product’s efficacy against a dur= transition now acts.
  • The ODE’s fixed delays (ss.constant) let the state’s other exits act on the people due to leave until they leave, so a competing exit acts over the whole delay (it missed half a step: a 12-day incubation with mortality 0.1 a day kept 5% too many).
  • Clearer errors where the model reviews hit crashes: one transition with several destinations, p=, and no rate or duration says to write a transition for each destination; a sum of states as a transition’s source says to write a list; a function in p= that gives a row per person is refused; a modifier named like a property of people says to rename it; a network asked for by name in a compartmental run points to sim.all_networks(); a coded module’s update_results() that fails at the first time point says it now runs there, before any step; ss.par(<several values>, bounds=) is refused; a parameter with no name gets a sensible example name.
  • Fixed crashes: a branch share by level (p=[ss.by(risk=...), None]) at seeding as agents (it also seeds each group at its own share, not the mean); ss.change on a beta for each route with a pair of directions; a coded module’s array as a modifier’s amount (multiply=coded.factor); ss.diff() of modules written as code; a module-level ss.par used in the class form keeps its name; a comparison such as Q.n < 20 as where=; ssl.MSMNet gives newcomers a debut.
  • A remainder branch (p=None) can sit beside a timed exit for other people: the remainder is the timed exit with the same where= as the branches (women split between CIN and clearance, men only clear).
  • New: ss.move(src, dst, p=, n=, uids=) (also disease.move()), a one-off move of people between states of a declared disease from code, the same under every solver (the number of people in a state of people, sir.I.n, is read, not set); .n (people) and .count() on states under every solver; ss.Births(birth_rate='nigeria') and ss.Deaths(death_rate='nigeria') load the UN rates; people.n in a compartmental run gives each group’s size, and repr(sim.people) says groups; a swept set of values is a scenario of its own ('beta=0.1'); .by() across runs returns levels that .plot() draws together; conditions keep their modules by name, which makes many modifiers faster (88 lazy modifiers: 0.43 s against 0.55 s).

  • People hold the values of a numeric dimension, binned into its levels: stratify(wealthquintile=[1, 2, 3, 4, 5]) gives people the values 1 to 5 (they held 0 to 4, binned by the edges 1 to 5, so the top level was empty). A property people already have (ss.People(extra_states=[...])) is kept and binned, not overwritten from the split, and split= for it raises.
  • A bare dt beside calendar-year start and stop is in years, with a warning, when the model’s typed values are in another unit (dt=1/12 with durations in months gave 1/12 of a month). ss.choice and ss.histogram take unit=, and ss.choice takes typed values (a=[ss.months(9), ss.months(10)]), so either can be a dwell time.   • ss.seasonal(peak=) refuses a number outside 0 to 1 (a peak of 142 was taken as 0.0, January), and takes a time of year, peak=ss.days(142).
  • Notes when solver='auto' runs agents with each agent standing for more than 1,000 people, and when a sim is stratified but none of its modules is declared (so no results are by group).
  • A note when ss.PartnerNet(match=...) matches partners by a property but everyone has the same number of partners (n_contacts=ss.by(...) gives more at some levels), and when a contact matrix by a dimension is not reciprocal for the dimension’s split (N_i·C_ij against N_j·C_ji); both are used as given.

  • As agents, a dwell time drawn when someone entered a state follows them when they move to a level where the transition runs at a different speed (adjust= by a dimension people move along: a transfer, a move=, age, or migration); they kept the dwell drawn at the first level (with recovery ten times slower in the level moved to, 0.37 still infected at day 20 against the ODE’s 0.83; now 0.82). About 4% slower for agent models with such an adjustment.
  • As agents, a state left only by branches with no wait (ss.Transition(J, A, p=0.3) and ss.Transition(J, B, p=0.7)) is passed through at once, as in the ODE; people were held in it for a step (HPVsim review HP2).
  • People infectious at the start (in a state an infection puts people into) have been so for the first step, as if infected in the step before: as agents their ti_I is -1, and in a compartmental run with a fixed delay they start one slot along. A seeded case with a fixed stay of one step was infectious for two steps under every solver, so the Reed-Frost model’s chance of no further case was 0.013 against the exact 0.131 (canon review CR4).
  • ss.MFNet draws the age of debut for anyone who has none on each step (newborns, and people who arrive at any age, who before were never given one and so never joined), and draws whether a person takes part when they reach their debut, so a participation probability by age is read at that age (it was drawn at birth, at age 0). ssl.MSMNet does the same. People born during a run now join the network at their debut (about 16 by default), so long runs with births have more partnerships (the baseline’s 20-year run: mfnet_n_edges +8.8%). With n_contacts=, in an open population people look for partners more (or less) often by a factor that keeps the mean number of partners at the target, since partners die and newcomers start with none (with 20-year partnerships and births and deaths, 0.86 against a target of 0.87; it was 0.65). mean_degree and concurrency are per person, so no longer multiplied by the population scale (0.551 became 110.1 with total_pop=1e6).
  • res.resample('year') and resample('month') on a sim with dates put the point on 1 January (or the 1st of the month) in the period before, since it closes the step that ends there, so a run from 2000 to 2003 has three years, not four with the last of one point; use_years=True labels each year by the year it covers.
  • res.resample('year') of a stock (n_alive, n_infected) gives its value at the end of each year, where Starsim 3’s annualize() gave the mean over the year; summarize_by='mean' gives the mean.
  • The time between two dates (ss.date(2010) - ss.date(1990)) is ss.days (here ss.days(7305)), not ss.datedur. ss.datedur is a thin wrapper of pd.DateOffset, taking whole numbers of years, months, weeks, and days (ss.datedur(months=1)); a fraction (ss.datedur(years=0.5)) raises an error that points to ss.years(0.5), and a time before year 1 is ss.years, not ss.datedur.
  • ss.SIR, ss.SIS, and ss.SEIR are the textbook models: dur_inf and dur_exp are the means of exponentials (a number is in years), and p_death defaults to 0. Starsim 3’s models, with a lognormal dur_inf and p_death=0.01, are ssl.AgentSIR, ssl.AgentSIS, and ssl.AgentSEIR. dur_inf=[mean, std] now raises an error, and python -m starsim.converters.migrate flags each use of ss.SIR, ss.SIS, and ss.SEIR.
  • An agent-based fit scores each point by one run (n_runs= for more), as Optuna’s search already learns from nearby points; stochastic compartmental fits keep four runs a point. Under Optuna each point takes fresh seeds, so the search averages over chance rather than fitting one seed’s realization, and the best values are those of the trial whose neighbors score lowest (a kernel average), since the single lowest trial is the luckiest; local methods such as Nelder-Mead keep the same seeds at every point. EpiModel’s fit (test_epimodel_fit) goes from 23.4% to 30.4% prevalence against the 30% fitted to.
  • A data series that is all zero is scaled by the model’s mean in the default goodness of fit, so it adds at most 1 instead of its raw counts (before, 420 deaths a week swamped a fit to cases).
  • NUTS chains start at optima found from the best points of a scan, so they no longer agree on a mode far below the best (1.75% of two-parameter fits in a simulation-based calibration).
  • The ODE’s automatic substeps also follow how fast a compartment grows through its inflows, not only how fast it is left, so a fast epidemic at a daily step is within about 1e-4 of the exact solution (Keeling and Rohani’s program 2.1 was 2.5% off); about 1.0 to 1.2 times the run time. The camdl and flepiMoP importers take one RK4 step a step, as those programs do.
  • An initial value given for the first state is kept: init=dict(S=0.1, I=1e-4) starts 10% susceptible, with the rest in the one state given no value (it put everyone else in S); if no single state is left for the rest, it is an error.
  • Any transition out of a disease’s first state is an acquisition, whatever its rate, unless a contact-mediated one leaves that state: rel_sus, a scalar vaccine efficacy, and ss.treat now act on infections by a bite rate, an EIR, or a reservoir (they did nothing). The infected states of a vector model include those whose count infects the vector (Eh, Ih in Ross-Macdonald), so ss.treat reaches them, and R0() of a vector model is the next-generation value at the vector’s disease-free equilibrium (it was 0).
  • As agents, counts (mosquitoes, a reservoir) take substeps as the ODE does, so they no longer die out or grow without bound at a long step; modifiers of their transitions apply (they were ignored); and people’s rates that use a count take it once advanced, as specified.
  • As agents, a dwell time already drawn follows a later change to its duration or rate (a modifier or ss.change() on the duration parameter, or a duration or rate that varies in time), as the ODE does; before, only a modifier on the transition was followed (a halved duration gave 825 infected on day 25 against the ODE’s 498).
  • As agents, where= on a transition with a dwell time takes effect for people already waiting once it holds (people who turned 30 during a run never left).
  • As agents, a rate competing with a dwell time acts over the whole dwell for people who entered by a progression (it missed the first step: a one-month dwell with a competing rate of 1 per year lost nobody to it, against 8%).
  • Compartmental runs follow a modifier or ss.change() on a parameter in a branch probability (p=); before, the share stayed at its starting value (0.2 against 0.8 as agents). Separate transitions with p= are decided on entry, one transition with several destinations at exit, with p evaluated then (now documented).
  • A fixed delay (ss.constant as a dwell time) in a compartmental run is a conveyor of whole steps, not 50 Erlang stages, so it is exact rather than approximate.
  • The particle filter draws each particle’s random numbers from a stream of its own, so its estimates for a given seed differ from before (statistically the same), and do not depend on the number of threads.
  • With several declared diseases, births or deaths reach every disease under the compartmental solvers (before, the other diseases had a fixed population); demographics=True with a declared disease runs births and deaths as its transitions (the same model, other random draws).
  • Time names: the time vocabulary is ss.dur, ss.per, and ss.prob, with ss.days to ss.years and ss.perday to ss.peryear; a probability per period is ss.prob(0.1, 'day') (and prints so). ss.probperday to ss.probperyear, ss.freq and ss.freqperday to ss.freqperyear, and the one-unit instances ss.day to ss.year stay. Removed: the Starsim 2 names ss.rate, ss.time_prob, and ss.rate_prob, deprecated in Starsim 3. A name that Starsim no longer exports raises an error that says what to write instead. ss.dur(3) and ss.per(2) need a unit (they were years).
  • Docs: the design specification (docs/design/ in the lingua_franca_design repo) matches the code: departures folded in, promised-but-absent features struck or moved to docs/admin/deferred.md, settled open questions closed; its code blocks (every chapter), error catalog, and vocabulary counts are checked by tests/test_spec.py. The best-practices documents keep only their argument, with links to the design for the specification.
  • Saved forms: a model is saved as code with ss.save('model.py', sim) (which writes sim.to_code()), and a sim with its results with ss.save('run.sim', sim); the model spec (sim.to_spec(), and disease.to_spec(), which disease.to_json() also gives) is the normalized form for sim.hash() and ss.diff() and is no longer read back (ss.from_spec() and ss.load() of a spec are removed). An outcome’s likelihood is written in the spec as its distribution and parameters (not a string), so to_code() writes it too.
  • Results by group: results by group are kept at every step only while they fit in about 100 MB a module (500 MB over the runs of sim.run(n_runs=)); beyond that they are kept every week, four weeks, quarter, and so on (a flow added up over the period, a state at its end), with a note, and totals are still kept at every step. ss.Sim(results=['n_I', 'cases']) keeps only the named results by group. A stochastic run with mixing between places, or with results kept every few steps, draws in a different order, so its runs differ from before (equally likely); across many runs, outcomes by group are worked out from the flows by group.
  • Dependencies: seaborn is no longer installed with Starsim (only Starsim 3’s ss.Calibration plots use it, and import it when they are made); starsim_data (named data) is installed with Starsim, and so is openpyxl (for Atomica’s workbooks), through Sciris.
  • Many runs: a MultiSim is its results: msim.results.<module>.<result> is an ss.Result with a run axis first, however the runs were made, with select(run=, scenario=, <swept parameter>=), quantiles(), median(), mean(), diff(), resample(), to_df(), and plot(); len(msim) is the number of runs. ss.parallel() is the one way to run many sims, and sim.run(n_runs=) its shortcut for one; pars= takes arrays. Removed: msim.reduce(), msim.mean(), msim.median(), msim.reset(), ss.MultiResult, and ss.multi_run() (iterpars= is pars=).
  • Flow names: a flow has one name, its transition’s (sim.results.sir.infection), and its running total is .cum, computed when asked for; new_infections, cum_infections, and prevalence are kept on ss.SIR, ss.SIS, and ss.SEIR, and not added to a disease declared with ss.Disease(); a data column new_infections matches the flow of a declared disease’s one transmission.
  • Typed arithmetic: arithmetic on a finished transition is about its flow, never its rate: 0.5 * infection given to a disease is an outcome (half its flow), not a second transition at half the rate (L25).
  • Time during a step: in every module, sim.ti is the time point at the start of the step (the first step has ti == 0, as in Starsim 3), and sim.advance() moves it to the end before results are recorded; a result written during a step goes at ti + 1. Code that tested sim.ti == k in an intervention fires one step earlier, and a disease written as code that is seeded at init progresses one step later than in earlier v4 builds (as in Starsim 3). ss.solvers.interval() is removed. A declared disease takes all of its transitions in step(), after the interventions, under every solver, so a delivery reaches the same people as agents as in compartments (screening as agents reached 7% fewer before). Runs as agents draw different numbers (from the same distribution).
  • Solvers: the solvers are auto, ode, binomial, gillespie, and abm; solver='gillespie' estimates the number of events from an ODE run and takes tau leaps above a million, with a note (approx=False keeps it exact, and refuses a value that varies smoothly in time); 'tau', 'sde', 'stochastic', and 'ctmc' are removed, with an error naming what to use. integrator= is the ODE’s scheme only ('rk4' or 'euler'); ss.parallel(pars=...) takes 300 or more ODE runs in one call to JAX by itself. Every compartmental run is taken by the kernels (the Python solvers and use_kernels are removed), including a function in a rate, a beta for each route, and where= on contacts (up to 20x faster); a function that gives an expression of the model’s states is built into the program. solver='auto' tries function interventions and analyzers and step() overrides on groups, and runs an ODE when they work (compartmental = True or False overrides it); its reasons are one record that sim.solvers(), describe(), and the CapabilityError read, and sim.kernel_reason() says why a run is not taken whole.
  • Diseases tracked jointly: diseases whose states are tracked jointly in a compartmental run (ss.Crossing, e.g. HIV and syphilis linked by ss.modify(..., where=)) run as one program in the kernels: every rate is worked out from the people at the start of the step (the ODE agrees with a fine step to 1e-7, where it was up to 1% off at quarter-year steps), and stochastic solvers draw each disease’s events in turn from those rates. Whole runs under every solver, many runs at once, the particle filter, and JAX take crossed diseases as they take one, and crossed runs are faster (binomial 67 to 19 ms). ss.gradients.JointRun is CrossRun.
  • One language: ss.SIR, ss.SIS, and ss.SEIR are declared from states and transitions, so they run under every solver; Starsim 3’s keywords still work, infected/susceptible are I/S (with no aliases), and results are named after the states (n_I, not n_infected). ss.SIS has no waning immunity. Starsim 3’s versions, written as code, are ssl.AgentSIR, ssl.AgentSEIR, and ssl.AgentSIS (they run only as agents). An ss.Disease subclass that declares nothing is written as code, as in Starsim 3; one transmitted between agents subclasses ss.Infection (as ss.NCD now does). A sim whose diseases are all declared counts time from 0 by default. Removed, with their v4 spellings in skills/migrate-starsim3: ss.routine_vx, ss.campaign_vx, ss.simple_vx, ss.routine_screening, ss.campaign_screening, ss.routine_triage, ss.campaign_triage, ss.seasonality, the short names ss.Vx(...)/ss.Dx(...)/ss.Tx(...) for the new products, and the Starsim 2 names ss.rate, ss.time_prob, and ss.rate_prob. On modules written as code, ss.modify() changes rel_sus and rel_trans, a condition can use their arrays (where=hiv.cd4 < 200), sim.fit() fits their parameters given as ss.par with bounds, and sim.new() works.
  • Errors and notes: errors are exception classes, named as before but without numbers (ss.UnknownState, ss.CapabilityError, …), subclasses of ss.CodedError (a ValueError; lookups are also KeyErrors), and can be pickled; ss.error() is removed. Warnings are classes too (ss.ImportIncomplete, ss.NotConverged, …), subclasses of ss.StarsimWarning, and notes are subclasses of ss.Note (ss.note(msg, category=ss.LargeStep, sim=)). verbose is one integer for every solver: 0 prints nothing, 1 (the default) the solver, notes, and about ten progress lines a run, and 2 everything; verbose=0.1 and 'brief' raise an error.
  • Random numbers: each module’s stochastic compartmental run draws from a generator of its own (from the sim’s seed and the module’s name), so its draws do not change when other modules are added, when the run is stepped, or when another sim runs in between; stochastic results differ from before. Tau-leaping draws the number leaving each compartment once, so the order of competing flows does not matter.
  • Units and defaults: the unit of a model’s bare numbers comes from the model (unit=, else its typed values, else dates), not from dt or a typed stop; typed values with different units alongside bare numbers raise ss.IncompatibleTypes. With no initial values, 1% start infected (marked as a guess), and init() prints R0 and the number infectious at the start. A keyword number on ss.Disease sets the parameter of that name (ss.UnknownParameter if there is none).
  • Distributions: a distribution for a parameter other than a dwell time (beta=ss.lognorm_ex(...)) gives each agent their own value and makes solver='auto' choose agents; a compartmental run uses its mean, with a note.
  • Results and fitting: every result has a kind ('flow', 'stock', 'ratio', or None for one with no meaning over time), guessed from its name if not given (as in Starsim 3), which decides how it is compared with data, whether it has a running total (.cum), and how it is summarized and resampled: its summarize_by ('sum' for a flow, 'last' for a stock, 'mean' for a ratio), which can be given to summarize it another way (e.g. a flow by its mean, or one added to ss.Result.summarizers) without changing its kind; ss.outcome(every=) and annualize() are removed (use resample('year')). A stochastic fit scores each point by the mean of 4 runs with the same seeds (n_runs=); optimizers use the priors when every series has a likelihood; parameter values are checked at init() (ss.UnvaluedParameter, ss.OutOfBounds).
  • Dimensions: an explicit contact matrix is used whatever its dimension is called; sir.age < 5 compares ages on a stratified model; contact matrices aggregate by population, and aging follows the population’s pyramid; ss.gravity() gives the shape of movement and away= its amount; a strain dimension with partial immunity runs as agents under auto; ss.StaticNet in a compartmental run uses its graph’s mean degree; a routine delivery by age reaches people as they reach the age.
  • Importers: EMULSION’s proba is per time unit; flepiMoP runs through end_date; Atomica’s initial numbers follow its setup weights.
  • Guesses: a bare number for a time (at=, start=, a time series key) is a time in the sim’s unit, counted from the start, and one outside the sim raises ss.TimeOutsideSim; a dimension’s kind comes from its value (kind= overrides it); a boolean dimension, or one a transfer moves people along, starts at its first level; with no population given, ages are the world’s; people age only with births or deaths (or use_aging=True); an initial value of 1 or more is a number of people, whether written 1 or 1.0; the string form of an SEIR’s transmission needs source= (ss.SourceNeeded).
  • Typed arithmetic: number / dur is a rate and number / rate a duration; - works wherever + does; adding probabilities combines their rates; meaningless arithmetic raises ss.IncompatibleTypes, and a rate slot that is not per unit time (or a dur= that is not a duration) raises ss.WrongDimension.
  • Regression: results use the convention of other modeling frameworks, under every solver and for modules written as code too: n_<state>[0] is the number at the start, n_<state>[ti] the number at time point ti (after ti steps), and a flow at ti (recovery[ti]) the number during the step that ends there (0 at the start). So n_R[ti] - n_R[ti-1] == recovery[ti]. A sim with stop=T ends at T: it takes one step fewer than before (none from T). The step that ends at time point ti goes from ti-1: modules written as code see time point ti (the end of the step), as before; a declared model takes values that vary in time at its start, and a delivery (ss.vaccinate(), ss.treat(), …) at time point ti happens at ti, between the steps, and is counted there. The events of a movement register dated at ti are in the numbers at ti.
  • In a compartmental run, when a test had follow-ups for both results, the second applied to some of the people the first had moved (e.g. a vaccine for negatives also reached people the treatment of positives had just cured).
  • A modifier on a transition chosen with p=, and where= on one, changed how long people took to leave by it, not how many left by it; people that where= excluded stayed in the state. They now change its probability, and the other branches take the rest.
  • The stochastic compartmental solvers follow a value that varies smoothly in time (ss.seasonal, ss.timeseries) within a step, as the ODE does: Gillespie and tau-leaping hold it for a quarter of a step at a time (at its middle), with events exact within each quarter, and the chain-binomial and SDE solvers take it at the middle of each substep. They held it at its value at the start of the step; with steps of a quarter of a year, a seasonal SIS had 5–6% too many infections.
  • As agents, people age in a model whose births are declared (ss.birth()), as with demographics modules (they stayed the age they were born at, unless use_aging=True was given).
  • Under Gillespie by place (solver='gillespie' with places that do not affect each other within a step), counts such as an environmental pressure are settled after the step’s register events, as SimInf does, so people who move count towards the place they arrive at. In the SimInf SISe3 example, infection now spreads between herds as fast as in SimInf (it was about 25% slower).
  • The summary of a delivery’s coverage (in sim.summarize()) is the total delivered over the total eligible; it averaged over every step, including those between rounds (a weekly screen at coverage 0.4 gave 0.06).
  • In a compartmental run, a function of the sim that compares people.age with an age inside an age group raises ss.CapabilityError (under auto, the model runs as agents); it gave each group the age of its middle.
  • Under solver='binomial' and 'gillespie', the flows are drawn in an order set by the names of their states and transitions, so the order the states are declared in no longer changes the draws. The draws of most stochastic compartmental runs change; their distributions do not.
  • Each run of sim.run(n_runs=) and ss.parallel() draws its outcomes from its own seed, as the same run on its own does; before, all runs drew them from the first run’s generator.
  • The exact solver (gillespie) follows only what each event changes when groups mix (strata, or places people commute between) or all groups are in one place, with at least 8 groups: groups with the same rates are taken together, and the exposures and rates are worked out again only where the mixing takes the change. The cost per event no longer grows with the number of groups (0.2 µs at 300 strata instead of 5.1; 4.1 µs at 300 commuting places instead of 42). Such runs have the same distribution of outcomes but different draws for a given seed.
  • A disease written as code dates an infection at the end of the step, as a declared disease does (ss.Disease.ti_entry, self.ti + 1; seeds at the start): the library’s ssl.AgentSIR, AgentSIS, AgentSEIR (and the diseases built on them) and ssl.HIV set ti_infected from it and schedule what follows from it, so infected agents are counted one step longer than in Starsim 3, and an infection lasting one step now transmits. Infection logs (ss.infection_log) record infections at the end of the step too, for both kinds of disease. In your own module written as code, set self.ti_infected[uids] = self.ti_entry to do the same.
  • ss.Births, ss.Deaths, and ss.Pregnancy take rate_units=None by default: a rate above 1 is per 1,000 people (as before, e.g. ss.Births(birth_rate=35)), and a rate of 1 or below is per person (before, per 1,000), with a warning when the largest rate could be either (0.1 to 1, or above 1,000). rate_units=1000 (or 1e-3) or rate_units=1 says which and silences the warning.
  • The default fitting method for a deterministic sim with gradients is Nelder-Mead when one or two parameters are fitted (about 10 times faster there than L-BFGS-B with gradients); L-BFGS-B from three.
  • In an agent run of a declared disease, the times of entering a state (ti_X) and of a scheduled exit are kept as 16-bit step numbers when the run has fewer than 32,000 steps (ss.arrays.StepArr), and which exit as an 8-bit integer: 142 → 114 bytes per agent at the peak for the LASER model (86 → 68 in the arrays), with no change in speed. Reading them gives float step numbers as before, with NaN when not set; .years converts them to years. Results are unchanged except where a dwell is rescaled by a modifier after it was drawn (what is left is now whole steps).
  • solver='gillespie' takes tau leaps when the exact run would take more than about a second (estimated from the events an ODE run gives and the number of groups that affect each other), rather than above a million events; places that do not affect each other are always run exactly. So a single group stays exact up to about 7 million events, runs by place are exact at any size, and groups linked by commuting switch sooner. ss.solvers.max_events is replaced by ss.solvers.max_seconds.
  • Regression: ssl.AgentSIR, AgentSEIR, AgentSIS, Ebola, Cholera and Measles schedule each course in whole steps as the agent engine does, so they agree with ss.SIR/ss.SEIR run as agents at any step (each case was half a step short, and the seeds half a step long); the initial infections of a disease written as code are dated at the start of the run.

  • Regression: a result’s scale follows its kind by default (flows and stocks scale with the population, ratios don’t), so a coded prevalence is no longer scaled; an integer result with no telling name is guessed to be a flow.
  • Regression: delivery rounds with interval= are timed by date, so yearly rounds on weekly steps no longer drift (they were 364 days apart).

  • A stock target (target=) on a delivery with a counter (increment=) counts the people the counter has reached; it crashed as compartments and counted nobody as agents. A counter that goes down with a target raises.
  • Regression: under the compartmental solvers, two transitions of one module triggered by the same transition of another, from different states (e.g. ss.Lactation’s start from N and restart from L, both on a delivery), each move the people who were in their own source; the second moved people the first had just moved, so people left a state uncounted.
  • stages= on a transition must be a whole number of at least 1; a misspelled value such as stages='steps' was ignored.
  • lost_capacity of a delivery with a target counts only the people needed to close the gap and not served for lack of capacity, not everyone chosen.
  • Regression: under the compartmental solvers, a rate that reads the time in a state (P.dwell) is read at the time the people in each step of it have spent there: it was read half a step late under the ODE and Gillespie, and under binomial nobody faced its first step, so at coarse steps such exits were too few (by 15% to 35% at monthly steps for a rate that halves in two months).

Performance

  • The kernels also exist in Rust (starsim/solvers/rust/, built with cd starsim/solvers/rust && ./build), with the same arguments and the same numbers, bit for bit: the passes over agents, the compartmental kernels, the draws (including the chain binomial’s in JAX), and the small kernels of arrays, networks and distributions. Compiled ahead of time, they need no compiling on a first run (a first ODE run: 0.01 s, against about 140 s for Numba from an empty cache), and are as fast as Numba’s or faster (compartmental runs 1.05–7×). ss.jit stays in Numba, since it compiles users’ own code. tests/test_kernel_sets.py checks that the sets agree.
  • Arr arithmetic and assigning one value to every agent (arr[:] = 1) work on the raw arrays, as comparisons do: 5–13× faster at 100,000 agents (arr*2 151 → 20 µs, arr *= x 135 → 10 µs); a write from code to a declared state that is being counted counts only the agents it changes (about 2× faster). Results unchanged.
  • ss.uids set operations skip NumPy’s sort when both sides are sorted with no repeats, as UIDs usually are (& and - 2–26× faster, | 1.3–13×, from 20 to 2,000 UIDs), and reading a result that is there is a plain dict lookup (2.5× faster); results unchanged.
  • The agent engine draws a distribution whose parameters are plain values (e.g. a lognormal dwell time) as the inverse of its own uniforms (ss.Dist.resolved()), rather than through rvs(), about 20% faster a draw; Dist.rvs() and the normal, lognormal and exponential inverses do less per call. Results unchanged.
  • Declared models as agents do less bookkeeping per move, with the same results: the engine writes its own moves into the state arrays and counts them directly (rather than through the watch on writes from code), finds who leaves a state with only scheduled exits in one pass over the agents, checks for people without a scheduled exit only when something other than its moves has put people in a state, and draws its unit exponentials without Dist.rvs()’s bookkeeping. An SIS run as agents on a network is within about 5% of the same model written as code (was 17% slower), and the test corpus runs 1.0 to 1.4 times faster at 100,000 agents than with the compiled rounds of moves that were tried before (which are removed, being no faster: about 1,050 lines). A value by sex alone is worked out for everyone once and kept for the run, and so are the parameters of the engine’s distributions that use one (so a draw of a dwell time by sex is the uniforms and the inverse, 18 µs, was 50); a trigger on a transition sees at once when nothing of it has happened since it looked. The same-step cascade is one sweep over the transitions in a fixed order worked out from the graph (each after those that take people into its source, and a trigger after its event and ahead of the scheduled exits of its source), as a model written as code takes them, in place of rounds of moves until nothing moves: each transition and trigger is taken once a phase of a step (STIsim’s triggers are checked 8 times a step, were 25). This changes the results of declared models as agents (the draws are keyed by the transition’s place in the sweep), not their distributions. STIsim’s SEIS case takes 3.8 s at 5,000 agents (Starsim 3 and STIsim 1.7: 3.8 s; the compiled rounds: 2.9 s). The Python engine’s step is in named parts, and its triggers work on the agents they concern, not the whole population.
  • Declared models as agents: a split’s or branch’s probabilities that are fixed for the run (numbers, values by sex) are worked out once for everyone; each of the engine’s distributions is drawn from without repeating its checks; a transition with no modifiers or adjust= is not multiplied by them; and ss.stay and delayed triggers use cheaper set operations for the few agents of a round. Results are unchanged. The three STIs of STIsim’s SEIS case take about 20% less time a step.
  • Dist.rvs() is about twice as fast for a small draw (10 µs, was 19, for 20 agents): it checks plain-number parameters in Python rather than with np.all(), and works out the span of slots only for a distribution drawn without its inverse; with parameters that are functions of the agents, it skips the unit checks when none has a unit and calls each function once (44 µs, was 58, for a lognormal by sex). ss.uids.unique() sorts and drops repeats, 5–10 times faster than np.unique() (which, from NumPy 2.3, uses a hash table for integers).
  • Many short compartmental runs (n_runs=, fits, the particle filter) are 3.3–3.7× faster: the kernels pass the program’s arrays without Numba’s reference counting on each call (borrow() in ss.kernels), and a step is compiled into the loop that takes the runs. A 4-age SEIR takes 1.7 µs a step, was 6.4 µs (odin: 1.35 µs). Compiling the kernels takes about 129 s once per install, was 105 s.
  • Networks whose edges last one step (ss.RandomNet by default) no longer remove the dead’s edges each step, since they end at the next step: 1.3–1.4× faster a step at 1M agents with births and deaths. Edges to people who died in the last step can remain between steps.
  • Declared births as agents are vectorized (as fast as ss.Births); the kernels’ chain binomial and tau-leaping share the exact solver’s move().
  • Declared models as agents: ss.by values only for the agents that need them and a p= over many destinations once per transition (FPsim’s contraception about 2× faster), one network pass for several transmissions over the same network (tbsim’s TB about 20% faster), and less fixed cost per step and per draw. New benchmarks: tbsim-shaped TB at two sizes, FPsim-shaped contraception, and 16 sets of strains under the ODE.
  • Whether JAX takes a compartmental run is decided from one timed step of the compiled kernels, so models with many places that mix no longer go to JAX for short runs (MEmilio’s 100 counties: 0.15 s, not 0.8 s).
  • Memory per agent is about 40% lower again (81 to 48 bytes at the peak for the LASER model): a stratification’s property that people do not already have (e.g. people.patch) is 16-bit integers, and with one stratification it is also the group array (otherwise the levels and groups sim.groups keeps are 16-bit); people.uid takes no memory, since a UID is its index (raw is made when read, read-only); and a declared disease run as agents keeps the time of entering a state (ti_S) only if something reads it: its scheduled exits, after=/before=, or the code of a module in the sim that names it (ss.Disease.times_read()). Reading one that was not kept raises ss.TimeNotKept; ss.options.keep_times = True keeps them all. A distribution no longer keeps the UIDs of its last draw.
  • Memory per agent is about a third lower (117 to 81 bytes at the peak for the LASER model): people.auids are 32-bit integers (ss.uids keeps 32-bit integers as they are); people.ti_dead and people.ti_removed are step numbers stored as 16-bit integers when the run has fewer than 32,000 steps (reading them gives float step numbers, NaN when not set, as before); people.slot, people.parent, people.scale, and a disease’s rel_sus and rel_trans take no memory until something sets them (ss.Arr(shared=True): until then raw is a read-only view of the default); and a People not yet in a sim holds no arrays per agent, so sim.inputs no longer keeps about 20 bytes per agent of copies.
  • ss.histogram draws through its CDF directly (the same values as SciPy’s ppf(), without about 90 bytes per value of temporaries), and a distribution no longer keeps the slots of its last draw.
  • A typed value is converted once, a value by level once a step, and a time series interpolated as numbers (declared demography by age with seasonal rates about 3× faster as an ODE, 1.5× as agents); a function of the sim used as a parameter is called once a step.
  • The particle filter reads each data point from its first contributing step, not from step 0, so its cost is linear in the length of the data (3,200 daily points: 0.7 s, from 3.3 s).
  • The exact solver on diseases tracked jointly (one program over the product of their compartments) keeps only the compartments that hold anyone, and a rate until its inputs change, rather than working out every flow of the product after each event: ss.SIR() and ss.SIS() with births and deaths over 50 years take 0.7 s rather than 20 s at 10,000 people, with the same results.
  • An ABC-SMC fit no longer starts with a scan over the bounds that it did not use (10 fewer runs per parameter).
  • The particle filter (ss.ParticleFilter, particle MCMC) runs its particles in parallel in the kernels on ss.options.threads threads (one in the workers of ss.parallel() and of a calibration): odin’s 4-group SEIR takes 2.9 µs per particle-step on one thread, from 6 µs, and 0.8 µs on eight; camdl’s SIR fit by particle MCMC takes 79 s, from 188 s. It works out an outcome (e.g. cases) at each data point from only the steps it depends on: 2.5 times faster on outcomes.
  • The compartmental kernels no longer pass the program to a function at every step or event, which cost about 0.5 µs a call: the Gillespie solver is 3 to 6 times faster, and chain-binomial and ODE runs of a small model about 25% faster, with the same results.
  • The exact solver by place (solver='gillespie' where places mix only within themselves) steps only the places that can have an event, works out each place’s rates without passing the whole program for each flow, and steps many places at once on Numba’s threads: SimInf’s 16,000 herds with 4.7 million register events run in 3.1 s on one thread and 1.7 s on 20 (30 s before), and the particle filter on one herd takes 0.6 ms per particle run (2.7 ms before). The places draw from a stream each, so results do not depend on the number of threads.
  • A movement register is read and resolved once for each distinct value rather than row by row, and places are grouped by one sort: building the 16,000-herd sim takes 2.0 s (39 s before).
  • Large agent-based sims of declared diseases are 5 to 13 times faster: the number in each state is counted once and then kept up to date with every change to the states (whatever makes it, including a function’s mod.I[uids] = True); infections are drawn in the same pass that works out each agent’s chance; deaths from a life table are filed under the step they happen in when each is drawn; and the passes over the population (here and in People) are split between threads above 200,000 agents (ss.options.threads; the workers of ss.parallel() and of a calibration use one). LASER’s England and Wales model, 3.3 million agents for two years, runs in about 8 s rather than 45 s (or 106 s with the life table declared), with the same results.
  • Agent-based sims use less memory: UIDs, slots, and parents are stored as 32-bit integers (read as ss.uids, which stay 64-bit), as are each agent’s group; a state has scheduled-exit arrays only if it has scheduled exits; and arrays grow by 20% at a time rather than 50%. LASER’s England and Wales model at 3.3 million agents takes 1.1 GB rather than 1.6.
  • A contact matrix within places, with commuting, is applied as the time share between places times the matrix between levels, rather than as their dense product, and movement between groups (aging, transfers, migration) is kept as sparse rates: MEmilio’s 400 counties by 6 ages run in under a second rather than 25 to 80 s, with memory linear in the places. ss.contacts() keeps its matrix as numbers, so a sim over 774 places builds in a tenth of a second (170 s and 10 GB before). The measles metapop model by age and district keeps 84 MB of results a run, not 2.3 GB.
  • Deliveries on a schedule (routine or in rounds) to people chosen by states and stratifications, with a coverage that is a number or ss.by, of a product that people hold (a vaccine, TPT) or a transfer, are taken by the kernels in a whole compartmental run, so the run is no longer stepped from Python: 15–30 times faster (tbsim with BCG, 19 ms rather than 545 ms), with the same results. Such sims can now also be run many times in one call (sim.run(n_runs=)), restarted, run in JAX, differentiated (sim.gradient()), and fitted by NUTS. A product’s effect no longer makes the program be worked out step by step before the run.
  • A compartmental run stepped from Python (e.g. with deliveries, or a modifier with when=) works out where each flow’s arrivals go only when a branch probability has changed: 20–30% faster.
  • Large agent-based sims are faster: dead agents are removed without sorting every agent’s ID, arr.true(), arr.false(), and arr.count() read the values of the active agents without gathering them first, the deaths in a step are counted in one pass, each agent’s group is updated in place, and (for declared models) every state is counted by group in one pass. LASER’s England and Wales model as 668,000 agents runs about 40% faster, with the same results; Starsim 3 sims give the same results, no slower.
  • solver='binomial' moves people through as many stages of a dwell time as they pass in a step, with one draw per compartment, so it takes whole steps instead of a substep for each stage. This is exact where one stage a substep was not. The LASER hub-and-spoke example (49 stages) runs in 0.33 s, from 15 s. Regression: chain-binomial results change, since the steps are whole; substeps= gives shorter ones.
  • sim.fit() on a sim with dates is 2–3 times faster: the data and the sim’s times are no longer converted to years at every evaluation.
  • Building a sim (sim.init()) is 2–5 times faster: the search for distributions and time parameters no longer walks results, timelines, or the copy of the inputs kept for sim.new(), nor (on its second pass) everything it has already searched; dates are made from years directly (all at once for a timeline); and the plan of the integration loop is made only when the loop runs (a sim run by the kernels in one call never needs it). A 30-year TB model with weekly steps builds in 22 ms (from 106), and an agent-based sim with HIV and births in 52 ms (from 114).
  • Diseases tracked jointly (a crossing) take the exposure summed over the other diseases’ compartments as one number per flow, instead of adding it up operation by operation in every flow: three HPV genotypes as an ODE run in 9 s instead of 383 s, with the same results.
  • ss.Mobility keeps the time share and the coupling between places sparse (sim.mixing.time_share is a SciPy sparse array), and ss.Mobility(matrix=) takes a SciPy sparse array, so models with thousands of places never form a place-by-place array; a first run at 6,000 places takes 0.08–0.19 s instead of 0.38–0.47 s, with the same results.
  • The workers of ss.parallel() and of a calibration run NumPy’s BLAS on one thread (set before they are forked, restored after), and are started by forkserver once this process has started Numba’s or JAX’s threads, which a fork can deadlock on.
  • sim.groups adds the levels of new agents to what it keeps when the people grow, rather than working out every agent’s group again (about 20 fewer bytes per agent at the peak of a step after births).
