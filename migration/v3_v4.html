Starsim v3 to v4 migration guide

Overview

Starsim 4 adds a way to write a disease as declared states and transitions, which can then be run as an ODE, as a stochastic compartmental model, or as agents. For a Starsim 3 model (custom ss.Infection subclasses with their own states and step methods, ss.MFNet and ss.RandomNet, ss.Births and ss.Deaths, custom interventions and connectors, and ss.Calibration), Starsim 4 is an upgrade rather than a switch: most of it still runs, and what is declared can then be described (sim.describe()), run as an ODE or a stochastic compartmental model when nothing in the sim needs agents, swept and compared with ss.parallel() and msim.diff(), and fitted with sim.fit(). This guide shows the same model in both, maps Starsim 3 code to Starsim 4 job by job, lists what changes meaning on the way, and ends with what works and what does not yet. It is written for both humans and LLMs.

Starsim 3 code is of two kinds, and they migrate differently:

  • Modules written as code (ss.Module, ss.Disease and ss.Infection subclasses (ss.Infection is now ss.AgentDisease, which the migration script renames) with define_states(), set_prognoses(), and step_state(), custom networks, ss.Intervention and ss.Analyzer subclasses, ss.Births, ss.Deaths, ss.RandomNet, and ss.MFNet, now ss.SexualNet) are still part of Starsim 4. They run unchanged, as agents, and can sit in the same sim as declared diseases. ss.Disease is the base of every disease, as in Starsim 3, whether it is declared, written as code, or both in one class; ss.Infection adds transmission written as code. Per-agent quantities that change continuously (a CD4 count, a level of immunity, time since an event) have no declared form, and keeping them as code is a supported choice.
  • Starsim 3 spellings that Starsim 4 replaces (the library ss.SIR, ss.SIS, and ss.SEIR as code; ss.routine_vx, ss.campaign_vx, ss.routine_screening, ss.treat_num, and the products ss.Vx, ss.Dx, ss.Tx; ss.seasonality) have been removed, as have ss.Calibration with its components, and ss.Samples and ss.Dataset. Use the table of jobs below to port them.

The migration script makes the mechanical changes for you and lists, by file and line, what needs a person: python -m starsim.converters.migrate mymodel.py --check lists what it would change, and without --check it rewrites the files (or folders) in place. Read its diff afterwards. A removed name raises an AttributeError in Starsim 4; the table of jobs says what replaced it.

Note: If you are an LLM reading this, migrate one module at a time, run the model after each step, compare it with the Starsim 3 results (allowing for the changes in the next section), and confirm with the user before going on.

The same model in both

An SIS on a random network, as Starsim 3 wrote it, with the library disease written as code and a beta for each network:

import starsim as ss # Starsim 3

sis = ss.SIS(beta=dict(randomnet=0.05), dur_inf=ss.years(1), init_prev=0.01)
sim = ss.Sim(diseases=sis, networks=ss.RandomNet(n_contacts=4), n_agents=5000, start=2000, stop=2010, dt=1/12)
sim.run()

In Starsim 4, the same disease is declared as states and transitions. Two things change meaning on the way (see What changes the numbers). A bare number in a Starsim 3 beta dict was a probability per step, so here it is written ss.prob(0.05, 'month'); copied as a bare number, it would be a rate per year, 12 times too low at monthly steps (item 3). And a duration in a declared transition is exponential with that mean, unless a distribution is given, while Starsim 3’s ss.SIS drew a lognormal dur_inf; dur=ss.lognormal(mean=ss.years(1)) keeps the old shape (item 5). Here the textbook exponential is used:

import starsim as ss

S, I = ss.states('S I')
sis = ss.Disease(
    infection = ss.Transition(S, I, rate=dict(randomnet=ss.prob(0.05, 'month')) * I),
    recovery  = ss.Transition(I, S, dur=ss.years(1)),
    init_prev = 0.01,
)
sim = ss.Sim(sis, networks=ss.RandomNet(n_contacts=4), n_agents=5000, start=2000, stop=2010, dt=ss.months(1), verbose=0)
sim.run()
print('Infections:', round(sim.results.sis.infection.sum()))
sim.plot()

This gives 22,860 infections with the default seed, against Starsim 3’s 21,557 (two seeds differ by about 6%). The Starsim 3 model itself, run unchanged as ssl.AgentSIS, is in What works and what does not yet.

The migration script

Most of the changes are mechanical, and a tool makes them: python -m starsim.converters.migrate rewrites Starsim 3 code for Starsim 4, in .py files and in the code cells of notebooks, Quarto, and Markdown files. It renames what was renamed (ss.MFNet is ss.SexualNet, ss.time_prob() is ss.probperyear(), the library’s modules are ssl.X), turns subclasses of Starsim 3’s ss.SIR, ss.SIS, and ss.SEIR written as code into subclasses of ssl.AgentSIR and the like, rewrites a beta pair on a sexual network as a probability per act in each direction, and renames the results that count people in a state. Everything else it lists by file and line, as something for a person to check. Give --check to see what it would change without changing anything. For this Starsim 3 script, mymodel.py:

import starsim as ss

class MySIS(ss.SIS):
    def step_state(self):
        super().step_state()

sis = MySIS(beta=dict(mf=[0.08, 0.04]), dur_inf=ss.years(1), init_prev=0.01)
net = ss.MFNet()
sim = ss.Sim(diseases=sis, networks=net, n_agents=5000, start=2000, stop=2010, dt=1/12, verbose=-1)
sim.run()
print(sim.results.mysis.n_infected[-1])

it says:

python -m starsim.converters.migrate mymodel.py --check
mymodel.py: would change 6 line(s)
  0: added import starsim.library as ssl
  3: Starsim 3's ss.SIS, written as code, is ssl.AgentSIS (ss.SIS is now declared)
  7: a beta pair on ss.MFNet (now ss.SexualNet; [p1 to p2, p2 to p1], with men in p1) is ss.peract(m2f=..., f2m=...), a probability per act in each direction
  8: ss.MFNet is ss.SexualNet (between='mf' is its default)
  9: verbose=-1 ("brief") is verbose=0
  11: the count of a state is the result named after the state (e.g. results.alive, res.infected, results["sir.infected"])

6 change(s) in 1 file(s); 0 item(s) to do by hand

Without --check, it makes the changes in place (so run it on code that is under version control, and read the diff afterwards); give it folders to upgrade a whole package. What it can’t do mechanically, such as a beta given as a bare number that was a probability per step, is in the next section, and an AI assistant with Starsim’s migrate-starsim3 skill can work through the list it leaves.

What changes the numbers

Read this first: each of these changes results without an error.

1. Stocks are recorded at the start of the step

In Starsim 4, each time point is a period: a step is taken from every time point, as in Starsim 3, and row ti of a result is the step from time point ti. A flow at ti (e.g. new_infections[ti], now infection[ti]) is the number during that step, as in Starsim 3. A stock (e.g. infected[ti]) is the number at its start, where Starsim 3 recorded it at the end of the step, in update_results(), but labeled it with the step’s start: Starsim 3’s infected[ti] was the number after step ti, which is Starsim 4’s infected[ti + 1]. So infected[0] is now the number at the start of the run, before any step, which Starsim 3 did not record, and the state after the last step is not recorded. The same script, with Starsim 3’s SIR (ssl.AgentSIR in Starsim 4; see 5), gives:

                  infected[:4]            new_infections[:2]
Starsim 3.7.2     53, 99, 186, 356        26, 46
Starsim 4         31, 64, 128, 240        33, 64

(ss.Sim(n_agents=3000, diseases=ss.SIR(beta=0.1), networks='random'), with ssl.AgentSIR(beta=0.1) in Starsim 4.) The counts of states are one index later, and the random draws differ after that, so results agree statistically (over several seeds), not number for number. For a model with yearly steps, the number infected in a row is the number on 1 January of that year, rather than on 31 December, while the infections in a row are still those during its year. To compare a stock with Starsim 3’s, compare Starsim 4’s x[1:] with Starsim 3’s x[:-1]. To reproduce published Starsim 3 numbers exactly, use pip install starsim==3.7.2.

With coarse steps, a model can also differ by more than one step. In Starsim 3, a person could pass through several states within one step (e.g. infected, then latent, then active, all in the same step), each taken for a whole step. In Starsim 4, people infected in a step are infected at its end, so they face the exits of the state they enter from the next step on (unless the exit is immediate, with no rate= or dur=), as in the compartmental solvers; someone moved by a rate during a step faces half a step of the rates out of the state they arrive in, so may move again in the same step (with agents by midsteps, the default; with solver=ss.solvers.abm(step='wholestep'), from the next step). So with long steps, people wait longer in their first state after infection. For tbsim with dt=0.1 years, latent TB is 36% higher and active TB 13% higher than in Starsim 3; at dt=0.005 they agree. If results differ at a coarse step, check them at a smaller dt (sim.check_dt() says whether the step is too long for the model’s rates).

So an agent can still move more than once in a step: through two states by rates, or out of a state by a rate and then infected again by the step’s transmission (e.g. asymptomatic, then recovered, then reinfected). Comparing each agent’s state at the end of one step with the next therefore misses some moves (about 1% of infections in tbsim at monthly steps). For flows, read the results of the transitions, which count every move (sim.results.tb.infection, by group with .by()), or, for who was infected, the infection log (disease.infection_log.to_df(ti=self.ti) in an analyzer; see Analyzers), rather than differences of states.

In a module written as code, split update_results() into record_states(), called at the start of each step, before any module steps, for the results that are the state then (a count of a state, a mean level), and record_events(), called at the end of the step, after the deaths, for those about what happened in it (doses, births, new cases). A class that still defines update_results() raises a TypeError when it is created, saying so. A result that needs both (births over the people alive) goes in record_events(), reading the stock from its result (self.sim.results.alive[self.ti]), or in finalize_results():

# Starsim 3
def update_results(self):
    super().update_results()
    self.results.n_on_art[self.ti] = self.on_art.sum()
    self.results.new_doses[self.ti] = self.n_doses

# Starsim 4
def record_states(self): # At the start of the step
    super().record_states()
    self.results.n_on_art[self.ti] = self.on_art.sum()

def record_events(self): # At the end of the step
    super().record_events()
    self.results.new_doses[self.ti] = self.n_doses

Code that reads a stock during a step now reads the step’s own row: sim.results.sir.I[sim.ti] is the number infectious at the start of this step, which in Starsim 3 was [sim.ti - 1], the end of the last step. A flow of this step is not known until it ends, so [sim.ti - 1] of a flow is still the last step’s.

2. One time index in every phase of a step

During the step from time point k to k+1, sim.ti (and self.ti) is k in every module and every phase, from record_states() and step() to record_events() and the analyzers, and self.now is time point k, the time the step starts, at which it reads inputs that change in time, as in Starsim 3. The first step is ti == 0, as in Starsim 3, so code that does something if self.ti == 0 in step() still does it in the first step, and self.results.x[self.ti] = v is right wherever it is written. An analyzer runs at the end of each step, as in Starsim 3; the people it sees are as at the next time point.

A declared disease’s ti_<state> is the index of the step in which each person entered the state (a move is taken at the start of its step, and an infection happens by its end); its clocks (dis.P.time_in) are right, and for how long people stayed in a state, use dis.P.stays.

A disease written as code dates its initial infections by the step before the first (self.ti is -1 while ss.AgentDisease.init_post() calls set_prognoses() for them), as a declared disease dates its seeds, where Starsim 3 dated them by the first step. So in a Starsim 3 disease that schedules recovery at self.ti + dur and takes it when ti_recovered <= self.ti, the seeds are infectious for one step less than in Starsim 3, as long as later cases are. Both are about half a step short of dur on average; to give every case dur steps on average, as a declared disease does, schedule from the step after the infection, since an infection happens at the end of its step, and round as the engine does: ss.TimeArr('ti_recovered'), self.ti_recovered[uids] = self.ti + 1 + dur, and self.ti_recovered.due() (see ss.Infection; ssl.AgentSIR and the others do this).

3. A beta dict of bare numbers changes meaning

In Starsim 3, beta=0.05 is a rate per year, but beta={'randomnet': 0.05} is a probability per step, used as it is. In Starsim 4 both are rates per unit time, so a dict copied verbatim is too low by a factor of about 1/dt: 12 times at monthly steps, 52 times at weekly ones (5 infections instead of 22,000 in an SIS on a random network at monthly steps). Give each value its Starsim 3 meaning explicitly:

Starsim 3 (monthly steps) Starsim 4
beta={'randomnet': 0.05} beta={'randomnet': ss.prob(0.05, 'month')}
beta={'mf': [0.008, 0.004]} beta={'sexual': ss.peract(m2f=0.008, f2m=0.004)}

Use ss.prob(..., 'week') or ss.prob(..., 'day') for weekly or daily steps. Starsim 4 does not warn about a dict of bare numbers; the migration script flags each one, but cannot know your step, so change them by hand. On ss.SexualNet (Starsim 3’s ss.MFNet), which has acts, a beta is a probability per act, the same at any step: Starsim 3’s pair, [men to women, women to men], is ss.peract(m2f=..., f2m=...), and the network is sexual in a beta dict, not mf. Over any network, rel_trans, rel_sus, an edge’s weight and the modifiers now scale the hazard of a contact rather than its chance: Starsim 3’s p·rel_sus is 1 − (1 − p)^rel_sus in Starsim 4. The two are close when p is small; with a large chance per contact, a 50% reduction in rel_sus reduces infections over that contact by less than half.

4. “Routine” delivery means something else

Starsim 3’s ss.routine_vx(prob=0.05, start_year=2005) gives each eligible person a 5% chance of vaccination every year. Starsim 4’s routine delivery, ss.vaccinate(..., coverage=0.05, start='2005'), offers the vaccine once, when a person first becomes eligible. In an SIS model with 5,000 agents from 2000 to 2020, the first reaches about half the population and the second about 5%. The Starsim 3 behavior is delivery in yearly rounds:

ss.vaccinate(efficacy=0.8, when=ss.schedule(every=ss.years(1), start='2005'), coverage=0.05)

5. A fixed duration becomes exponential

In a disease you declare with ss.Disease(...) (or a class with states and transitions), a duration given as a number (dur=ss.years(1)) is the mean of an exponential distribution, as in an ODE; describe() marks this as a guess. Starsim 3’s library diseases used a lognormal (ss.lognorm_ex(), now ss.lognormal()). To keep a distribution, give it: I >> R @ ss.lognormal(mean=ss.years(6)). (A distribution that is not exponential runs as Erlang stages in a compartmental run, with a note.)

This includes the library ss.SIR, ss.SIS, and ss.SEIR, which are now declared, with Starsim 3’s keywords but the textbook defaults, of a respiratory infection, in days: ss.SIR() has beta=ss.perday(0.3) and dur_inf=ss.days(10) (R0 = 3 without a network), where Starsim 3 had 0.1 a year and 6 years, and a sim of it runs for 100 days by default, not 50 years. A bare number is in the unit of the model’s typed values, so ss.SIR(beta=0.1, dur_inf=10) is now per day and 10 days; give the units (beta=ss.peryear(0.1), dur_inf=ss.years(10)), which the migration script does for dur_inf and asks for beta. dur_inf (and dur_exp) given as a number or an ss.Duration is the mean of an exponential, where Starsim 3 had a lognormal with a standard deviation of 1 in the same unit (nearly fixed); and nobody dies of the infection unless p_death is given, where Starsim 3 had p_death=0.01. The shape matters: an SIR with R0 = 2.5 and a 7-day infectious period, with beta cut by 40% from day 30 to 90, infects 715,000 of a million with the exponential and 786,000 with Starsim 3’s nearly fixed period. Starsim 3’s models, with their defaults, are ssl.AgentSIR, ssl.AgentSIS, and ssl.AgentSEIR (import starsim.library as ssl): use them to keep Starsim 3’s model, or give ss.SIR(dur_inf=ss.lognormal(mean=ss.years(6), std=ss.years(1)), p_death=0.01).

6. Result names follow the states

A declared disease’s results are named after its states and transitions: I, not n_infected (a module written as code also counts each state under its own name: infected, and sim.results.alive, not n_alive); the flow of a transition is named after it (infection, recovery, with the cumulative total res.infection.cum); and new_infections and cum_infections are infection and infection.cum, for a disease written as code too. Map the names before comparing with Starsim 3 results.

The results of demographics follow the same rule: ss.Births and ss.Deaths have the flows birth and death (were new), with totals birth.cum and death.cum (were cumulative); ss.Pregnancy has preterm, very_preterm, and unborn (were n_preterm, n_very_preterm, and n_unborn), and maternal_death and neonatal_death (were plural).

7. Write dates as strings

Write calendar dates as strings (start='2000', stop='2030-06-30'), and step sizes with a unit (dt=ss.months(1), not dt=1/12). Whether a sim has a calendar is decided once, from its start: a date or a year (a bare number from 1800 on, start=2000) gives it one, and then every bare number given as a time (stop=, when=, the times of ss.schedule and ss.timeseries) is a year; otherwise a bare time is a time in the sim’s unit from 0. A duration given as a time is that long after the start, as in Starsim 3 (when=ss.days(30), start=ss.days(30), sim.run(until=ss.years(5))). stop= is a time, read as the start is, and the length of the run is dur= (ss.Sim(start=2000, dur=10), or dur=ss.years(10), or ss.Sim(stop=2010, dur=10), which starts in 2000); with a calendar, stop=ss.years(10) is an error that suggests dur=ss.years(10).

The keywords of the distributions are their moments, where they have them: ss.normal(mean=, std=) (was loc=, scale=), ss.truncnorm(mean=, std=, low=, high=), ss.expon(mean=) (was scale=), ss.poisson(mean=) (was lam=), ss.weibull(shape=, scale=) (was c=), and ss.gamma(shape=, scale=) (was a=) or ss.gamma(mean=, std=); the order by position is unchanged. ss.datedur(months=1) is ss.months(1). The migration script renames these.

Migrating one disease at a time

A published model does not have to move all at once. Keep the hard disease as code and declare the easy one: the mixed sim runs as agents, and sim.new(), ss.parallel() scenarios and sweeps, msim.diff(), and sim.fit() work on the whole sim.

import starsim as ss
import starsim.library as ssl

hiv = ssl.HIV(beta={'sexual': ss.peract(m2f=0.008, f2m=0.004), 'random': 0}, init_prev=0.05) # Starsim 3's module, written as code (see 3 for its beta)
S, I = ss.states('S I')
sis = ss.Disease( # Newly declared
    infection = ss.Transition(S, I, rate=dict(sexual=0, random=ss.par(ss.prob(0.005, 'month'), bounds=[0.001, 0.05])) * I),
    recovery  = ss.Transition(I, S, dur=ss.years(2)),
    init_prev = 0.05,
    name = 'sis',
)
susceptible = ss.modify(sis.rel_sus, multiply=3, who=hiv.infected)
sim = ss.Sim([hiv, sis], networks=[ss.SexualNet(), ss.RandomNet()], connectors=susceptible,
             n_agents=2000, start='2000', stop='2020', dt=ss.months(1))

vaccination = ss.vaccinate(efficacy=0.8, disease=sis, when=ss.schedule(every=ss.years(1), start='2010'), coverage=0.05)
msim = ss.parallel({'Baseline': sim, 'Vaccine': sim.new(interventions=vaccination)}, n_runs=3)
msim.diff('Baseline')

Two things to know in a mixed sim:

  • A condition can name the arrays of a module written as code (who=hiv.infected, who=hiv.cd4 < 200), or be a function of the sim (who=lambda sim: sim.diseases.hiv.infected).
  • ss.modify() and ss.vaccinate() act on a module written as code too, as agents, if it has what they change (such as rel_sus); give disease= when there are several diseases. Its Starsim 3 connectors and interventions also still run.

To validate each step, run the Starsim 3 version and the ported one over several seeds (ss.parallel(sim, n_runs=10)) and compare means and spreads, after mapping the result names and allowing for the one-step shift.
