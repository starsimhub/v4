results

results

Results: the values a sim records at each time point (ss.Result), the containers that hold them (ss.Results), and how they are compared with data (ss.simdata)

These exist so that a result knows its own time points, scale, and how to resample and plot itself, whichever solver wrote it.

Used with: agents and compartments; declared and coded modules

Parameters

Name Type Description Default
module str the name or label of the parent module, e.g. ‘SIR’ None
name str the name of this result, e.g. ‘infection’ None
shape int / tuple the shape of the result array (usually module.npts) None
scale bool whether the result scales with the population (by pop_scale, the people each agent stands for): by default (‘auto’), by its kind, so a flow or stock (a count, e.g. infections) does, and a ratio (e.g. prevalence) does not 'auto'
auto_plot bool whether to include automatically in sim.plot() results True
label str a human-readable label for the result None
values array prepopulate the Result with these values None
timevec array an array of time points None
low array values for the lower bound None
high array values for the upper bound None
kind str what the result is, which decides how it behaves: ‘flow’ (a number of events in each step, e.g. new infections; it has a cumulative total, and is summed over each period of data it is compared with), ‘stock’ (a quantity at each time point, e.g. the number infected), ‘ratio’ (one quantity divided by another, e.g. prevalence; one that keeps its numerator and denominator sums each over a period, then divides), or None for a result with no meaning over time. The kind also sets the default scale. By default (‘auto’) it is guessed from summarize_by if only that is given, or else from the name (new_... is a flow; n_..., cum_..., and cumulative are stocks), or else from the dtype: an integer is a count, guessed to be a flow (a count over each step, e.g. doses given), and anything else is a ratio. Give kind='stock' for a count of people at each time point with no such name (e.g. ss.Result('vaccinated', dtype=int, kind='stock')), and kind= for anything else the guess gets wrong 'auto'
summarize_by str how the result is summarized over time (and resampled): by default (‘auto’), by its kind: ‘sum’ for a flow, ‘last’ for a stock, ‘mean’ for a ratio, and None for none; or another way, e.g. ‘mean’ to average a flow over time, or any other key of ss.Result.summarizers 'auto'
columns list if provided, make a 2D result of shape (npts, len(columns)), with these names for the columns, e.g. ['wild', 'alpha'] None
runs dataframe for a result across the runs of a MultiSim: one row per run, with its scenario (and the values of any parameters swept); the values then have a run axis first, of shape (n_runs, npts) None
groups bool for a module written as code in a stratified sim: keep the values by group too, so they can be selected (res.select(sex='female'), res.by('age')) as a declared module’s are; set them with set_groups() False

In most cases, ss.Result behaves exactly like np.array(), except with the additional fields listed above. To see everything contained in a result, you can use result.disp().

For a 2D result, res.alpha or res['alpha'] returns a 1D result for that column (which shares data with the 2D result), and res[ti] returns the row for that timestep.

Examples

res = ss.Result('infection', columns=['wild', 'alpha'], shape=10)
res[3] = [20, 5] # Set the values for timestep 3
res['alpha'][4] = 8 # Set one value for timestep 4
res['alpha'].label # Returns 'infection (alpha)'

A result across the runs of a MultiSim (msim.results.sir.I) is the same result with a run axis first: select() also takes run= (a position), scenario=, and the parameters swept; quantiles(), median(), and mean() summarize over the runs of each scenario; and plot() draws the median and a 95% interval of each scenario (lines=True draws every run).

```python
msim = sim.run(n_runs=10)
I = msim.results.sir.I # Runs by time points
I.select(run=3) # One run, as a result of one sim
low, mid, high = I.quantiles([0.025, 0.5, 0.975])
I.median().plot()
```

resample
results.Result.resample(new_unit=None, summarize_by=None, use_years=False)

Resample the result to a longer time unit, by its summarize_by (which by default follows its kind)

A flow is summed over each period, a stock takes its value at the end of each period, and a ratio sums its numerator and denominator over each period (by group, if it has them) and divides them (one with no parts is averaged over the period). Periods start at the sim’s start and include their end, as for data; calendar months and years are used instead for a sim with dates. Each period is labeled by its end: for calendar months and years, the first day of the next (so a year of weekly steps is labeled 1 January of the next year, not the week ending after it), or the end of the run if sooner; otherwise its last time point. The values by group (select() and by()) are resampled too.

Parameters
Name Type Description Default
new_unit str / dur the new unit: ‘day’, ‘week’, ‘month’, ‘year’, or a duration, e.g. ss.weeks(2) None
summarize_by str resample this way instead of by the result’s own, e.g. ‘mean’ to average a stock over each period None
use_years bool label the periods by their year (as integers) False
Returns
Name Type Description
Result a new Result with resampled values
Examples
res = sim.results.sir
res.infection.resample('week') # Weekly totals
res.I.resample('week') # The number infected at the end of each week

select
results.Result.select(run=None, **dims)

Select groups of a stratified result by name: keeps the given levels of each dimension, and sums over the rest

The values by group are kept at every time point, or, if that would take too much memory, every few steps (see ss.solvers.group_rows() and the sim parameter results); then the result has a value at the end of each of these periods, which for a flow is its total over the period.

For a result across the runs of a MultiSim, also select runs: by position (run=3, a result of one run), by scenario (scenario='vaccine'), or by the value of a parameter swept (beta=0.3).

Parameters
Name Type Description Default
run int / list for a result across runs, the position of a run (or a list of them) None

The value is their total; or, given the denominator of each group, a ratio: the total of the values over the total of the denominators (e.g. the prevalence among everyone), with both kept, so that selecting groups adds up each before dividing.

Examples
# In a module written as code, in a sim stratified by sex and age
def init_results(self):
    super().init_results()
    self.define_results(ss.Result('n_infected', groups=True), ss.Result('prevalence', scale=False, groups=True))

def update_results(self):
    super().update_results()
    alive, infected = self.sim.groups.count(), self.sim.groups.count(self.infected)
    self.results.n_infected.set_groups(self.ti, infected)
    self.results.prevalence.set_groups(self.ti, infected, alive)

sim.results.sis.prevalence.select(sex='female', age='15-24') # Women aged 15-24 infected, over all women aged 15-24

compare

results.compare(sim, df=None)

Line up a sim’s results with its data

A flow (new infections, reported cases) is summed over the interval ending at each data time; a stock or ratio (a count, a prevalence) is interpolated at the data’s time. Data by calendar year (an integer year column) is compared with the year each row names: a flow summed over the year, a stock or ratio averaged over it. A column that matches no result is left out (see check_data()).

Returns a dict of {column: (data values, model values)}.
