connectors

connectors

Define connectors, which are used to mediate interactions between modules when the sim is run.

While most of the coupling between disease modules happens automatically via shared states (e.g., shared susceptibility), connectors allow explicit cross-module logic such as seasonal forcing or co-infection effects; ss.modify() changes a named quantity, e.g. a seasonal ss.modify(sir.rel_trans, multiply=ss.seasonal(amplitude=0.2, peak='January')).

Used with: agents and compartments; declared and coded modules

Connector

connectors.Connector(name=None, label=None, **kwargs)

Base class for Connectors, which mediate interactions between disease (or other) modules

Because connectors can do anything, they have no specified structure: it is up to the user to define how they behave.

modify

connectors.modify(
    target,
    multiply=None,
    add=None,
    set=None,
    efficacy=None,
    share=None,
    route=None,
    where=None,
    start=None,
    stop=None,
    when=None,
    hold=None,
    name=None,
    **kwargs,
)

Change a named quantity while a condition holds: scale it, shift it, or set it

A modifier never overwrites the quantity it changes: the base value is kept, and the value used is (set value if any, else base) × multipliers + addends over the modifiers that are currently active. It can be passed to a sim in connectors (interactions that are part of the model) or interventions (policy), or be a member of a declared disease, as part of its natural history.

Note: CRN safe.

Parameters

Name Type Description Default
target par / str the quantity to change (for a modifier that is a member of a disease, its own, e.g. beta, recovery, or 'rel_trans'): a parameter (sir.pars.beta), a transition (sir.recovery, which scales its rate, or its probability if it is a branch with p=), sir.rel_sus or sir.rel_trans, a parameter of any module written as code, or the path of any of these as a string ('sir.pars.beta'); or the contacts of a network, as the network (ss.contacts('Kenya', layer='school'), matched by its name) or as a path ('school.pars.n_contacts') required
multiply float multiply the quantity by this; like add and set, it can also be ss.by(...), a function of the sim, or an ss.timeseries, for changes at given times None
add float add this to the quantity: a parameter, or an inflow (a transition from ss.null, e.g. CFUs shed into a reservoir), to which it adds an amount per unit time from outside the model None
set float replace the quantity with this (a parameter only) None
efficacy float for protection such as a condom or a needle program, the share of the risk it removes: the same as multiply=1 - efficacy (give one of them) None
share float with multiply= or efficacy=, the share of acts (or, on a route without acts, of contacts) it acts on: the hazard is multiplied by 1 − share·(1 − multiply), exactly, since hazards add; a number, an ss.timeseries, an ss.by, or (with route=, as agents) a function of the network returning one value per edge (e.g. lambda net: net.edges.condoms) None
route str / list for a modifier of a transmission, the network or networks (by name) it applies on; by default, every route. A disease written as code has no transmission to name, so on a route the target is its rel_sus (of the people who would be infected over it) None
where Cond / func who it applies to: a condition (e.g. sir.vaccinated), a condition on a count (e.g. sir.I.n > 1000, worked out at each step), or a function of the sim (default: everyone); with route=, the people who would be infected None
start date / float when the modifier starts to apply, within the sim (default: the start of the sim); a number is a calendar year from 1900 on, and otherwise a time in the sim’s unit None
stop date / float when it stops applying (default: never); a stop after the end of the sim never stops it None
when func a condition on time: a function of the timeline returning True on the steps it applies (e.g. lambda t: t.ti % 7 == 0); a condition on anything else goes in where= None
hold dur once where= (or when=) selects someone, the modifier stays on for them for at least this long, as a rule that is lifted only after a while; a bare number is in the sim’s unit None
name str the name of the modifier None

Examples

S, I, R = ss.states(3)
sir = ss.Disease(infection=S >> I @ 0.3*I, recovery=ss.Transition(I, R, dur=10), init_prev=0.01)
masks = ss.modify(sir.pars.beta, multiply=0.6, start=30)
sim = ss.Sim(sir, interventions=masks, stop=100).run()

# Changes at given times, each holding until the next; before the first, the quantity has its own value
lockdown = ss.modify(sir.pars.beta, multiply=ss.timeseries({30: 0.5, 60: 1.0}), start=30)

# Each place on its own: contacts cut by 40% for at least 14 days once a week's cases pass 200 per 100,000
npi = ss.modify(sir.pars.beta, multiply=0.6, where=sir.infection.incidence(over=ss.days(7), by='patch') > 200e-5, hold=ss.days(14))

# Condoms, 90% effective against gonorrhea, used in a share of acts that grows over time, on one network
use = ss.timeseries({2000: 0.05, 2020: 0.3})
condoms = ss.modify(ng.infection, efficacy=0.9, share=use, route='sexualnet')

# A member of a disease, with the rest of its natural history
class Measles(ss.Disease):
    S, I, R = ss.states('S I R')
    infection = S >> I @ 0.5*I
    recovery = I >> R @ ss.days(10)
    fading = ss.modify('rel_trans', multiply=0.5**(I.time/ss.days(3)), where=I)

check_applied

connectors.check_applied(sim)

Raise a ValueError for any modifier or efficacy of a product that nothing in the sim would apply, naming it and why

Called once by sim.init(), after every module has registered its modifiers in sim.modifiers (by module, kind of quantity, and name). For each quantity modified, the module it belongs to says whether it reads it: a declared module from its graph (unapplied()), and a module written as code from what its own code reads (ss.solvers.Effects.unapplied_par(), and for a disease ss.solvers.Undeclared.unapplied()). A network’s contacts are read by every transmission over it. It costs one pass over the quantities modified.

to_time

connectors.to_time(sim, val)

Convert a time (a date, a duration since the start, or a number) to the same kind of time as the sim’s timeline

A number from 1900 on (see ss.time.assume_cal_year()) is a calendar year, as start=2000 is: in a sim with dates, 2005 is the start of 2005, and 2005.5 the middle of it. Any other number is a time in the sim’s unit: in a sim with dates, that long after the start; otherwise, a time on the sim’s own axis (which, for a sim whose start and stop are years, is the year). So a number means the same in a sim with dates as in one whose start and stop are years; for, e.g., 2000 days after the start, give ss.days(2000).
