The sim (ss.Sim)

This is what a user runs. It exists to gather the people, modules, and settings of a model in one object; to choose how to run it (the solver); and to hold the results. It works the same way for every kind of model.

Used with: agents and compartments; declared and coded modules

The sim: a model, how to run it, and its results

Every Starsim model, whatever its kind, is run with a sim. It gathers the people and the modules (ss.Disease, ss.Network, ss.Intervention, ss.Demographics, and others), runs them step by step (see ss.loop.Loop), or all at once in the compiled kernels when nothing needs to happen between the steps, and holds the results.

Parameters

Name Type Description Default
model Module / list / dict the model: a module or a list of modules, which are sorted by kind as for modules; transitions, alone or in a list (or in diseases=), are one disease, named from its states (e.g. sim.sir). Alternatively, the sim’s settings as an ss.SimPars or a dict, which can include any of the other arguments
pars dict / SimPars the values of the model’s parameters by name, e.g. pars=dict(beta=0.1) or pars=fit.pars (see ss.par). As in Starsim 3, it can also hold settings of the sim (e.g. pars=dict(start=2000, dur=10, n_agents=1000, beta=0.1)): a name is a setting if no parameter of the model has it, and a keyword given directly wins over the same setting here. A whole ss.SimPars is taken as if given in place of the model. A name that is neither raises a KeyError when the sim is initialized None
label str a name for the sim, shown in plots and printouts None
people People the people to use (by default, the sim makes them) None
demographics str / Demographics / list / bool births, deaths, and migration: declared (ss.birth(), ss.death(), which run under every solver), or modules (e.g. ss.Births(), ss.Pregnancy()), or a list; True for births and deaths at default rates None
connectors str / Connector / list as above, for connectors None
networks str / Network / list as above, for networks None
interventions str / Intervention / list as above, for interventions None
diseases str / Disease / list as above, for diseases None
analyzers str / Analyzer / list as above, for analyzers None
modules Module / list modules of any kind, sorted among demographics, diseases, etc.; a module of your own that is none of these (an ss.Module, or a function of the sim, which becomes its step()) is kept in sim.custom None
solver str / Solver how a declared model is run: ‘auto’ (the default: chosen from the model; sim.solver_reason says why), ‘ode’ (deterministic and fastest), ‘binomial’ (stochastic compartments, a chain binomial), ‘gillespie’ (stochastic and exact, event by event), ‘tau’ (tau-leaping, a faster approximation to Gillespie), or ‘abm’ (agents, for detail about individuals). A solver can take options, e.g. ss.solvers.ode(integrator=, substeps=, dwells=) (dwells='exact' keeps each dwell time as it is, rather than as a chain of stages), ss.solvers.binomial(substeps=), or ss.solvers.abm(step=) (step='events' for agents in continuous time). A declared module can have its own way of running as agents, ss.Disease(..., solver=ss.solvers.abm(step='wholestep')), which the sim’s does not override. sim.solver is the one that runs, e.g. isinstance(sim.solver, ss.solvers.abm)
branching bool run the declared model as a branching process, under any solver: infection takes no one from the uninfected and gives no one back, so the susceptible side stays as it would with no infection. This is useful for the early growth or extinction of an outbreak, and for the size of chains of transmission; as agents, only the infected are made, so a large population costs little. See sim.branching for the size and outcome of each run, and sim.run(until=) to stop one
unit str the unit of bare numbers in declared transitions, e.g. ‘day’; if nothing in the model has a unit, time is in timesteps
approximations str what to do when a solver has to approximate part of the model (e.g. a dwell time run as stages): ‘note’ (the default) says so in one line (kept in sim.notes, and printed unless verbose=0); ‘allow’ keeps the note without printing it; and ‘error’ raises an error, for when the results must be exact
stratify dict stratify every module by properties of people, e.g. dict(age=[0, 15, 65], risk={'low': 0.8, 'high': 0.2}), as sim.stratify() takes them
data df data to compare the results with: a dataframe (or dict, or the name of a file) with a column “time” and columns named “module.result”, e.g. “hiv.infection”; it is plotted with the results, and is what sim.fit(), sim.log_density(), and sim.gradient() fit to None
copy_modules bool by default, the sim runs a copy of each module it is given, so the same modules can be given to several sims (read the ones that ran from the sim, e.g. sim.sir); if False, it runs the modules themselves, which saves a copy (and lets you read them directly after the run), but then the sim can’t be run again or copied with sim.new(), and the modules can’t be given to another sim True
n_agents int / float the number of agents, if the model runs as agents (default 10,000); more agents give less noisy results but run slower. Not for a compartmental run, which has no agents (give total_pop=)
total_pop int / float the number of people (default: one per agent); as agents, each stands for total_pop/n_agents of them (sim.pop_scale), and the results that count people are scaled up by it, so a large population can be modeled with fewer agents
rescale bool / dict dynamic rescaling of agents, as in Covasim (default False): each agent starts standing for one person, and the number grows to sim.pop_scale as the agents are infected, with some made naive again each time. This keeps the detail of a small outbreak in a large population without an agent per person. True, or a dict of its options, dict(threshold=0.05, factor=1.2) (the defaults): the fraction of agents who are not naive that triggers rescaling, and the least factor by which the scale grows each time
start float / str / date when the sim starts: a date (e.g. ‘2020-01-01’) or a year (a number from 1800 on, e.g. 2000), which give it a calendar; any other number (or a duration) is a time in the sim’s unit from 0 (default: 2000 for a model in years, else 0). With a calendar, every bare number given as a time (stop=, when=, the times of ss.schedule and ss.timeseries) is a year; without one, a time in the sim’s unit from 0. A duration given as a time (when=ss.days(10), until=, the start= of a module) is that long after the start with a calendar, else a time from 0 (day 10; the same when the start is 0)
stop float / str / date / dur when the sim ends, read as the start is: a date, a bare number (a year, or with no calendar a time in the sim’s unit from 0), or a duration from 0 (e.g. stop=ss.days(100), with no start; ss.years(2030) in a sim of calendar years is the year 2030); with no start, a year starts the sim in 2000, unless unit= is other than years (unit=‘day’, stop=3650 is 3,650 days from 0; default: a run of 100 days in days, else 50 of the sim’s unit)
dur float / dur the length of the run from its start, e.g. start=2000, dur=10 (a bare number is in years in a sim of calendar years, as a bare stop is, else in the sim’s unit) or start='2020-01-01', dur=ss.days(90); any two of the start, stop, and length define the third (stop=2035, dur=10 starts in 2025), and all three must agree
dt float / dur the timestep, in the sim’s unit (default 1.0); a smaller step is more accurate but slower (sim.check_dt() shows how much the results depend on it)
rand_seed int the random seed, from which every module’s random numbers are drawn; the same seed gives the same results, and different seeds give different runs of a stochastic model
even_draws bool for agents, space each call’s random numbers evenly, so that close to the expected number of agents move each time (default False). This makes runs much less variable (about 3 to 10 times less in the final size of a simple SIR), which helps when comparing scenarios with few runs; but outbreaks die out less often than they should, and the mean of a result can shift (e.g. the peak of an SIR on a network, by about 10%). Agents only, and needs ss.options.crn
keep_times bool for a declared disease run as agents, keep the time each agent entered every state (e.g. ti_S) and the history of every transition (e.g. sir.infection.n_times), for your own code to read after the run, e.g. in an analyzer. By default, only those the model needs are kept, which saves memory and time (default: ss.options.keep_times, False)
aging bool whether agents age (by default, they age if there are births or deaths)
record_people bool whether to record the results about people (alive, female, died, emigrated, etc.) every step (default True); False saves a little time in a sim that doesn’t need them, but some modules, e.g. demographics, rely on results.alive
step_order str the order in which the modules step: ‘type’ (default) at the place of each kind of module in the loop (see ss.Loop), or ‘given’ in the order they were given (the model and modules= first, then the modules given by kind, e.g. diseases=), before the deaths and results of the step; ‘given’ is for when one module must act on what another did earlier in the same step. Analyzers, which read the step’s results, still step last
require_kernels bool raise an error (ss.CapabilityError) if a compartmental sim can’t be run all at once in the compiled kernels, and would instead run step by step in plain Python, which can be 100 times slower; useful for making sure a fit or a large batch of runs stays fast (sim.describe() says why a sim can’t use them)
group_results list the results to keep by group (e.g. by age), by name, e.g. ['I', 'cases'] or ['sir.I']; the others keep only their totals, which saves memory in a sim with many groups (default: all, at every few steps if every step would take more than about 100 MB)
verbose int / float how much to print: 0 nothing, 1 the solver, notes, and progress (default), 2 everything (e.g. each step); a fraction is as 1, with progress at each such fraction of the run (e.g. 0.1 for every 10%)
kwargs dict the settings above, by name (they are kept in sim.pars, an ss.SimPars)

Modules can be given by kind (diseases=, networks=, etc.), all together with modules=, or both: they are sorted by kind and merged.

Examples

S, I, R = ss.states(3)
sim = ss.Sim(ss.Disease(S >> I @ 0.3*I, I >> R @ ss.days(10), init_prev=0.01)) # A declared model; here run as an ODE, or give solver= (e.g. solver='abm')
sim = ss.Sim(diseases='sir', networks='random') # Agents on a network; equivalent to ss.demo()
sim = ss.Sim(diseases=ss.SIR(), networks=ss.RandomNet()) # The same, with objects instead of strings
sim = ss.Sim(diseases=['sir', ss.SIS()], networks=['random', 'degree']) # Lists, mixing strings and objects
sim = ss.Sim(modules=[ss.SIR(), ss.RandomNet()]) # Modules of several kinds, sorted by kind

add_module
sim.Sim.add_module(module, key=None)

Add a module to a sim that has already been initialized, and possibly run part-way

Usually modules are supplied when the sim is created; use this method to add one later, e.g. an intervention after running the sim to a certain date. It should be called between timesteps (not from within a module’s step()). The module’s results cover the whole sim, but are only filled in from the current timestep onwards.

Parameters
Name Type Description Default
module ss.Module the module to add required
key str the type of module, e.g. “interventions” (if None, determine from the module’s class) None
Examples
sim = ss.Sim(diseases='sis', networks='random', start='2000-01-01') # The default run of 100 days
sim.run(until='2000-02-01')
sim.add_module(ss.modify(sim.diseases.sis.pars.beta, multiply=0.5, when=ss.schedule(start='2000-03-01'))) # Not a delivery of a new product, which changes the model's structure
sim.run()

sim.Sim.fit(
    pars=None,
    data=None,
    weights=None,
    likelihood=None,
    loss=None,
    penalty=None,

    rand_seed=None,

Fit every parameter that has bounds to every result that has data

Fits every parameter that has bounds (see ss.par) to every result that has data (see ss.Sim(data=...)). The original sim is not changed. The fitting itself is in ss.fitting, which is imported when it is first used.

A parameter can be one of a declared model, of a module written as code (ssl.HIV(beta=ss.par(...)), also a value in a dict parameter, fitted as e.g. cin_fn.k, or a setting kept as an attribute), a modifier’s amount (ss.modify(..., multiply=ss.par(...))), or a keyword argument of a function given as a module (def set_testing(sim, symp_prob=ss.par(0.1, bounds=[0.01, 0.5])), for a value set in code); one named alike in several modules is fitted with its module’s name, e.g. hpv16.rel_beta. A parameter whose value is an array, with bounds for each element (ss.par(np.array([...]), bounds=[lows, highs])), has each element fitted, as knots[0], …, except those whose bounds are equal. A data column names a result, as sim.results has it: e.g. prevalence, sir.prevalence, an analyzer’s by_age.cancers_0_15, a result nested deeper (hpv.genotype.cancers), or a column of a result with columns (sis.infection.alpha).

The fit uses either likelihoods or a loss: every data series has a likelihood (declared on its outcome, or given here), and the fit maximizes their sum; or none has, and it minimizes the loss. loss= is used in place of likelihoods declared on the outcomes (with a note), and likelihood=False switches them off. Some series with a likelihood and some without is an error, as is loss= with likelihood=.

By default, the fit finds the best values (a point estimate), by the method that suits the sim, and prints which and why:

  • ‘l-bfgs-b’ for a deterministic sim, with gradients from JAX (see ss.gradients), or by finite differences for one that JAX cannot run
  • ‘nelder-mead’ for one whose likelihood or priors JAX does not cover (e.g. a likelihood given as a function), or with one or two fitted parameters (where it is faster than gradients)
  • ‘optuna’ for a stochastic sim, including an agent-based one

Other methods for a best fit are ‘powell’ (no gradients), ‘slsqp’ (with gradients, like ‘l-bfgs-b’), and ‘if2’ (iterated filtering, for the sims that ‘pmcmc’ fits: the maximum-likelihood values, from passes of a particle filter in which each particle’s values are perturbed by a shrinking random walk; see ss.fitting.Swarm). For the uncertainty in the values (a posterior), ask for one by name:

  • ‘nuts’ (the No-U-Turn sampler), for a deterministic sim with gradients whose data series all have a likelihood; each chain starts from a draw near one of the best optima found from a scan over the bounds
  • ‘pmcmc’ (particle MCMC), for a sim whose data series all have a likelihood: a random-walk Metropolis sampler on the likelihood estimated by a particle filter for a stochastic compartmental sim (see ss.fitting.ParticleFilter), or on the exact likelihood for a deterministic sim (e.g. one JAX cannot run); each chain starts from a different one of the best points of a scan, and a run is kept with each draw, fit.trajectories, which fit.project() continues
  • ‘abc-smc’ (approximate Bayesian computation by sequential Monte Carlo), for any stochastic sim, with no likelihood needed; its accuracy depends on the tolerance it reaches, and it gives no posterior for a deterministic sim

The priors are the parameters’ prior=, or uniform over their bounds.

Parameters
Name Type Description Default
pars list the names of the parameters to fit (default: all that have bounds) None
data df the data to fit to (default: the sim’s data) None
weights dict the relative weight of each data series (default: equal) None
likelihood ss.Dist/dict/bool the likelihood of every data series (e.g. ss.poisson()), or of each by its name (e.g. dict(prevalence=ss.normal(std=0.02))), in place of any declared on its outcome; or False, for none (the declared ones are not used, and the fit minimizes the loss). The fit then maximizes their sum (plus the log of the priors of the parameters that have one, for the methods that find a best fit: the most probable values) None
loss str / func the measure of the mismatch to minimize, with no likelihoods (or in place of those declared on the outcomes): ‘nae’ (normalized absolute error, the default), ‘rmse’, or a function of the sim; any other name is an error None

rand_seed int the random seed for the fitting method (default: the sim’s, so a fit gives the same answer each time) None
verbose bool whether to print progress None
Returns
Name Type Description
An ss.fitting.Fit, with the calibrated sim as fit.sim and the best-fit values as fit.pars
Examples
beta = ss.par(0.1, bounds=[0.01, 0.5])
S, I, R = ss.states(3)
sir = ss.Disease(S >> I @ beta * I, I >> R @ ss.days(10), init_prev=0.01)
sim = ss.Sim(sir, data='cases.csv', start='2020-01-01', stop='2020-06-01')

more = sim.fit(method=ss.fitting.method('nuts', draws=1000, chains=2), likelihood=ss.poisson()) # With settings of the method
fit.sim.plot()

new
sim.Sim.new(pars=None, inplace=False, **kwargs)

A new, uninitialized sim: a copy of this one as it was when it was initialized, optionally with other values

A sim that has not been initialized is copied as it is, with any changes made to it since it was made. Once a sim is initialized, its settings are those of its run: setting one (e.g. sim.pars.stop = 30 after sim.run()) raises, so give it here instead (sim.new(stop=30)). Other changes made to it then (e.g. to a module’s parameters) belong to that run only, and are not kept.

To run a finished sim again from the start, sim.run() is enough (and sim.restart(pars=...).run() with other values, which for a sim that is nothing but compartments is much faster than a new sim); sim.new() is for other settings, e.g. sim.new(solver='abm').run(). To copy a sim as it is, including its results, use sim.copy().

optimize
sim.Sim.optimize(
    goal=None,
    total=None,
    start=None,
    spend=None,
    bounds=None,
    target=None,
    maxiter=50,
    verbose=None,
    **kwargs,
)

Allocate spending between programs to reach a goal, keeping the total fixed; or find the least total that reaches a target

The spending of each program is a parameter of the model: one per program of an imported program book (sim.imported.programs), or any parameters, given by name with spend=. The search (SciPy’s SLSQP) is over the fractions of the total, and each point is a run (restarted, if the sim is nothing but compartments). With target=, the total is doubled until its best allocation reaches the target, then found by bisection between a total that reaches it and one that does not (to within 1%), assuming that more money never does worse. The sim itself is not changed. The search is in ss.fitting, which is imported when it is first used.

Parameters
Name Type Description Default
goal ss.fitting.maximize/ss.fitting.minimize what to make as large or as small as possible: a result (e.g. ss.fitting.maximize('all_vs', at=2030), or ss.fitting.minimize('hiv.new_infections')), or a function of the run sim None
total float the total to allocate (default: the current total); with target=, the total the search starts from None
start float / date when the new allocation takes effect (default: the start of the sim), read as any time is (see ss.connectors.to_time(): a bare number is a year if the sim has a calendar) None
spend dict / list the spending parameters: names, or {program: name} (default: the imported programs) None
bounds tuple / dict the least and most a program can have, as amounts (default: 0 and the total); a dict gives them by program, e.g. dict(testing=(1e5, None)) (None for no limit), and a program not in it has the default None
target float the value of the result to reach (at least this with ss.fitting.maximize(), at most with ss.fitting.minimize()) with the least total None
maxiter int the most iterations of the search (of each total’s, with target=) 50
verbose bool whether to print progress None

Returns an ss.fitting.Optimization.

Examples
sim = ss.import_from('hiv_framework.xlsx', format='atomica', databook='hiv_databook.xlsx', progbook='hiv_progbook.xlsx', programs_start=2020)
best = sim.optimize(ss.fitting.maximize('all_vs', at=2030), start=2020)
best.summarize()
least = sim.optimize(ss.fitting.maximize('all_vs', at=2030), start=2020, target=1.1*best.value) # The least money that reaches it

rescale
sim.Sim.rescale()

Dynamically rescale the population; only used if pars.rescale=True

The scale factor starts at 1. Once the fraction of agents who are not naive (i.e. have ever been infected with any disease) exceeds the threshold (rescale=dict(threshold=)), the scale factor is increased by at least rescale=dict(factor=) (up to sim.pop_scale), and the same fraction of non-naive agents are made naive again (via disease.make_naive()), so that each agent now represents more people. Based on Covasim’s dynamic rescaling.

The people no agent stands for yet are counted as one number, results.unrepresented: pop_scale - 1 for each agent at the start, less the people the agents alive take on at each rescaling (from scale s to s', s' - s for each); the deaths and births of agents do not change it. So alive is scale people for each agent alive, plus these.

restart
sim.Sim.restart(pars=None, rand_seed=None)

Take a sim back to its start, optionally with new values of its parameters or a new seed, without running it

sim.run() does this itself for a finished sim; restart() is for running it again with other values or another seed (sim.restart(pars=dict(beta=0.1), rand_seed=2).run()), for stepping it yourself from the start (sim.restart().run(until=2010)), or for a function that sets the values to try (as for ss.gradients.Density). The values given are kept for later runs (as sim.par_values), until changed again.

For a sim that is nothing but compartments (one that the kernels run from start to finish: see sim.describe()), this makes repeated runs many times faster; any other sim (or a change the compartments were not laid out for, such as a new distribution) is built again, as sim.new() would. ss.parallel(sim, n_runs=...) and sim.fit() use it where they can.
