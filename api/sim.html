sim

sim

The sim (ss.Sim) and its parameters (ss.SimPars)

This is what a user runs. It exists to gather the people, modules, and settings of a model in one object; to choose how to run it (the solver); and to hold the results. It works the same way for every kind of model.

Used with: agents and compartments; declared and coded modules

The Sim object

All Starsim simulations run via the Sim class. It is responsible for initializing and running all modules and generating results. The sim orchestrates ss.People, ss.Network, ss.Disease, ss.Intervention, ss.Demographics, and other modules via the ss.Loop integration loop.

Parameters

Name Type Description Default
model Module / list / dict the model: a module or a list of modules, which are sorted by type as for modules; transitions, alone or in a list (or in diseases=), are one disease, named from its states (e.g. sim.sir). Alternatively, the sim parameters as an ss.SimPars object or a nested dictionary, which can include all other arguments required
pars dict the values of model parameters by name, e.g. pars=dict(beta=0.1) or pars=fit.pars (see ss.par), and of sim settings by their own names (e.g. stop) where no parameter of the model has the name; a name that is neither raises a KeyError None
label str the human-readable name of the simulation None
people People if provided, use this ss.People object None
demographics str / Demographics / list / bool births, deaths, and migration of everyone: declared (ss.birth(), ss.death(), for every solver), or modules (e.g. ss.Births(), ss.Pregnancy()), or a list; True for births and deaths at default rates None
connectors str / Connector / list as above, for connectors None
networks str / Network / list as above, for networks None
interventions str / Intervention / list as above, for interventions None
diseases str / Disease / list as above, for diseases None
analyzers str / Analyzer / list as above, for analyzers None
custom Module / list as above, for any custom user-created modules not matching one of the above types None
modules Module / list alternatively, supply all modules together and divide among demographics, diseases, etc. based on type None
solver str how to run modules with declared states and transitions (see ss.Disease): ‘auto’ (the default: an ODE if every part of the model has a compartmental form, otherwise agents), ‘ode’, ‘ide’ (deterministic, with each dwell time as it is rather than as stages), ‘binomial’ (chain-binomial), ‘gillespie’ (exact, one event at a time), ‘tau’ (tau-leaping: close to exact, and much faster for a run of many events), or ‘abm’ required
branching bool run the declared model as a branching process, under any solver: infection takes no one from the states of the uninfected and gives no one back, so the susceptible side stays as it would be with no infection (agents are made only for the infected); see sim.branching for the size and outcome of each run, and sim.run(until=) to stop one required
integrator str the scheme of the ODE: ‘rk4’ (the default) or ‘euler’ required
unit str the unit of bare numbers in declared transitions, e.g. ‘day’; if nothing in the model has a unit, time is in timesteps required
approx bool by default, each approximation a solver makes is noted in one line (kept in sim.notes, and printed unless verbose=0); True does not print them, and False makes them errors required
stratify dict stratify every module by a property of people, e.g. dict(age=[0, 15, 65]) required
data df a dataframe (or dict) of data, with a column “time” plus data of the form “module.result”, e.g. “hiv.infection”: plotted with the results, and what sim.fit(), sim.log_density(), and sim.gradient() compare them to None
kwargs dict merged with pars; see ss.SimPars for all parameter values {}

Note

Modules can be supplied either via individual keyword arguments (diseases, networks, etc.) or all together via the modules argument. When using modules, Starsim automatically sorts them by type. The individual kwargs and modules can be mixed; they are merged together.

Examples

sim = ss.Sim(diseases='sir', networks='random') # Simplest Starsim sim; equivalent to ss.demo()
sim = ss.Sim(diseases=ss.SIR(), networks=ss.RandomNet()) # Equivalent using objects instead of strings
sim = ss.Sim(diseases=['sir', ss.SIS()], networks=['random', 'degree']) # Example using list inputs; can mix and match types
sim = ss.Sim(modules=[ss.SIR(), ss.RandomNet()]) # Can supply multiple types of module with the 'modules' argument

add_module
sim.Sim.add_module(module, key=None)

Add a module to a sim that has already been initialized, and possibly run part-way

Usually modules are supplied when the sim is created; use this method to add one later, e.g. an intervention after running the sim to a certain date. It should be called between timesteps (not from within a module’s step()). The module’s results cover the whole sim, but are only filled in from the current timestep onwards.

Parameters
Name Type Description Default
module ss.Module the module to add required
key str the type of module, e.g. “interventions” (if None, determine from the module’s class) None
Examples
sim = ss.Sim(diseases='sis', networks='random', start=2000)
sim.run(until='2010-01-01')
sim.add_module(ss.modify(sim.diseases.sis.pars.beta, multiply=0.5, start='2012-01-01')) # Not a delivery of a new product, which changes the model's structure
sim.run()

sim.Sim.check_dt(factor=2, output=False)

Rerun the sim with a smaller timestep, and report how much each result changes

In a run that takes whole steps this covers everything that depends on the size of the step: turning rates into probabilities, the delay of a step between modules, and the order of the modules. In a stochastic run the change also includes the difference between two runs.

fit
sim.Sim.fit(
    pars=None,
    data=None,
    weights=None,
    likelihood=None,
    gof=None,
    penalty=None,
    method=None,
    n_runs=None,
    reseed=None,
    rand_seed=None,
    nopython=True,
    verbose=None,
    **kwargs,
)

Fit every parameter that has bounds to every result that has data

Fits every parameter that has bounds (see ss.par) to every result that has data (see ss.Sim(data=...)). The original sim is not changed. The fitting itself is in ss.fit, which is imported when it is first used.

A parameter can be one of a declared model, of a module written as code (ssl.HIV(beta=ss.par(...)), also a value in a dict parameter, fitted as e.g. cin_fn.k, or a setting kept as an attribute), a modifier’s amount (ss.modify(..., multiply=ss.par(...))), or a keyword argument of a function given as a module (def set_testing(sim, symp_prob=ss.par(0.1, bounds=[0.01, 0.5])), for a value set in code); one named alike in several modules is fitted with its module’s name, e.g. hpv16.rel_beta. A parameter whose value is an array, with bounds for each element (ss.par(np.array([...]), bounds=[lows, highs])), has each element fitted, as knots[0], …, except those whose bounds are equal. A data column names a result, as sim.results has it: e.g. prevalence, sir.prevalence, an analyzer’s by_age.cancers_0_15, a result nested deeper (hpv.genotype.cancers), or a column of a result with columns (sis.infection.alpha).

Parameters
Name Type Description Default
pars list the names of the parameters to fit (default: all that have bounds) None
data df the data to fit to (default: the sim’s data) None
weights dict the relative weight of each data series (default: equal) None
likelihood dict the likelihood of a data series, by its name (e.g. dict(prevalence=ss.normal(scale=0.02))), for series whose outcome does not declare one. If every series has a likelihood, the fit maximizes their sum (plus the log of the priors of the parameters that have one, for the methods that find a best fit: the most probable values) None
gof str / func the goodness of fit: ‘nae’ (normalized absolute error, the default), ‘rmse’, or a function of the sim; any other name is an error None
penalty func a function of the parameter values (a dict by name, an array whole) returning a number added to what a best fit minimizes, e.g. a smoothness penalty, lambda pars: 10*np.sum(np.diff(pars['knots'], 2)**2) None
method str / list by default, a best fit (a point estimate), by the method that suits the sim, which is printed with the reason: ‘l-bfgs-b’ for a deterministic sim with gradients (from JAX; see ss.gradients), ‘nelder-mead’ for one without them, or with one or two fitted parameters (where it is faster than gradients), and ‘optuna’ for a stochastic sim, including an agent-based one. A posterior is asked for by name: ‘nuts’ (the No-U-Turn sampler, for a deterministic sim with gradients whose data series all have a likelihood, with each chain started from one of the best points of a scan over the bounds that are apart), ‘pmcmc’ (particle MCMC, for a stochastic compartmental sim whose data series all have a likelihood: a random-walk Metropolis sampler on the likelihood estimated by a particle filter; see ss.fit.ParticleFilter), or ‘abc-smc’ (approximate Bayesian computation by sequential Monte Carlo, for any sim, with no likelihood needed); the priors are the parameters’ prior=, or uniform over their bounds. Also: ‘if2’ (iterated filtering, for the sims that ‘pmcmc’ fits: the maximum-likelihood values, from passes of a particle filter in which each particle’s values are perturbed by a shrinking random walk; see ss.fit.Swarm), ‘powell’ (no gradients) or ‘slsqp’ (with gradients, like ‘l-bfgs-b’), or a list of methods, each started from the best fit of the one before (a stage that does not converge stops the list; see ss.fit.fit_stages()) None
scan int for the SciPy methods, NUTS, and particle MCMC, the number of points spread over the bounds to try first (default: 10 per parameter, at most 100); the search starts from each of the best restarts=3 of them that are apart (for SciPy; 1 for a single parameter of a deterministic sim), each NUTS chain from one of the best that are apart, and particle MCMC from the best required
n_runs int runs per evaluation, for a stochastic sim (default 4 for a stochastic compartmental sim, and 1 for agents and for a deterministic one); every point is scored by the mean over the same seeds (common random numbers), except under Optuna, where each point takes fresh seeds so that its search averages over chance (see reseed=); fit.mismatch is the score at the best fit over the first seeds None
reseed bool whether each point takes fresh seeds (default: True for Optuna, False otherwise); reseed=False with Optuna scores every point with the same seeds, e.g. for a rare outcome, where with fresh seeds the search favors values whose runs were lucky None
rand_seed int the random seed for the fitting method (default: the sim’s, so a fit gives the same answer each time) None
nopython bool for a deterministic sim with gradients and a likelihood for every series, whether the gradients (and a NUTS posterior) have to be taken with the log-likelihood as one function in JAX; if the model has something JAX does not cover yet, the fit is then an error that says what, and with nopython=False it takes them with Python in the loop instead, which is much slower True
verbose bool whether to print progress None
kwargs dict passed to the fitting method (each method’s settings are in the docs of ss.fit.fit_scipy(), fit_optuna(), fit_if2(), fit_pmcmc(), fit_abc_smc(), and fit_nuts(), and one the method does not take is an error), e.g. n_trials=200 for Optuna (and n_workers=4 to run trials in 4 processes at once, and storage='fit.log' to keep the trials in a file, so that calling it again resumes the fit; see ss.fit.fit_optuna()), maxiter=500 for SciPy, draws=500, warmup=500, and chains=4 for NUTS (the defaults; 1,000 draws and 1,000 warm-up draws for particle MCMC, whose draws are more correlated), particles= for particle MCMC (default: chosen by each chain in its warm-up; see ss.fit.pmmh()), or parallel=False to run its chains one after another; for IF2, particles=1000, iterations=50 (passes of the filter), cooling=0.5 (the share of the first size of the random walk’s steps that is left after 50 passes, as pomp’s cooling.fraction.50), sd=0.05 (that first size, on the scale searched on: the logit of each value’s place between its bounds, of its log for wide bounds), and chains=4 (each from its own start: the best of the initial values and a spread of points over the bounds, by the filter) {}
Returns
Name Type Description
An ss.fit.Fit, with the calibrated sim as fit.sim and the best-fit values as fit.pars
Examples
beta = ss.par(0.1, bounds=[0.01, 0.5])
S, I, R = ss.states(3)
sir = ss.Disease(S >> I @ beta * I, I >> R @ ss.days(10), init_prev=0.01)
sim = ss.Sim(sir, data='cases.csv', start='2020-01-01', stop='2020-06-01')
fit = sim.fit() # A best fit
post = sim.fit(method='nuts') # A posterior, given a likelihood for each data series
fit.sim.plot()

get_modules
sim.Sim.get_modules(query=None, match_case=False, as_dict=False)

Retrieve modules from the Sim

Retrieve a module by name or by type. The query term can be the type of module to match e.g., ss.SIR, ss.Disease, ss.Intervention, or a string which is tested against module names. The string can contain a '*' at the start or end.

gradient
sim.Sim.gradient(results=None, pars=None)

The derivative of results, or of a function of the run sim, with respect to parameters, at their current values

The ODE run is differentiated by JAX (see ss.gradients), so this needs JAX, a sim with solver='ode', and one that the kernels run from start to finish (see sim.kernel_only()). The sim itself is not changed. A parameter with several values (a value for each level, ss.by(patch=[...]); an array; or a time series) has a derivative for each, named as sim.fit() names them (beta[a], beta[b], …).

Parameters
Name Type Description Default
results str / list / func the results, by name ('I', or 'sir.I' where needed); or a function of the run sim that returns a number or an array (e.g. a cost); default: every result of the declared modules None
pars str / list the parameters, by name (or one value of one, 'beta[a]'); default: every parameter that has bounds None
Returns
Name Type Description
An sc.obj by parameter, then module, then result, of the derivative at each step; for a function, by parameter, of the derivative of what it returns
Example
beta = ss.par(0.3, bounds=[0.1, 1])
S, I, R = ss.states(3)
sir = ss.Disease(S >> I @ beta * I, I >> R @ ss.days(8), init=dict(I=0.01), name='sir')
sim = ss.Sim(sir, unit='day', stop=100)
grad = sim.gradient('I')
grad.beta.sir.I # How the number infectious at each step changes with beta
sim.gradient(lambda sim: sim.results.sir.infection.sum()).beta # How the total infections change with it

new
sim.Sim.new(pars=None, inplace=False, **kwargs)

A new, uninitialized sim: a copy of this one as it was when it was initialized, optionally with other values

A sim that has not been initialized is copied as it is, with any changes made to it since it was made. Once a sim is initialized, its settings are those of its run: setting one (e.g. sim.pars.stop = 30 after sim.run()) raises, so give it here instead (sim.new(stop=30)). Other changes made to it then (e.g. to a module’s parameters) belong to that run only, and are not kept.

A sim that has run is run again this way, so it is seldom needed: sim.run() runs a finished sim again from the start, and sim.run(solver='abm') or sim.run(n_runs=10) build what they need themselves.

rescale
sim.Sim.rescale()

Dynamically rescale the population; only used if pars.rescale=True

The scale factor starts at 1. Once the fraction of agents who are not naive (i.e. have ever been infected with any disease) exceeds pars.rescale_threshold, the scale factor is increased by at least pars.rescale_factor (up to pars.pop_scale), and the same fraction of non-naive agents are made naive again (via disease.make_naive()), so that each agent now represents more people. Based on Covasim’s dynamic rescaling.

The people no agent stands for yet are counted as one number, results.unrepresented: pop_scale - 1 for each agent at the start, less the people the agents alive take on at each rescaling (from scale s to s', s' - s for each); the deaths and births of agents do not change it. So alive is scale people for each agent alive, plus these.

shrink
sim.Sim.shrink(inplace=True, full=True, size_limit=1.0, base_size=30, die=True)

“Shrinks” the simulation by removing the people and other memory-intensive attributes (e.g., some interventions and analyzers), and returns a copy of the “shrunken” simulation. Used to reduce the memory required for RAM or for saved files.

After shrinking, each module is expected to be smaller than size_limit*(base_size + n_timesteps) KB. The base_size term covers the fixed structural overhead of a module (parameters, results metadata, etc.) that does not depend on the simulation length, expressed as a number of timesteps’ worth of allowance; the n_timesteps term covers the per-timestep results that legitimately grow with the simulation; and size_limit scales both. A module exceeding this is most likely still holding a per-agent array that failed to shrink.
