fit

fit

Fitting sims to data: likelihoods, particle filters, samplers, and what sim.fit() runs

These exist so that a model can be fitted, with its uncertainty, in the same way whichever solver runs it. Parameters are chosen by giving them bounds (ss.par), in declared modules or in the parameters of modules written as code. Some methods are for some solvers only: gradients come from JAX, and particle filters need a stochastic compartmental solver.

Imported when it is first used (by ss.fit.X, sim.fit(), or sim.sensitivity()), not by import starsim.

Used with: agents and compartments; declared and coded modules

ParticleFilter

fit.ParticleFilter(sim, likelihood=None, weights=None)

An estimate of the likelihood of a stochastic sim’s data, from a bootstrap particle filter (see sim.fit() with method='pmcmc')

Many runs of the sim (the particles, ss.solvers.Particles) go forward together. At each data point, each is weighted by the likelihood of the data given its results, and when the weights become uneven, the runs are drawn again in proportion to them, so that runs that have strayed from the data are dropped and those that follow it are copied. The product over the data of the mean weight is an unbiased estimate of the likelihood (Andrieu, Doucet & Holenstein 2010), which is what particle MCMC needs.

Each declared disease is filtered on its own, since the diseases of a sim that the kernels run whole do not affect each other, except those tracked jointly (see ss.solvers.Crossing), which are filtered together, as the runs of their program. An outcome is compared with the data as its expected number (rather than drawn, as a run of the sim draws it), as the likelihood would compare it.

Each particle has random numbers of its own, so the particles are shared between threads (see ss.options.threads; one in the workers of ss.parallel() and of a calibration), and the estimate does not depend on how many there are.

sim ss.Sim the sim, initialized; it is restarted with each set of values before the filter is called required
likelihood dict the likelihood of each data series, if not declared on its outcome None
weights dict a multiplier on each series’ log-likelihood (default 1) None

Swarm

fit.Swarm(sim, fitted, set_pars, to_x, z0, sd=0.05, cooling=0.5, n_points=1)

The parameter values of each particle of IF2, iterated filtering, and the rates of the run that they give (see sim.fit() with method=‘if2’)

Each particle carries values of its own, on the unbounded scale that the fit searches on, which a random walk perturbs at the start of each pass of the filter and before each data point, by steps that shrink geometrically, to cooling of their first size after 50 passes (as pomp’s mif2() and camdl do; Ionides et al. 2015). The rates are worked out from each particle’s values by the model’s own expressions, so the kernels run each particle with its own, and they are checked against the sim’s own.

set_pars func restarts the sim with an array of values required
to_x func gives the values (an array, or particles by values) from the search scale, and their places between the bounds required
z0 array the values the sim is restarted with now, on the search scale required
sd float the first size of a step of the random walk, on the search scale 0.05
cooling float the share of the first size that a step has after 50 passes 0.5
n_points int the data points in a pass 1

abc_smc

fit.abc_smc(
    distance,
    logprior,
    z0,
    particles=200,
    generations=8,
    quantile=0.5,
    tolerance=None,
    min_acceptance=0.02,
    seed=None,
    verbose=True,
)

Approximate Bayesian computation by sequential Monte Carlo (Beaumont et al. 2009): a posterior without a likelihood

A population of particles is drawn from the prior, and in each generation a new one is drawn from the last (each particle perturbed by a Gaussian kernel twice as wide as the population) and kept only if its run is within the tolerance of the data; the tolerance is the median distance of the last population, so it shrinks as the population moves toward the data. Weights correct for the particles not being drawn from the prior.

Parameters

Name Type Description Default
distance func the distance of a run from the data, given a point (on the sampler’s scale) and a seed required
logprior func the log of the prior density of a point, on the sampler’s scale required
z0 array a point on the sampler’s scale (only its length is used: the first generation is drawn uniformly on that scale and weighted by the prior) required
particles int the size of the population 200
generations int the most generations; fewer if the tolerance or the acceptance rate says to stop 8
quantile float the share of the last population’s distances below the next tolerance 0.5
tolerance float stop once the tolerance is this small None
min_acceptance float stop once a generation accepts fewer of its proposals than this 0.02
seed int the random seed None
verbose bool whether to say what is being done True

Returns the population (particles × values, on the sampler’s scale), its normalized weights and distances, the tolerance and acceptance rate of each generation, and the number of runs.

compare_models

fit.compare_models(sims, data=None, holdout=0.25, folds=None, **kwargs)

Compare models by how well they predict data they were not fitted to

Each model is fitted (with sim.fit()) to all but the last part of each data series, run forward over that part, and scored on it: by the default goodness of fit, or by the log predictive density if every series of every model has a likelihood; the same measure is used for every model. A model with more parameters usually fits better; the prediction error needs no separate penalty for them.

holdout float / date the fraction of each series to hold out (default: the last 25%), or the date (or time) from which to hold it out 0.25
folds int if given, repeat the comparison with this many cut points over the held-out part (fit to the first part, predict the next block), and report the mean and spread of the prediction error None
kwargs dict passed to sim.fit(), e.g. weights= {}

Returns

Examples

diagnose

fit.diagnose(draws)

The R-hat (near 1 if the chains agree) and the effective sample size of each value, from draws (chains × draws × values)

Both are BlackJAX’s, rank-normalized and from split chains (Vehtari et al. 2021, as in Stan and ArviZ): the R-hat is the larger of that of the draws and that of their distance from the median, and the effective sample size is of the bulk. Both are NaN for chains of fewer than 4 draws, too short to tell, and without BlackJAX (pip install "starsim[jax]").

Parameters

Name Type Description Default
draws array the draws, with shape (chains, draws, values) required

fit_abc_smc

fit.fit_abc_smc(
    problem,
    particles=None,
    generations=8,
    quantile=0.5,
    tolerance=None,
)

A posterior without a likelihood, by approximate Bayesian computation (see abc_smc()): the runs within a shrinking distance of the data

For any sim, including agents. The distance is the goodness of fit (gof=), and each generation takes many runs of the sim. It has converged once the tolerance has stopped shrinking.

Parameters

Name Type Description Default
problem Problem the fit, as sim.fit() sets it up required
particles int the number of particles, which are the draws of the posterior (default 200) None
generations int the most generations 8
quantile float the quantile of the distances that sets the next generation’s tolerance 0.5
tolerance float the distance to stop at (default: run every generation) None

Examples

import starsim as ss

beta = ss.par(0.3, bounds=[0.1, 1])
S, I, R = ss.states(3)
infection = S >> I @ beta*I
sir = ss.Disease(infection, I >> R @ ss.days(8), ss.outcome(0.5*infection, name='cases'), init=dict(I=0.01), name='sir')
pars = dict(total_pop=10_000, unit='day', stop=60, solver='binomial')
data = ss.Sim(sir, pars=dict(beta=0.5), rand_seed=2, **pars).run().to_data('cases', resample='week')
fit = ss.Sim(sir, data=data, **pars).fit(method='abc-smc', particles=100, generations=6)
print(fit.table, fit.samples.head())

fit_if2

fit.fit_if2(
    problem,
    particles=1000,
    iterations=50,
    cooling=0.5,
    sd=0.05,
    chains=4,
)

Maximum likelihood by iterated filtering (IF2; Ionides et al. 2015): passes of a particle filter in which each particle’s values are perturbed by a shrinking random walk, and selected with it (see Swarm)

For a stochastic compartmental sim that the kernels run whole, with a likelihood for every data series, and parameters that are single values of the model’s rates. It gives the best values, not a posterior, with the range of the chains’ estimates in fit.table; for a posterior, use method='pmcmc'. It has converged if the chains end within 2 of each other in log-likelihood.

Parameters

Name Type Description Default
problem Problem the fit, as sim.fit() sets it up required
particles int the number of particles in each pass; more gives a less noisy likelihood 1000
iterations int the number of passes of the filter in each chain 50
cooling float the share of its first size that a step has after 50 passes, as cooling.fraction.50 in pomp 0.5
sd float the first size of a step of the random walk, on the scale searched on: the logit of each value’s place between its bounds, or of its log for wide bounds 0.05
chains int the number of chains, each from its own start: the best of the initial values and a spread of points over the bounds 4

Examples

import starsim as ss

beta = ss.par(0.3, bounds=[0.1, 1])
S, I, R = ss.states(3)
infection = S >> I @ beta*I
sir = ss.Disease(infection, I >> R @ ss.days(8), ss.outcome(0.5*infection, name='cases'), init=dict(I=0.01), name='sir')
pars = dict(total_pop=10_000, unit='day', stop=60, solver='binomial')
data = ss.Sim(sir, pars=dict(beta=0.5), rand_seed=2, **pars).run().to_data('cases', resample='week')
sim = ss.Sim(sir, data=data, **pars)
fit = sim.fit(method='if2', likelihood=dict(cases=ss.poisson()), particles=300, iterations=50)
print(fit.pars, fit.converged)

nuts

fit.nuts(
    logdensity,
    z0,
    draws=500,
    warmup=500,
    chains=4,
    traced=False,
    forward=True,
    seed=None,
    verbose=True,
)

Sample from a posterior with the No-U-Turn sampler (NUTS, from BlackJAX), with Stan’s warm-up of the step size and the mass matrix

The log-density is given in one of two ways. By default, as a function of NumPy arrays that returns its value and gradient, so it can be anything (here, a run of the sim, differentiated by ss.gradients.gradient()); it is called back from JAX, and the chains are run one after another. With traced=True, as a JAX function (see ss.gradients.Density), so that the whole of the sampling is compiled, with the chains run together (each on cores of its own); its gradient is taken in forward mode (one direction per parameter), which for a few parameters is much cheaper than reverse mode through the steps of an ODE, or with forward=False in reverse mode (one pass whatever their number, for many parameters).

warmup int the draws for the warm-up of each chain, which are not kept 500
chains int the number of chains 4

optimize

fit.optimize(
    sim,
    total=None,
    maximize=None,
    minimize=None,
    at=None,
    start=None,
    spend=None,
    bounds=None,
    target=None,
    maxiter=50,
    verbose=None,
)

Allocate spending between programs to maximize (or minimize) a result, keeping the total fixed; or find the least total that reaches a target

The spending of each program is a parameter of the model: one per program of an imported program book (sim.imported.programs), or any parameters, given by name with spend=. The search (SciPy’s SLSQP) is over the shares of the total, and each point is a run (restarted, if the sim is nothing but compartments). With target=, the total is doubled until its best allocation reaches the target, then found by bisection between a total that reaches it and one that does not (to within 1%), assuming that more money never does worse.

Parameters

Name Type Description Default
sim ss.Sim the sim, not yet run required
total float the total to allocate (default: the current total); with target=, the total the search starts from None
maximize str / func what to make as large as possible: a result of the disease (e.g. 'all_vs', or 'hiv.n_vs'), or a function of the run sim None
minimize str / func or what to make as small as possible None
at float / date the time of the result (default: the end), read as any time is (see ss.connectors.to_time(): a number from 1900 on is a year); without it, a function of the sim decides None
start float / date when the new allocation takes effect (default: the start of the sim), read as at is None
spend dict / list the spending parameters: names, or {program: name} (default: the imported programs) None
bounds tuple / dict the least and most a program can have, as amounts (default: 0 and the total); a dict gives them by program, e.g. dict(testing=(1e5, None)) (None for no limit), and a program not in it has the default None
target float the value of the result to reach (at most this with minimize=, at least with maximize=) with the least total None
maxiter int the most iterations of the search (of each total’s, with target=) 50
verbose bool whether to print progress None

Returns an ss.fit.Optimization.

pmmh

fit.pmmh(
    logpost,
    z0,
    draws=1000,
    warmup=1000,
    chains=4,
    particles=None,
    seed=None,
    parallel=True,
    verbose=True,
)

Sample from a posterior by particle marginal Metropolis-Hastings: a random-walk Metropolis sampler on a log-density that is estimated by a particle filter

Since the estimate of the likelihood is unbiased, the chains sample from the exact posterior (Andrieu, Doucet & Holenstein 2010), however noisy it is; more noise only makes them move more slowly. In the warm-up, the proposal’s covariance is learned from the chain so far (Haario et al. 2001), and its scale is tuned toward accepting 15% of proposals (about the best when the estimate is noisy; Sherlock et al. 2015). In the first half of the warm-up, the estimate where the chain is is made again at each step, so that a chain far from the posterior, where the estimate is noisiest, cannot be held by a lucky one.

Parameters

Name Type Description Default
logpost func called with a point (an array, on an unbounded scale), a random number generator (np.random.Generator) to draw any seeds from, and the number of particles; returns an estimate of the log of the posterior density there required
z0 array the point to start each chain from required
draws int the draws to keep from each chain 1000
warmup int the draws for the warm-up of each chain, which are not kept 1000
chains int the number of chains 4
particles int the number of particles; by default, each chain uses 100 for the first half of its warm-up, and then enough that the variance of the estimate at the middle of where it has been lately is about 1 (Doucet et al. 2015) None
seed int the random seed None
parallel bool whether to run the chains in parallel processes True
verbose bool whether to say what is being done True

Returns

Name Type Description
The draws (chains × draws × values), the estimate of the log-density at each (chains × draws), the share of proposals accepted after the warm-up in each chain, and the number of particles that each chain used

profile

fit.profile(sim, par, values=None, level=0.95, **kwargs)

The profile likelihood of one parameter: at each of its values, the others refitted by maximum likelihood (sim.fit(pars=...)), and the confidence interval it gives

The interval is the values whose negative log-likelihood is within half the chi-squared quantile with one degree of freedom (1.92 for 95%) of the lowest. Unlike the spread of a point estimate, it also shows whether the data determine the parameter at all: a profile that stays flat to a bound does not end within it.

For a deterministic sim (an ODE) whose data series all have a likelihood, and parameters with no priors (so each refit is the maximum likelihood); a stochastic sim’s estimates of the likelihood are noisy, and need a smoothed profile, which is not yet supported.

Parameters

Name Type Description Default
sim ss.Sim the sim, with data, which is not changed required
par str the name of the parameter to profile, one with a single value required
values list its values (default: the best fit of every parameter, 10 points spread over the bounds of this one, on the scale it is searched on, then 10 more at a time over the interval and the points next to it, until 5 are within it, at most 4 times) None
level float the confidence level of the interval 0.95
kwargs dict passed to sim.fit() for each fit, e.g. likelihood= or pars= (the parameters to refit; default: all that have bounds) {}

Returns an objdict with table (a dataframe with a row for each value: the value, the refitted values of the others, the negative log-likelihood nll, and whether the value is in the interval), best (the value with the lowest), interval (its low and high ends, where the profile crosses the threshold, interpolated between the values; an end that the values do not reach is the outermost of them, with a warning), and threshold.
