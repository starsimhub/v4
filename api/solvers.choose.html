solvers.choose

solvers.choose

The solvers to choose from (ss.solvers.ode(), binomial(), gillespie(), tau(), and abm(), each with its options), and, not for the user, choosing the solver: which engine runs a declared model, and why (choose_solver()), and the steps that build a declared model before it is run (parameters by name, births and deaths of the population, a named population, the unit, life tables)

It exists so that a model need not say how it runs: the choice is made from what it holds, and the reason is kept. Modules written as code are taken into account, and get an engine too.

Used with: agents and compartments; declared and coded modules

Solver

solvers.choose.Solver(**kwargs)

A solver, for ss.Sim(solver=...), with only the options of its own: ss.solvers.ode(), binomial(), gillespie(), tau(), or abm()

The common case is its name, solver='ode', which is the same as solver=ss.solvers.ode(). Once the sim is initialized, sim.solver is the one that runs (its defaults, if it was asked for by name or chosen by 'auto'), so which one it is can be tested as a class, e.g. isinstance(sim.solver, ss.solvers.abm); str(sim.solver) is its name.

Undeclared

solvers.choose.Undeclared(module, sim)

The engine of a disease that declares no states or transitions (see ss.Disease): there is nothing for it to run, so the disease’s own code is all of it. It gives that code what a declared disease’s engine gives its own, as agents: the modifiers and products on its rel_sus, rel_trans, and parameters (dis.current_value(), and self.pars while it runs), transmission over the networks (ss.Disease.transmit(rel_trans=..., rel_sus=...); see Transmission), and, for a delivery, the people its conditions select and a cure (force())

It exists so that code written for a disease can act on any disease in the same way.

abm

solvers.choose.abm(step=None)

Agents, with their options: ss.Sim(solver=ss.solvers.abm(step='events')); solver='abm' is the same with the defaults

Also a declared module’s own way of running as agents, which the sim’s does not override: ss.Disease(..., solver=ss.solvers.abm(step='wholestep')); or what a module’s class suggests, suggested_solver = ss.solvers.abm(step='wholestep') in the class body, which solver='abm' (or 'auto') follows, and a sim’s solver that names a step (e.g. ss.solvers.abm(step='midstep')) overrides (see ss.solvers.agent_solver()).

Parameters

Name Type Description Default
step str

how the agents of a declared module are stepped:

  • ‘midstep’ (the default): by steps, with those who arrive in a state during a step facing its rates for the rest of it, which is the more exact at a coarse step
  • ‘wholestep’: by steps, with rates over whole steps only, for those in the state at the start of the step, as code with ss.bernoulli() takes them: faster, and a little less exact at a coarse step; use it to match a model written as code
  • ‘events’: event by event in continuous time within each step (a prototype)
 None

ode

solvers.choose.ode(integrator='rk4', substeps=None, dwells='stages')

The ODE solver (deterministic compartments: the average epidemic, with no randomness), with its options: ss.Sim(solver=ss.solvers.ode(integrator='euler', substeps=1)); solver='ode' is the same with the defaults

Parameters

Name Type Description Default
integrator str the scheme: ‘rk4’ (fourth-order Runge–Kutta, the default: accurate at a coarse step) or ‘euler’ (simpler and less accurate; use it to match a model written with Euler steps) 'rk4'
substeps int the number of substeps per timestep (default: enough that no compartment turns over, or grows through its inflows, by more than a quarter in one). More is more accurate and slower. With integrator='euler', substeps=1 takes each step whole, as a model written in discrete time does, e.g. to reproduce another model’s numbers None
dwells str how the time spent in a state is modeled: ‘stages’ (the default: as Erlang stages, or exponential, which is fast) or ‘exact’ (the duration’s own distribution, e.g. a fixed 5 days, as a conveyor of whole steps at its own chance of leaving: an integro-differential model, which under branching=True is the renewal equation; see the user guide on branching processes). Use ‘exact’ when the shape of the duration matters, e.g. a fixed incubation period 'stages'

choose_engine

solvers.choose.choose_engine(sim)

Whether JAX takes the sim’s whole run of the ODE, as ss.gradients runs it, rather than the kernels, and why

By sim.jax: True for JAX, and otherwise (False, or None, the default) the kernels. JAX is never chosen for a run by itself: it is chosen where it is needed, for gradients and the fits and log-densities that use them (sim.gradient(), sim.log_density(), sim.fit()), and is worth asking for only for a long run over many groups (it takes about half a second to start in a session, and compiles each model; an ODE run in JAX agrees with the kernels to about 1e-14). The other solvers are run by the kernels, as is a model JAX does not cover (see why_not()), with a note.

Returns whether to use JAX, and the reason, also kept as sim.engine_reason.

choose_solver

solvers.choose.choose_solver(sim)

Work out the sim’s unit and solver; see ss.Disease for declaring a model that can be run with different solvers

Agents are made only when something needs them, whether the model is declared or written as code: a sim of modules written as code with nothing per person (e.g. an ODE of its own in NumPy) has no agents, and one with per-person arrays (e.g. a disease written as code) runs as agents. Which engine then takes a whole compartmental run, the kernels or (with sim.jax = True) JAX, is chosen when the sim is run, by choose_engine().

The steps: the modules are gathered and the declared model is built (init_model()); what matters to the choice is recorded (init_capabilities()), with what the layout of the compartments refuses, found by making it (init_layouts()); the solver is chosen; and the population is made ready for it (init_agents() or init_compartments()), and checked. The layouts are made once: a compartmental run uses them, unless its groups changed since.

init_capabilities

solvers.choose.init_capabilities(sim)

One record for each ingredient that changes which solvers can run the model, read by solver='auto', sim.describe(), and the CapabilityError of a compartmental solver that was asked for

Each record has the ingredient; the reason it makes auto run the model as agents (reason); whether it stops a compartmental solver that was asked for (fatal); and whether auto runs as agents for it (switch): see capabilities. Code is never run to find out: setting compartmental = True or False on a module (or its class) says whether it works on groups, and agent_reasons() is what a module says for itself. Any module written as code that says nothing, and the code and functions of a declared module, run beside the compartments (and raise a CapabilityError if they ask for agents). What the layout of the compartments refuses is not predicted here: init_layouts() makes the layout, which runs none of the model’s code, and adds its refusal as a record.

init_joint_states

solvers.choose.init_joint_states(sim, layouts=None)

In a compartmental run: track jointly the states of diseases that refer to each other, or whose people are born or die (see joint_groups())

For example, ss.modify(hiv.rel_trans, multiply=3, who=syph.I) needs the number of people with HIV who also have syphilis. Each disease in joint states becomes a dimension of the sim, whose levels are its compartments and which applies to the people of the others, so the model grows to the product of their compartments, which is counted before anything is made, and kept within ss.options.max_joint. See ss.solvers.JointStates.
