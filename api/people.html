people

people

The people in a sim (ss.People), lazy references to their properties (ss.ppl), and how they are made

People hold what every module shares, such as age, sex, and who is alive. In a compartmental run, each row is a group of people rather than an agent.

Used with: agents and compartments; declared and coded modules

LazyPeople

people.LazyPeople()

The people’s properties, before there are any people: ss.ppl.<name> is a lazy reference to the property <name> of each person (e.g. ss.ppl.age, ss.ppl.urban), checked when the sim is built

It can be used in a condition (ss.ppl.age < 15, for where=) and, as the person’s value, in a rate, a branch probability, or a result (expit(b0 + b1*ss.ppl.urban)); a condition in a rate is 1 for the people it holds for and 0 for the others (0.3*(ss.ppl.age > 65)).

Examples

p_use = expit(b0 + b_age*ss.ppl.age + b_urban*ss.ppl.urban)
kids = ss.ppl.age < 15

MadeOnUse

people.MadeOnUse()

One of the four fundamental arrays of ss.People, made on first use (see People.make_uids())

A descriptor rather than a branch of People.__getattr__(), so that a subclass with a __getattr__() of its own can’t hide it. It defines only __get__(), so once the arrays are made, the attribute in the instance’s __dict__ is found first and this costs nothing.

People

people.People(
    n_agents,
    age_data=None,
    extra_states=None,
    p_female=0.5,
    mock=False,
)

A class to perform all the operations on the people This class is usually created automatically by the sim. The only required input argument is the population size, but typically the full parameters dictionary will get passed instead since it will be needed before the People object is initialized.

Note that this class handles the mechanics of updating the actual people, as well as the additional housekeeping methods (saving, loading, exporting, etc.).

Parameters

Name Type Description Default
n_agents int the initial number of agents in the model required
age_data dataframe/series/array/str/ss.Dist the age distribution: a dataframe with columns age (the lower edge of each age bin) and value (the number or share of people in it), a series of values indexed by age, a two-column array, a CSV file with the dataframe’s columns, or a distribution of ages. This gives agents ages; for age groups in a compartmental model, use disease.stratify(age=[0, 15, 65], split=[0.3, 0.6, 0.1]) instead None
extra_states list non-default states to initialize None
p_female float the share of agents who are female 0.5
mock bool if True, initialize the People object with a mock Sim object (for debugging only) False

Examples

ppl = ss.People(2000)
kids = ss.ppl.age < 15 # A lazy condition, for a sim run as agents or as compartments (see ss.ppl)

add_module
people.People.add_module(module)

Add a Module to the People instance

This method is used to add a module to the People. It will register any module states with this people instance for dynamic resizing, and expose the module via People, in two ways

  • People.<module> will be a reference to the module itself, enabling access via people.hiv.susceptible
  • People.states['<module>.<state>'] will be a reference to the state, enabling access via people.states['hiv.susceptible']

add_state
people.People.add_state(state)

Add a property of each person, from a module (e.g. a social determinant of health that several modules read, as ss.ppl.<name>)

Idempotent: if the people have a property of that name already (added by another module, say), it is returned as it is, so each module that reads it can add it. Call it before the people’s values are made, e.g. in a module’s init_pre(); added later, its values are made at once.

Parameters

state Arr the array, e.g. ss.BoolArr('housing', default=False) or ss.FloatArr('adherence', default=ss.uniform()) required
Returns
Name Type Description
The property’s array (the one given, or the one added before)

Example::

def init_pre(self, sim):
    super().init_pre(sim)
    self.housing = sim.people.add_state(ss.BoolArr('housing', default=ss.bernoulli(0.8)))

get_age_dist
people.People.get_age_dist(age_data)

Return an age distribution based on provided data

The data should be provided in the form of either an Nx2 array, a pandas series with age as the index and counts/probability as the value, or a pandas DataFrame with “age” and “value” as columns. Each of these should look like e.g.:

age      value
0      220.548
1      206.188
2      195.792
3      187.442

The ages will be interpreted as lower bin edges. An upper bin edge will automatically be added based on the final age plus the difference of the last two bins. To explicitly control the width of the upper age bin, add an extra entry to the age_data with a value of 0 and an age value corresponding to the desired upper age bound.

Parameters
Name Type Description Default
age_data An array/series/dataframe with an index corresponding to age values, and a value corresponding to histogram counts or relative proportions. A distribution will be estimated based on the histogram. The histogram will be assumed to correspond to probability densitiy if the sum of the histogram values is equal to 1, otherwise it will be assumed to correspond to counts. required

Note: age_data can also be provided as a string (interpreted as a filename).

If no value is provided, the ages are the world’s (ss.data.age('world')), as for a sim with no named population.

Returns
Name Type Description
An ss.Dist instance that returns an age for newly created agents

init_results
people.People.init_results()

Initialize results for People; called during Sim.init_results()

By default, People reports on counts for any ss.BoolState instances, e.g. if People contains a ss.BoolState called ‘alive’ it will automatically contain a Result for ‘alive’ (the number alive). For identical behavior that does not automatically generate results, use ss.BoolArr instead of ss.BoolState.

This method also creates the standard people-related results like died and emigrated, the flows of people who died or left (results.died.cum is the cumulative total).

If sim.pars.people_results is False, People-level result collection is disabled (no results are created here and People.update_results is skipped in the loop).

make_uids
people.People.make_uids()

Make the four fundamental arrays: UIDs for tracking agents, slots for tracking random numbers, AUIDs for tracking alive agents, and agents’ parents

They are made on first use rather than in __init__(), so that a People not yet in a sim (such as the copy a sim keeps of itself before it is initialized, for sim.new()) holds no arrays per agent. The slots read the UIDs, and the parents are all none, until one is set (see shared in ss.Arr), so they take no memory unless something (e.g. ss.Pregnancy, with fetuses as agents) sets them.

phase
people.People.phase(uids=None)

Each agent’s phase, in [0, 1), by UID: a time between steps, t, is taken at step floor(t + phase), so it is rounded up or down at random in proportion (2.3 steps is 2 for 70% of agents and 3 for the rest), keeping its mean, with no draws: both a time due in a disease written as code (ss.TimeArr.due()) and a dwell time of the agent engine. Spread evenly over the slots (so an agent has the same phase in every scenario), and shifted by the sim’s seed

Parameters
Name Type Description Default
uids uids the agents to give the phases of (worked out for them alone); by default, every agent’s, kept until agents are made None

request_death
people.People.request_death(uids, cause=None, hazard=None)

External-facing function to request an agent die at the current timestep

In general, users should not directly interact with People.ti_dead to minimize interactions between modules (e.g., if a module requesting a future death, overwrites death due to a different module taking place at the current timestep).

Modules that have a future time of death (e.g., due to disease duration) should keep track of that internally. When the module is ready to cause the agent to die, it should call this method, with itself as the cause.

The actual deaths are resolved after modules have all run, but before analyzers. That way, regardless of whether removing dead agents is enabled or not, analyzers will be able to see and record outcomes for agents that died this timestep.

Each person dies once, of one cause: if several modules request the death of the same person in the same step, one of them is chosen at random (whatever the order of the modules, with common random numbers): in proportion to the hazards of the claims if each gave one (hazard=), and otherwise each equally likely. The cause is kept in people.cause_of_death (see people.causes). A module counts its deaths after they are resolved, with people.died_of(module), so a death is counted once.

Parameters
Name Type Description Default
uids Agent IDs to request deaths for required
cause Module / str what they die of: a module (by its name) or a name (default: none) None
hazard float / array the hazard of this death, one number or one per agent (in any unit, the same for every module, e.g. per year), to weight the choice of cause among the claims on the same person in the step (e.g. dis.death.hazard(uids) for a declared transition) None
Returns
Name Type Description
UIDs of agents that have been scheduled to die on this timestep

people

people.people(place, year=None, n_agents=None, revision=None)

A named population: the size, age structure, and sex ratio of a country or a US state

The data are the UN World Population Prospects, bundled with starsim_data (for a US state, the US Census for 2023, downloaded on first use: see ss.data.population()). The sim takes its population size (total_pop) from them, unless it is given one, and the split of an age stratification that is not given one, so a compartmental model can use a named population as well as agents can. Where the population came from is shown by sim.describe().

Parameters

Name Type Description Default
place str a country, by name or code (‘Kenya’, ‘KE’, ‘KEN’), or a US state (‘United States:Massachusetts’) required
year int the year (default: the year the sim starts, if it has dates; otherwise the year of the WPP revision, e.g. 2024); years between the decadal values are interpolated None
n_agents int the number of agents (default: the sim’s); giving it makes the model agent-based, as ss.People(n_agents) does None
revision str the WPP revision (default: the latest bundled) None

Returns

Name Type Description
An ss.People, with ppl.named saying where it came from

Examples:

sim = ss.Sim(sir, people=ss.people('Kenya', year=2024), networks=ss.contacts('Kenya'))
ss.people('NG').named.total # The population of Nigeria in 2024
