internals.gradients

internals.gradients

Not for the user: the ODE run in JAX: gradients of results with respect to parameters, and many runs at once

A compartmental engine flattens its flows into a ss.kernels.Program. The kernels (Numba or Rust) step through it; run() here takes the same program and runs the same fourth-order Runge-Kutta (or Euler) steps in JAX, so that the run can be differentiated (gradient()) and many runs with different values can be taken in one call (run_sets()). JAX is imported only when one of these is used.

What JAX differentiates is the run: the program’s numbers, and the compartments at the start, to the compartments and flows at every step. The steps either side of it are Python (working out those numbers from the parameters, and the results from the run, including outcomes and the goodness of fit), and are differentiated by central differences along the direction the run is differentiated in. They are cheap and smooth, so this is accurate to about 1e-9 of the value.

Used with: compartments; declared modules

Density

internals.gradients.Density(
    sim,
    fitted,
    x0,
    set_pars,
    likelihood=None,
    weights=None,
    external=None,
    bounds=None,
)

The log of the posterior density of a sim’s fitted parameters, as one function in JAX, so that it can be compiled and differentiated whole (see sim.fit() with method=‘nuts’)

The numbers in the run are worked out from the parameters in JAX: the values in the rates by evaluating the model’s own expressions, and the rest (e.g. the compartments at the start) from the change in them as each parameter changes, which has to be linear (checked at the corners and the middle of the bounds when it is built). Then the run, the results that have data, and the likelihood and priors. If anything is not covered, Unsupported says what.

jax

internals.gradients.jax()

Import JAX (imported only when first used, since it takes a few tenths of a second), on the platform that ss.options.jax says

If JAX has not been imported yet, it is given a device for each core of the CPU (as numpyro.set_host_device_count() does), or as many as the threads asked for in the environment (e.g. OMP_NUM_THREADS=1: see ss.settings.thread_limit), so that the chains of a posterior run on cores of their own; everything else runs on the first. XLA’s own threads (most of them compiling) are not limited by it: no flag of XLA’s limits them.

The platform it runs on is ss.options.jax (e.g. “cpu”), if not “auto”. If JAX has started already on others (by Starsim or anything else), it is started again on these: arrays made already stay on their devices, and are moved when used with new ones, and what was compiled is compiled again. “auto” goes back to the platforms JAX had before Starsim first changed them. The first time, its devices are started here, so that a GPU that fails to start (e.g. with a CUDA plugin of another version than jaxlib) says what to do.
